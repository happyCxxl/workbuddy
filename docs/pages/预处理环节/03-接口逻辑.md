# 接口逻辑

预处理是执行链的**第三个环节**：上游是组装产物（统一文档），下游是切片。它按策略把统一文档**逐元素复制成派生视图**（`PreprocessView`），原文（统一文档）零改动。执行器与读取侧分工：`PreprocessTaskRunner` 管落库与产物，`PreprocessPipeline` 是纯算法（不碰 DB、不碰对象存储、确定性执行）。

## 一、控制面（触发）

`KnowledgeFilePreprocessController` 只有两个方法：触发与详情。归属校验与任务解析复用各环节共用的守卫：`FileResultAccessGuard` 在**服务层入口**按 `wb_file_result.knowledge_base_id` 反查知识库再走 `KnowledgeBaseRules.checkAccessible`，越权与不存在同样返回 `KB_NOT_FOUND`（40401），未登录 40101；`TaskDetailSupport` 统一解析"被查看的那次运行"。

### 触发顺序

1. **归属校验**（越权 / 不存在 → 40401）；
2. **解析策略版本**（两档：显式指定的 `strategyVersionId` → 知识库绑定的策略版本）：显式指定档校验存在 / 类型匹配 / 启用，任一不满足给 **40433**；两档都不命中（绑定开关关闭、未绑定、绑定行缺失或已停用）一律 **40438**，文案形如「预处理未绑定策略，请显式选择策略后触发」或「预处理绑定的策略已停用或不存在，请重新绑定或显式选择策略」。**不做兜底**：既没有「取库内启用中最新」，也没有代码内置的默认策略，策略一律来自 `wb_knowledge_pipeline_strategy_version` 表（`init.sql` 里有 `preproc-default` 等种子行）；
3. **上游校验**：`upstreamProductId` 必填，未给或传 0 → **40436**；按它取产物并校验存在、环节为 `STRUCTURE`、且属于该文件结果（任一不满足 → **40432**）；**下游门禁**：产物的产出任务须为 `SUCCESS` 或 `PARTIAL_SUCCESS`，否则 **40439**（挡孤儿产物，`PARTIAL_SUCCESS` 放行并 warn）；任务行缺该引用时执行期落 `FAILED`(`TASK_UPSTREAM_MISSING`)；上游产物读不到 / 反序列化失败 / 无元素都会在任务里落 `PREPROCESS_EMPTY`。**执行期不再"取该环节最新产物"**，兜底已删；
4. **执行键查重**（`TaskTriggerSupport.trigger` 的第一行是存储一致性校验，不一致 → **40453**；随后按「文件结果 + `PREPROCESS` + 上游产物 ID + 策略版本 ID」查任务）：**查到就抛 40431**（任何状态，含执行中；消息「预处理任务已创建（taskId=…，状态 …），请勿重复触发」，**不返回既有结果**）；
5. **新建任务**：查不到才新建一条 `QUEUED` 任务，写入策略版本 ID、策略快照（capabilitySnapshot）与上游产物引用，入队；**入队写不进队列时**该任务立刻落 `FAILED`（`TASK_ENQUEUE_FAILED`，文案"任务入队失败，请重试"），异常继续抛出。

**失败即终局，不允许原地重跑**：想重来一次有两条路——**换上游产物**（从另一张组装卡片发起）或**换策略版本**（下拉里选另一个版本）；执行键不同即新链路，旧任务与旧产物保留。**补投完全归 `TaskStartupCompensator`**：启动补偿一次 + 低频周期扫描（`knowledge.task.low-freq-sweep-enabled`，默认开启、间隔 1 分钟，多实例用 Redis 锁防重），触发入口不再承担唤醒。

**服务停机**：先停领批 → 给在跑任务最多 `knowledge.task.shutdown-wait`（默认 30s）完成 → 到点中断并把仍未结束的任务显式置 `FAILED(TASK_SHUTDOWN_INTERRUPTED)`（条件更新，runner 已写终态则不覆盖）；`kill -9`/断电等硬停不做任何收尾，仍由启动时的 RUNNING 孤儿恢复兜底。两个池是具名 `ThreadPoolTaskExecutor` bean（`taskWatchdogExecutor` / `taskRunnerExecutor`），上面那句"最多等 `knowledge.task.shutdown-wait`"就落在它们的 `awaitTerminationSeconds` 上；环节超时取值同样按归一化环节名查（`knowledge.task.timeout.*`）。Spring Boot 自动给这两个池打点 `executor.*` 指标；`/actuator/health` 免认证；`/actuator/metrics` 需携带登录凭证（`SecurityConfig` 默认拒绝），端点暴露范围由 `management.endpoints.web.exposure.include=health,metrics` 决定。

## 二、执行链：九步

`PreprocessPipeline` 先把文档级信息**预计算**一次（重复页 / 噪声页取自组装写入的页标记；按页统计目录行数，Word 没有页概念时按连续 `TOC_LINE` 窗口判定；自定义规则的正则预编译一次），再逐元素建派生副本并按固定 `order` 执行启用规则。**逐元素 try/catch 隔离**：某条规则对某个元素抛异常时只影响该规则的产物，异常计入该步骤的告警与错误摘要，并把任务落成 **`PARTIAL_SUCCESS`**（部分成功，不是失败）。

| # | 步骤（`stepName`） | 规则名（轨迹里的 `rule`）                                                                   | 动作要点                                                                                                                                                                                                                                                        |
|---|--------------------|---------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1 | 编码规范化         | `encoding-clean-v1`                                                                         | 字符级整理产出 `displayText` 与 `normalizedText` 基座（空白/换行/乱码 + Unicode NFKC 全角→半角）；表格单元格同样处理；原文永不动                                                                                                                                |
| 2 | 段落/表格文本整理  | `text-tidy-v1`                                                                              | 空白归一化、**折行段落合并**（同段内硬折行合成一行，段间与列表项不动）、标点与引号统一、断词连字符合并、项目符号后补空格、移除 URL/邮箱；不动结构（不合并单元格、不改层级行列）                                                                                 |
| 3 | 页眉页脚           | `HeaderFooterRule`                                                                          | 页眉页脚元素按策略"仅标记"或"剔除"；页码文本随页眉页脚一起处置（**没有独立的页码规则**）                                                                                                                                                                        |
| 4 | 目录               | `TocRule`                                                                                   | 目录行按页内行数或连续窗口判定，短目录不处理，命中后按动作处理（KEEP/MARK/EXCLUDE）；**判定阈值对所有动作都生效**，非目录页的特征行不受影响                                                                                                                     |
| 5 | 重复               | `RepeatRule`                                                                                | 重复页 / 重复段落的重复份按处置方式处理：EXCLUDE 只保留首份（默认）/ MARK 标记但保留（重复份仍在内容流）/ KEEP 不改动（只统计）；判定来自组装环节结构标记                                                                                                       |
| 6 | 字段规范化         | 多条 `*-v1`（如 `amount-cn-v1`、`chinese-date-v1`、`unit-normalize-v1`、`cert-extract-v1`） | 金额 / 日期 / 面积 / 证书号标准化，产出 `normalizedFields`（`field` / `value` / `unit` / `rule`）；**拿不准或日期越界/不存在时不改写并记人工复核**（`MANUAL_REVIEW`，计入该步告警，不产出字段）                                                                 |
| 7 | 噪声               | `NoiseRule`                                                                                 | 噪声页与噪声元素按策略处置：KEEP 只统计不处置 / MARK 标记保留 / EXCLUDE 剔除出检索内容流（噪声计数来自组装环节页标记，与动作无关）                                                                                                                              |
| 8 | 自定义规则         | `CustomCleanRule`                                                                           | 用户正则规则按序执行：REMOVE 整体移除 / REPLACE 按替换文本改写（`$1` 组引用，替换文本必填）/ EXTRACT 只留命中（多个命中空格连接，无命中保持原文）；上限 20 条、单条正则 ≤200 字符，非法正则在预编译阶段跳过；规则组写在 `custom`，写进 `rules` 会被保存校验拒绝 |
| 9 | 视图组装           | —                                                                                           | 组装 `PreprocessView`：视图元信息 + 元素 + 每步的步骤日志（8 规则 + 视图组装）                                                                                                                                                                                  |

四条必须知道的现状：

1. **没有独立的"页码"规则**：页码是页眉页脚里的文本，随页眉页脚元素一起被标记或剔除，规则目录里没有单列一项；
2. **空白页没有元素级处置**：没有元素就没有副本可处置，噪声页只在**任务告警里计一笔**（「噪声页 N 页已标记」），不产生 `ViewElement`；
3. **「仅标记」态仍进检索内容流**：`MARKED_*`、`NOISE` 与 `MARKED_REPEAT` 只是标注，`normalizedText` 照常产出，切片会带走它们；只有剔除态与重复份的剔除档（`CHUNK_SKIP_STATUSES`）才不进切片（重复档选 MARK / KEEP 时重复份照常进切片）。
4. **判据在上游环节，本环节只决定"怎么处置"**：页眉页脚由**解析**环节识别（PDF 取页顶/页底带内跨页重复文本与页码模式，DOCX 直接取页眉页脚部件），重复页 / 重复段与噪声页由**组装**环节标记（噪声判据 = 无元素页 / 仅图片页 / 页文本乱码率 > `knowledge.structure.noise-garbled-ratio`，默认 0.4）。这些阈值**不在预处理策略里**，策略页也不提供：要改"怎么判定"得改上游环节；要改"判定出来怎么处置"才在预处理策略。

## 三、三层文本与处置状态

| 层         | 字段                                      | 是否可变 | 用途                                                  |
|------------|-------------------------------------------|----------|-------------------------------------------------------|
| 原文层     | `rawText`                                 | 从不修改 | 回溯原文、展示"改写前"                                |
| 展示层     | `displayText`                             | 可整理   | 阅读口径：空白 / 换行 / 明显乱码整理 + NFKC 全角→半角 |
| 检索层     | `normalizedText`                          | 可改写   | 检索口径：三层文本之上的字段标准化；剔除态为 null     |
| 表格单元格 | `cells[].text` / `cells[].normalizedText` | 同上     | 单元格展示文本永在，检索文本随元素一起被置 null       |

处置状态（`ViewElementStatus`）：`NORMAL`、`MARKED_HEADER` / `MARKED_FOOTER` / `MARKED_TOC` / `NOISE` / `MARKED_REPEAT`（仅标记，仍进检索）、`EXCLUDED_HEADER` / `EXCLUDED_FOOTER` / `EXCLUDED_TOC` / `EXCLUDED_NOISE`（剔除）、`REPEATED`（重复份剔除）、`IMAGE_REF_ONLY`（图片仅保留引用，OCR 预留）、`BACKUP_SKIPPED`（组装冲突被裁决方，不进内容流）。每个元素带 `preprocessTrace`（规则 / 字段 / 动作 / 前 / 后 / 证据，动作为 `MARK` / `REPLACE` / `EXCLUDE` / `KEEP` / `EXTRACT` / `MANUAL_REVIEW`，KEEP 表示未命中）。

## 四、剔除口径有两套

| 口径                  | 包含                                 | 谁在用                                                                                                   |
|-----------------------|--------------------------------------|----------------------------------------------------------------------------------------------------------|
| `EXCLUDED_STATUSES`   | 四个 `EXCLUDED_*` + `BACKUP_SKIPPED` | `summary.excludedCount`、卡片「剔除」格的"剔除态"部分                                                    |
| `CHUNK_SKIP_STATUSES` | 上面这些 + `REPEATED`                | **切片**决定哪些元素不进内容流；统计里的 `chunkSkippedCount`、卡片「剔除元素」一行、详情「剔除内容」页签 |

两者差一个 `REPEATED`：页面口径要看清是哪一个——卡片第一行与「剔除内容」页签用的是后者（不进切片的总数），详情统计条的「剔除」「重复」是分开的两格。

## 五、统计在读取侧现算

统计与结论都**不落产物**，由读取侧用同一份产物现算，节点与详情同源：

- 节点侧（执行树卡片）：`LineageQueryServiceImpl` 遍历任务时按 `PREPROCESS` 读一次产物（每个任务至多一次对象读取），交给 `PreprocessStatsSupport` 算统计与结论；
- 详情侧：`PreprocessControlServiceImpl.preprocessDetail` 读同一份产物算同一套统计；
- **合并式落位**：先在本地 map 落通用统计（由 `step_log` 聚合出 `matched` / `changed` 等），预处理统计随后 `putAll` 合并进去，最后统一转成 `PreprocessStatsVO` —— 顺序反过来会把先落的通用键覆盖掉，卡片会丢掉 `matched` / `changed`；
- 产物读不到（引用为空 / 对象缺失 / JSON 解析失败）时统计与结论都为 null，页面不陈述结论。

## 六、落库与产物

| 时机                | 落什么                                                                                                                                           |
|---------------------|--------------------------------------------------------------------------------------------------------------------------------------------------|
| 执行成功 / 部分成功 | 派生视图产物（`PreprocessView` JSON，`artifactId` = 内容 sha256）+ 九条 `step_log`（步骤名 / 状态 / 耗时 / 命中数 / 改写数 / 告警数 / 错误摘要） |
| 空视图 / 上游不可读 | **不落产物**，任务落 `PREPROCESS_EMPTY` 与失败说明                                                                                               |
| 执行异常            | 任务落 `PREPROCESS_FAILED`（兜底码），错误摘要截断后落到任务与步骤上                                                                             |
| 规则局部异常        | 产物照常落，任务落 `PARTIAL_SUCCESS`，异常进对应步骤的告警                                                                                       |

涉及的表：`wb_knowledge_pipeline_task`（任务与策略快照；唯一键 `uk_exec` = 文件结果 + 环节 + 上游产物 + 策略版本，0 表示"没有上游"与"该环节无策略"两档）、`wb_knowledge_pipeline_product`（产物引用与内容指纹）、`wb_knowledge_pipeline_step_log`（九步子步骤）、`wb_knowledge_pipeline_strategy_version`（策略版本）。预处理不写 `wb_file_result`，也不改统一文档产物。

## 七、读取侧的任务解析

`preprocess-detail` 与 `stage-content` 都按 `taskId` 精确取"被查看的那次运行"的产物（历史任务同样可展示自己的产物）：`taskId` 缺省取该环节最新任务，传了但不属于该文件该环节给 40001；文件结果不存在或没有该环节任务时，产物内容返回 `latest=false` 与空列表，页面按"没有产物"渲染。
