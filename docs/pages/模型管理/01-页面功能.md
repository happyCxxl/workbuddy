# 页面功能

两个页面同属侧栏分组「模型管理」，用全局骨架（`.page` / `.page-head` / `.page-title` / `.page-desc` / `.page-panel` / `.page-toolbar` / `.page-table-body` / `.page-panel-foot`，见 `../../../web/src/styles/page-shell.css`）。两页的写动作只有一类：改 `wb_model` 的业务列与状态（另写一条审计），**没有任何密钥与地址的输入口**。

**模型清单**（`/model/manager`）：页头副标题「维护可用模型与价格限额，以及启用状态」，右侧一个主操作按钮「新增模型」。

```
┌ 模型清单                                       [ 新增模型 ] ┐
├──────────────────────────────────────────────────────────────┤
│ 能力▾  状态▾  [搜索模型名 / 展示名]  [查询] [重置]      ⟳     │
│ 厂商   模型   能力   价格   限额   状态   操作               │
│ …                                                            │
│ 共 4 条                                                      │
└──────────────────────────────────────────────────────────────┘
```

**用量与成本**（`/model/usage`）：页头副标题「按时间区间查看模型调用明细与成本统计」，页头不带操作按钮。

```
┌ 用量与成本                                                   ┐
├──────────────────────────────────────────────────────────────┤
│ [日期区间]  能力▾  路由原因▾  [查询]                    ⟳     │
│ ┌调用总数┐┌已知成本合计┐┌未知用量占比┐┌切换次数┐             │
│ 时间  业务  能力  模型  用量  成本  延迟  路由原因  状态      │
└──────────────────────────────────────────────────────────────┘
```

## 权限与可见性

- **菜单与路由对所有登录用户开放**：侧栏一级分组「模型管理」下的两个二级项都不带 `adminOnly`，两条路由 `/model/manager` 与 `/model/usage` 都不带 `meta.adminOnly`；普通用户看得到入口，手输这两条路径也进得来。
- **六条接口都不要求管理员**：两个 Controller 的方法上都没有 `AdminOnly` 注解，任何登录用户都能调通；未登录回 `40101`。口径是**模型管理页面与接口对所有登录用户开放，不是管理员专项**；审计照旧（价格与模型的变更写业务审计）。
- **厂商候选来自前端枚举**：抽屉里的厂商下拉读 `web/src/types/model.ts` 的 `MODEL_VENDORS`（码与后端配置 `knowledge.model.vendors` 的键一致）；页面不显示密钥状态，也不新建厂商。
- **接口失败不改页面状态**：提示由请求层拦截器弹出，页面 `catch {}` 留空只处理成功分支。

## 两页的取数时机

| 页面       | 计数徽标 | 进页面时是否取数                            |
|------------|----------|---------------------------------------------|
| 模型清单   | 无       | 取（进页面即调清单接口，页脚给「共 N 条」） |
| 用量与成本 | 无       | 取（进页面即调用量接口，默认区间为当天）    |

两页各自记住自己的筛选与表格数据，切换页面不互相重置。

## 模型清单

### 工具栏

| 控件   | 口径                                                                                                                  |
|--------|-----------------------------------------------------------------------------------------------------------------------|
| 能力   | 下拉，选项是本地字典的五项（`CHAT` / `EMBEDDING` / `OCR` / `LAYOUT` / `TABLE_STRUCTURE`），首项「全部能力」按空值下发 |
| 状态   | 下拉，「全部状态」/ 启用 / 停用；启用与停用按码值 `ENABLED` / `DISABLED` 下发                                         |
| 关键字 | 输入框，回车与清除都触发查询，占位「搜索模型名 / 展示名」；空白关键字不参与过滤（trim 后为空即不传该参数）            |
| 查询   | 按当前三项条件重新取清单                                                                                              |
| 重置   | 三项条件清空后重新取清单                                                                                              |
| 刷新   | 原生 `button.page-refresh`；请求进行中禁用并旋转图标                                                                  |

三个过滤条件都在服务端生效：状态与关键字下推到 SQL，能力在服务端按逗号分隔串逐行比对（与目录端口同一口径，见 `03-接口逻辑.md`）。

### 表格列

列宽口径与全站一致：七列同 `min-width="150"`、不写 `width`、逐列 `align="center"`（见 `../../../web/src/styles/page-shell.css` 的「列表表格」一节）。

| 列   | 内容                                                                                                                                                                    |
|------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 厂商 | 第一行厂商展示名，第二行灰色等宽的厂商码                                                                                                                                |
| 模型 | 第一行展示名（留空过的一律已经回落成模型名），第二行灰色等宽的厂商侧模型名                                                                                              |
| 能力 | 每个能力一枚描边标签（码值原文，如 `OCR`）                                                                                                                              |
| 价格 | 按能力取对应计价口径：含 `CHAT` 读「输入 / 输出 币种·百万 token」，含 `EMBEDDING` 读「单价 币种·千次」，含视觉三能力读「单价 币种·页」；多组之间用 `/` 连接，全空读 `—` |
| 限额 | 「RPM / TPM」，任一为空读 `—`                                                                                                                                           |
| 状态 | 启用绿标 / 停用灰标（`el-tag`，`effect="dark"`）                                                                                                                        |
| 操作 | 两个行内按钮：编辑 / 启停（见下）                                                                                                                                       |

### 行内操作

| 按钮 | 动作                                                                                                                        |
|------|-----------------------------------------------------------------------------------------------------------------------------|
| 编辑 | 打开抽屉，标题「编辑模型 · <模型名>」；把行上的值铺进表单（含生效区间与备注）                                               |
| 启停 | 当前启用调 `PATCH` 改成 `DISABLED`（按钮文案「停用」），当前停用改成 `ENABLED`（文案「启用」）；按钮 loading 期间不可重复点 |

### 空态与页脚

- 空态落在表格 `#empty` 插槽：读取期间「加载中…」，读完后「暂无模型」（筛选条件把全部行都过滤掉时也是这一条）。
- 页脚读「共 N 条」（N 是当前清单条数，接口不分页，配置级表的行数在几十行量级）。

## 新增 / 编辑抽屉

抽屉宽度 520px，标题在新增时读「新增模型」、编辑时读「编辑模型 · <模型名>」，底部两个按钮「取消」与「保存」。进抽屉第一段是说明文案：厂商选项来自前端枚举（与配置 `knowledge.model.vendors` 的键一致），密钥与接口地址都在配置里（yml 写 `${ENV_VAR:}` 占位），本页不涉及密钥。

| 字段                     | 控件                     | 必填 | 口径                                                                         |
|--------------------------|--------------------------|------|------------------------------------------------------------------------------|
| 厂商                     | 下拉（只列枚举里的厂商） | 必填 | 选项文案「<展示名>（<厂商码>）」；候选来自 `MODEL_VENDORS`；页面不能新建厂商 |
| 模型名（厂商侧）         | 文本                     | 必填 | 最长 128 字符；保存时去首尾空白                                              |
| 展示名                   | 文本                     | 否   | 最长 128 字符；留空由服务端回落成模型名                                      |
| 能力                     | 多选下拉                 | 必填 | 五项字典值，选项文案「<码值> · <展示名>」；至少选一项                        |
| 上下文窗口（tokens）     | 数字                     | 否   | 非负整数，留空不下发                                                         |
| 币种                     | 下拉                     | 是   | `CNY` / `USD`，默认 `CNY`                                                    |
| 价格 · 输入 / 输出       | 数字 ×2                  | 否   | 每百万 token 单价，非负，留空表示未登记                                      |
| 价格 · 图像 / 版面 / OCR | 数字                     | 否   | 按页单价，非负，留空表示不按页计价                                           |
| 价格 · 嵌入              | 数字                     | 否   | 按千次单价，非负，留空表示不按千次计价                                       |
| 限额 · RPM / TPM         | 数字 ×2                  | 否   | 非负整数，两项都留空则该模型不参与容量占用判断                               |
| 生效区间 · 开始 / 结束   | 日期时间 ×2              | 否   | 留空表示立即生效 / 长期有效；两段都填时结束必须晚于开始                      |
| 状态                     | 单选                     | 是   | 启用 / 停用，默认启用                                                        |
| 备注                     | 文本                     | 否   | 最长 512 字符                                                                |

**字段顺序**：厂商 → 模型名与展示名（一行两项）→ 能力 → 上下文窗口与币种（一行两项）→ 价格四列（两行两项）→ 限额两项（一行两项）→ 生效区间两段（一行两项）→ 状态 → 备注。三段小标题分别是「价格（按能力的计价口径填对应项，可留空）」「限额（都能留空；两项都留空则该模型不参与容量占用判断）」「生效区间（留空 = 立即生效 / 长期有效）」。

### 校验

- 抽屉内先过表单规则：厂商必选、模型名必填且不超过 128 字符、展示名不超过 128 字符、能力至少一项、备注不超过 512 字符、结束时间不早于开始时间。
- 数值列都带 `min: 0` 规则，提交前再扫一遍七个数（上下文窗口、四个价格、两个限额），**出现负数就地拦下并提示「<字段>不能为负数」**，不发请求。
- 服务端仍会重跑同一套校验（含厂商码必须在配置里、唯一键不冲突），前端提示只是提前反馈。

### 保存

- 新增调 `POST /model/models`，成功提示「已新增模型」；编辑调 `PUT /model/models/{id}`，成功提示「已保存模型」。
- 成功后关闭抽屉并重新取一次清单（筛选条件不动），表格与「模型清单」的计数徽标一起更新。
- **价格与限额清空即写空**：抽屉里清掉的数值下发成 `null`，服务端按覆盖口径把那几列写成 `NULL`；状态与币种留空时保持行上的原值（新增时取默认值）。
- 编辑时厂商码可改（下拉仍只列枚举里的厂商）；改厂商等于把这一行换到另一家厂商下，唯一键按新的「厂商码 + 模型名」重新判定，厂商码不在后端配置里则回 `40461`。

## 用量与成本

### 工具栏

| 控件     | 口径                                                                                         |
|----------|----------------------------------------------------------------------------------------------|
| 日期区间 | `el-date-picker` 的 `daterange`，值格式 `YYYY-MM-DD`，默认两段都是今天，不可清空；改动即查询 |
| 能力     | 与清单同一套能力字典，首项「全部能力」                                                       |
| 路由原因 | 六项字典值，首项「全部原因」；选项文案取本地展示名（如 `CAPACITY_HIGH` → 避开高占用）        |
| 查询     | 按当前条件重取概览与明细                                                                     |
| 刷新     | 同清单的刷新按钮，请求进行中禁用并旋转                                                       |

时间两段按**左闭右开**下发：选中的结束日期加一天作为 `to`，例如选 10-14 到 10-14 下发 `from=2026-10-14`、`to=2026-10-15`。明细一次取 500 条（接口上限 2000）。

### 概览卡

四张卡（`.model-stats` 的四列栅格），每张卡三行：标签 / 大数值（等宽）/ 副文案。

| 卡                          | 数值                                                  | 副文案                                                                                       |
|-----------------------------|-------------------------------------------------------|----------------------------------------------------------------------------------------------|
| 调用总数                    | 概览的 `calls`，无数据读 `—`                          | 「成功 N · 失败 M」                                                                          |
| 已知成本合计                | 概览的 `costTotal`，空值读 `—`                        | 「未知用量行不参与合计」                                                                     |
| 未知用量占比                | 概览的 `unknownRatio` 乘 100 保留两位小数，空值读 `—` | 「未知 N 条 · 三项 token 与成本记 NULL」                                                     |
| 切换次数（按 route_reason） | 明细里 `route_reason` 非 `OK` 的行数                  | 各原因与条数（如 `CAPACITY_HIGH 14 · UNHEALTHY 6`），没有切换时读「最近 N 条明细里没有切换」 |

切换次数在本地按当前取回的明细统计（概览接口没有按路由原因的分组字段），条数上限 500，取的是「最近 500 条明细」的口径。

### 明细表

概览之下是一行说明（`usage_unknown = 1` 的行三项 token 与成本记 NULL，写 0 表示确实为零，两者不混用），再往下是九列明细表，同 `min-width="120"` 等宽。

| 列              | 内容                                                                                          |
|-----------------|-----------------------------------------------------------------------------------------------|
| 时间            | 明细写入时刻，`yyyy-MM-dd HH:mm:ss`                                                           |
| 业务            | `bizType`，当前写空读 `—`（`bizId` / `traceId` 同样留空，见 §4.5 的 v22 口径）                |
| 能力            | 标签，码值原文                                                                                |
| 模型            | 等宽文本，实际使用的模型（别名漂移以响应回传为准）                                            |
| 用量（入 / 出） | `usage_unknown = 1` 或两项 token 有任一项为空时读 **NULL**（压暗），其余读「入 / 出」两个数字 |
| 成本            | `cost` 为空读 **NULL**（压暗），其余按最多六位小数去尾零展示                                  |
| 延迟            | `<n>ms`，为空读 `—`                                                                           |
| 路由原因        | 标签，码值原文（`OK` 表示常规选型）；为空读 `—`                                               |
| 状态            | 成功绿标 / 其余红标；码值经本地展示名（超时 / 限流 / 熔断），失败行的悬停提示给出 `errorCode` |

空态读「暂无调用明细」（读取期间「加载中…」）。

## 页面不做的几件事

- **没有任何密钥界面**：没有「接入配置」视图、没有密钥掩码、没有轮换密钥入口；页面**不显示密钥状态**（「是否已配密钥」不在页面上出现）。
- **不新建厂商**：厂商的候选与展示名来自前端枚举（`MODEL_VENDORS`，与后端配置的键一致），页面不能新增、编辑或停用厂商。
- **不做试连**：没有连通性测试入口，清单里也没有试连结论列（该功能已下线，`wb_model` 不含结论两列）。
- **不删模型**：只有启停，没有删除入口；`wb_model` 的行靠启停表达可用性。
- **不做路由策略**：没有优先级、权重、灰度、限额调整入口；路由参数在 `knowledge.model.route.*`。
- **没有趋势图**：§8.2 的用量视图列了趋势图，本页只落概览卡与明细表 —— 概览接口给的是区间聚合、明细接口按调用倒序（不做日聚合表，D16），画按天趋势需要本地分桶或补接口。
- **不改配置**：页面的写动作只落 `wb_model` 的业务列与审计，`config/workbuddy-model.yml` 始终不动；改密钥、改地址、改超时都要改配置并重启。
