# 接口逻辑

本文件写「后端拿到请求之后到底做了什么」。入口是 `ModelController`（模型四条）与 `ModelUsageController`（用量两条），模型侧的编排与校验全在 `ModelAdminServiceImpl`，库表读写走 `WbModelDbService`（表 `wb_model`）。通用机制（错误码分段、鉴权、公共字段填充、逻辑删除）见 `../../README.md` 的「全局约定」章。

## 一、清单

`GET /model/models`（`ModelAdminServiceImpl.list`）：

1. **收参解析**：`capability` 按 `ModelCapability.of` 解析（留空即不过滤，填了不在字典内回 `40001`）；`status` 按 `ENABLED` / `DISABLED` 字典解析（大小写不敏感，落库取大写，留空即不过滤）；`keyword` 去首尾空白，空白即不传。
2. **取数**：`WbModelDbService.listByCondition(status, keyword)` —— 状态与关键字**下推到 SQL**（关键字在 `model_key` 一列上做模糊匹配），排序是 `vendor_code` 升序、`model_key` 升序；`del_flag = '0'` 由 `@TableLogic` 自动补上。
3. **能力过滤在应用侧**：能力是多值逗号分隔串，候选行取回后按 `ModelCapability.parse` 切分比对。**不用 `LIKE`** 的理由与目录端口一致：子串会误命中（`OCR` 会串到别的短取值上），而 `wb_model` 是配置级表、行数在几十行量级，整表读进内存没有规模风险。这一处口径与 `DbModelCatalog.listByCapability` 同源。
4. **字段映射**：逐行转 `ModelItemVO`，能力串切成字典名清单，厂商展示名按内置映射补齐。

清单**不分页**：接口返回数组，页面按条数展示；`/models` 也不接受 `current` / `size` 这类参数。

## 二、新增与编辑

`POST /model/models` 与 `PUT /model/models/{id}` 走同一段校验与赋值（`fill`），编辑额外做两件事：先按主键取行（取不到回 `40464`），唯一键判定排除本行。

**校验顺序**（任一条不通过即抛出，后面的步骤不再执行）：

| 序 | 校验                                                                        | 不通过的错误码与消息口径                                                                                      |
|----|-----------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------|
| 1  | 请求体非空                                                                  | `40001`「请求体不能为空」                                                                                     |
| 2  | 厂商码非空且不超过 64 字符                                                  | `40001`「厂商码不能为空」/「厂商码最长 64 字符，当前 N」                                                      |
| 3  | **厂商码必须出现在 `knowledge.model.vendors` 里**                           | `40461`「厂商码不在配置里：<码>（配置键 knowledge.model.vendors，已配置厂商：[…]）」                          |
| 4  | 模型名非空且不超过 128 字符                                                 | `40001`「模型名不能为空」/「模型名最长 128 字符，当前 N」                                                     |
| 5  | 唯一键 `(vendor_code, model_key)` 不冲突（编辑时排除本行）                  | `40001`「该厂商下已存在同名模型（唯一键 vendor_code + model_key）：<码> / <模型名>」                          |
| 6  | 能力至少一项、逐项在字典内、序列化后不超过 255 字符                         | `40001`「能力至少选一项」/「能力取值不在字典内：<值>」/「能力清单最长 255 字符…」                             |
| 7  | 思考模式标记只接受 `1` / `0`（留空取 `0`）                                  | `40001`「思考模式标记只接受 1（支持）或 0（不支持），当前 N」                                                  |
| 8  | 四个长度列与上下文长度非负                                                  | `40001`「<字段>不能为负数，当前值 N」                                                                         |
| 9  | 三个价格列非负                                                              | `40001`「<字段>不能为负数，当前值 N」                                                                         |
| 10 | 币种在 `CNY` / `USD` 内                                                     | `40001`「币种取值不在字典内：<值>（取值 CNY / USD）」                                                         |

**保存路径不收状态**：`ModelSaveDto` 没有 `status` 字段，`fill` 无条件写 `ENABLED`，因此新增与编辑保存后模型都是启用态；停用与重新启用只走 `PATCH /model/models/{id}/status`。

**留空的回落口径**：状态不在收参里，新增与编辑都写 `ENABLED`（停用只走启停接口）；币种留空时新增取 `CNY`、编辑保持行上原值；思考模式标记留空取 `0`。文本列一律去首尾空白后入库。

**模型没有展示名与生效区间**：清单的「模型」列直接读 `model_key`；可用性只有 `status` 一个开关，目录候选只按 `status = ENABLED` 筛，路由层也不再判生效窗口。

**覆盖式更新（`updateAll`）**：编辑把校验后的业务列写进一个新的实体（只带主键与业务列），由 `WbModelDbService.updateAll` 落库。MyBatis-Plus 的实体更新策略跳过 `null`，**被清空的列由更新条件里的 `set(列, null)` 显式写成 `NULL`** —— 长度、价格与限额可以真正清空，而不是"留空保持原值"；显式清空的列清单与实体上可空的业务列一一对应。公共字段由 `KnowledgeMetaObjectHandler` 在实体上填 `update_by` / `update_time`。

## 三、启停

`PATCH /model/models/{id}/status`：取行（取不到 `40464`）→ 解析目标状态（留空或非法回 `40001`）→ `WbModelDbService.updateStatus` 定点回写 `status` 一列 → 写审计（`ENABLED` 记启用、`DISABLED` 记停用）。**启停不动长度、价格与限额**，也不改配置。

停用的模型不再进候选集（目录端口按 `status = 'ENABLED'` 筛），在途的调用不受影响；再次启用后重新进候选。

## 四、审计

模型的变更写业务审计（§8.3 的口径）：

| 接口               | 动作（`wb_audit_log.action_type`） | 对象类型（`object_type`） | 前摘要 / 后摘要                     |
|--------------------|------------------------------------|---------------------------|-------------------------------------|
| `POST /models`     | `MODEL_CREATE`                     | `MODEL`                   | 空 / 新增行的 JSON                  |
| `PUT /models/{id}` | `MODEL_UPDATE`                     | `MODEL`                   | 变更前的行 JSON / 覆盖后的行 JSON   |
| `PATCH .../status` | `MODEL_ENABLE` / `MODEL_DISABLE`   | `MODEL`                   | 变更前的行 JSON / 状态改后的行 JSON |

对象 ID 是模型行的主键；摘要由 `JsonUtil.toJsonStr` 生成（`wb_model` 不含密钥，整行可入摘要）。审计与业务写在同一事务里（`@Transactional(rollbackFor = Exception.class)`），业务回滚时审计一并回滚。

## 五、涉及的表

| 表                  | 用途                                                                                                         |
|---------------------|--------------------------------------------------------------------------------------------------------------|
| `wb_model`          | 模型目录本体：厂商码、模型名、能力多值、思考模式标记、四个长度列、上下文长度、三个价格列、币种、两个限额与状态             |
| `wb_model_call_log` | 用量与成本的数据源；调用（含解析 / 嵌入链路上的真实调用）在这里一行一次                                      |
| `wb_audit_log`      | 模型新增 / 修改 / 启停留痕：动作 `MODEL_*`、对象类型 `MODEL`、对象 ID 是模型行主键                           |

表结构定义见 `../../../workbuddy-biz/src/main/resources/sql/README.md` 与同目录的 `init.sql`。库表访问与 SQL 片段的单测口径（Mockito 打桩 + `getSqlSegment()` / `getSqlSet()` 断言，仓库没有 DB 测试基建）见 `DbModelCatalogTest` 与本页同批的 `WbModelDbServiceImplTest`。

## 六、权限、异常与边界

- **六条接口都不要求管理员**：两个 Controller 的方法上都没有 `AdminOnly` 注解，任何登录用户都能调用，未登录回 `40101`；口径是模型管理页面与接口对所有登录用户开放，不是管理员专项。`GlobalExceptionHandler` 与两个 REST 出口保证 HTTP 状态恒为 200 + `R.code`。
- **厂商候选在前端枚举**：`MODEL_VENDORS` 的码与配置 `knowledge.model.vendors` 的键一致；保存时的配置校验仍在服务端（`requiredVendorCode`），枚举与配置不一致时以后端配置为准。
- **路径参数不是数字**时类型转换失败，按 `40500` 兜底（与既有接口一致）。
- **`/models` 上没有 DELETE 映射**：模型只启停、不删除，`wb_model` 的逻辑删除标记由库里手工维护。
- **不提供写密钥的入口**：没有 `/credentials` 映射（回 404），也没有任何接收密钥的字段；`ModelSaveDto` 里没有密钥类字段，页面也不显示密钥状态。
- **不改 `config/workbuddy-model.yml`**：页面的写动作只落 `wb_model` 的业务列与审计，配置（厂商连接、路由参数）始终不动。
