# 模型管理

模型能力平台的**管理页**（对所有登录用户开放）：维护「哪些模型可用、它的能力、价格与限额」，并只读查看调用用量与成本。页面拆成两个路由：**模型清单**（主入口，行内可编辑 / 启停，右上「新增模型」）与**用量与成本**（概览卡 + 调用明细表），两页同属侧栏分组「模型管理」。

口径的三条前提（见 `../../design/模型能力平台-方案设计.md` 的 §4.1 / §4.2 / §8）：

- **厂商连接与密钥都在配置**（`knowledge.model.vendors.<厂商码>`，落在 `../../../workbuddy-biz/src/main/resources/config/workbuddy-model.yml`），库里只有一张 `wb_model` 表、只存厂商码；**页面没有密钥与地址的任何入口**，厂商下拉的候选来自前端枚举（`MODEL_VENDORS`，当前 `dashscope` 与 `deepseek`）、不可新建。
- **限额只写在模型行上**（没有厂商级限额）；价格三列都按每百万 token 计（输入·缓存未命中 / 输入·缓存命中 / 输出），都能留空。
- **长度只登记、不校验**：最大输入 / 最大输出（含思考模式两档）与上下文长度都存整数 token，页面用 K / M 输入与展示（`1K = 1000`、`1M = 1000000`）；「是否支持思考模式」也只登记能力，不装配请求参数。
- **没有生效区间**：可用性只有「启用 / 停用」一个开关，目录候选按 `status = ENABLED` 筛。
- **路由参数在配置里**（`knowledge.model.route.*`），页面不做策略、不做灰度、不做人工优先级。

## 厂商枚举与密钥口径

厂商下拉的候选来自**前端枚举**：`MODEL_VENDORS`（`../../../web/src/types/model.ts`）按「码 + 展示名」成对给出，码与后端配置 `knowledge.model.vendors` 的键一致，接入新厂商时两处同步。页面**不显示密钥状态** —— 密钥只在配置与部署环境变量里，接口与页面都没有密钥字段，也没有任何下发路径；轮换密钥与改地址走配置 + 重启。

厂商连接（地址、认证方式、密钥、超时）写在 `../../../workbuddy-biz/src/main/resources/config/workbuddy-model.yml`。密钥用**环境变量占位符**给出（写法 `api-key: ${DASHSCOPE_API_KEY:}`，带空默认），密钥本身不进仓库；占位符解析不出来时启动失败，错误信息带厂商码。

保存模型时**厂商码必须出现在配置里**：不在配置里回 `40461`（`MODEL_VENDOR_UNKNOWN`），消息带配置键 `knowledge.model.vendors` 与当前已配置的厂商清单，避免"配错到运行期才发现"。枚举与配置不一致时，以后端配置为准。

厂商的展示名在枚举里给出，与后端清单返回的 `vendorName` 取同一套取名（内置映射：`dashscope` → 阿里百炼、`deepseek` → DeepSeek、`openai` → OpenAI，未命中回落厂商码本身）。当前接入两家：**阿里百炼**（`dashscope`，base-url 留空取适配器内置的百炼兼容端点）与 **DeepSeek**（`deepseek`，base-url 必须显式写 `https://api.deepseek.com`；适配器内置默认地址是百炼的）。

## 两处口径差异（如实登记，不自行改口径）

- **能力字典**：方案 §4.6 的字典含 `RERANK` / `IMAGE`，`workbuddy-common` 的 `ModelCapability` 枚举只有 `CHAT` / `EMBEDDING` / `OCR` / `LAYOUT` / `TABLE_STRUCTURE` 五项。接口按枚举校验，页面也按五项给选项，**这两个取值当前会被拒**（差异登记见 `../../design/模型能力平台-待办清单.md` 第六节第 5 项）。
- **明细的业务归属列**：`bizType` / `bizId` / `traceId` 当前写空（§4.5 v22 口径），明细表的「业务」列读作 `—`。

## 待定项

- **厂商枚举与配置的一致性靠人工**：`MODEL_VENDORS` 与 `knowledge.model.vendors` 的键要同步改，枚举里多一个或少一个都不会在启动期报错（保存时按配置校验，回 `40461`）；是否改成由后端下发候选尚未决定。
- **编辑时允许改厂商码**：厂商码与模型名共同构成唯一键，改成另一家等于换一条模型行；当前实现允许改（下拉只列枚举里的厂商），是否改为编辑时锁定厂商码尚未决定。
- **切换次数按前 500 条明细统计**：概览接口没有按 `route_reason` 的分组计数，页面用明细接口（`limit` 500）在本地统计，超过 500 条时这个数字只是"最近一批"的口径；是否给概览补一个分组字段尚未决定。
- **长度与思考模式只登记、不接线**：四个长度列与「是否支持思考模式」目前只入库、只在页面展示，既不拦请求也不参与容量估算，思考模式也没驱动请求参数；是否接上校验与参数装配尚未决定（登记为 `../../design/模型能力平台-待办清单.md` 第六节第 10 条）。
- **缓存命中价尚未分列计入成本**：`wb_model` 已有「缓存未命中 / 缓存命中」两个输入单价列，但明细侧只有一个 `unit_price_in` 留档列，命中行按哪一档计价尚未接线（并入同一清单第六节第 4 条）。
