# 自测清单

改完本页（页面、接口、后端逻辑任一）后手工过一遍。前置条件：中间件已起、后端与前端 dev server 已启动；准备一个管理员账号与一个普通用户账号；`wb_storage_source` 至少有一行 `status = 'ENABLED'` 且 `is_current = 1`。数据源由初始化脚本或库内 SQL 维护，MinIO 与本地目录两种存储源都可用。

## 入口与权限

- [ ] 管理员登录后，侧栏一级叶子项出现「系统设置」，点击进入 `/settings`，页面上能看到「存储源」这张卡
- [ ] 普通用户登录后，侧栏**同样出现**「系统设置」，点击能进 `/settings`
- [ ] 普通用户进 `/settings`：只有页标题与一行灰字空态「暂无你可以修改的设置」，卡片不渲染，卡内下拉与按钮都找不到
- [ ] 普通用户直接 `GET /system/storage-sources`（绕过界面）→ 回 `40104`
- [ ] 普通用户绕过界面调 `POST /system/storage-sources/{id}/current` → 回 `40104`，`is_current` 不变
- [ ] 未登录直接 `GET /system/storage-sources` → 回 `40101`

## 卡片与下拉

- [ ] 管理员进页面时只有一张卡「存储源」（`.setting-cards` 的 `--setting-card-w: 275px` / `--setting-card-h: 305px` 定下的固定宽高）；卡内只有存储源下拉、「启用」按钮与「当前启用」信息块——没有清单表格、没有行操作列、没有表单
- [ ] 不同参数条数（少 / 多）下卡片尺寸一致且为固定值：分别用参数少与参数多的存储源重进页面，卡片量出来都是宽 275px、高 305px，不随参数行条数变化
- [ ] 新增一张设置卡片时与现有卡片同尺寸：加一张卡后两张卡同宽同高（都取容器上的两个变量，卡片自身不另设宽高），窄视口下一行放不下时卡片换行排布、卡片区滚动
- [ ] 下拉只列 `status = 'ENABLED'` 的存储源；把某行改成 `DISABLED` 后重进页面，该行不在候选里
- [ ] 选项文案是存储源名称（如 `MinIO`），不带类型码
- [ ] 进页面时下拉默认选中当前启用的那一行（`current = 1`）；重新取清单后选中项还在候选里就保持不变
- [ ] 选中项就是当前启用项时按钮文案读「已启用」且置灰；换选另一个启用中的存储源后按钮读「启用」且可点
- [ ] 进页面时清单还没读完、选中项为空，按钮置灰；读完后按上面「已启用」与「启用」两种文案给出状态
- [ ] 表里一行都没启用（全部行 `DISABLED`）时：下拉禁用且占位文案「暂无启用的存储源」、选中项为空、「启用」按钮禁用

## 「当前启用」信息块与状态四态

- [ ] 信息块展示的是**当前启用的那个存储源**：把下拉换选到另一个存储源，块头的名称与状态、字段行都不变
- [ ] 块头是「当前启用」+ 名称 + 四态文案，不拼探测时间（探测时间只在「连接失败」的悬停提示里出现）
- [ ] 类型行只显示 `storageTypeName`（如 `MinIO`），不带类型码
- [ ] 参数行按 `params` 单列逐行铺开（一行一个参数），展示名是中文（`minio`：服务端点 / 访问密钥 / 私有密钥 / 文件桶 / 产物桶；`local`：根目录 / 文件目录 / 产物目录），参数值按等宽字体渲染，`accessKey` 与 `secretKey` 的取值完整可见；一个参数都没有时这一块没有参数行
- [ ] 参数区没有「密钥 已配置」这类占位行；把库里该行的 `secretKey` 清掉后重进页面，「私有密钥」那一行不再出现
- [ ] 给库里某行的 `config_json` 加一个未知键 → 页面上那一行显示原始键名（中文展示名只覆盖上面八个键）
- [ ] 四态逐个核对：`registered = true` 且 `probeOk = true` 是「已接入」；`probeOk = false` 是「连接失败」（悬停给出最近探测时间）；`probeOk` 为空是「未测试」；`registered = false`（停用的行）是「未接入」
- [ ] 参数极多时面板内滚动、卡片不被撑开：参数行多到面板装不下后，面板内出现滚动条，卡片量出来仍是宽 275px、高 305px；参数少时留白落在面板内部，卡片底部不空出一截
- [ ] 清单里没有 `current = 1` 的行时（全部行停用后重启）块内读「暂无启用的存储源」，读取期间读「加载中…」

## 设为当前：两步走

- [ ] 点「启用」→ 先弹确认窗，标题「启用 <存储源名称>」，正文首行是后端返回的 `message`，下面两块计数「排队中 · 将跑不了」与「执行中 · 将跑不了」
- [ ] 弹窗点「取消」或点遮罩空白 → **不发**设为当前请求，`wb_storage_source` 的 `is_current` 不变，此时新上传仍落在切换前的存储源
- [ ] 预览这一步不动库：弹窗弹出后核对 `wb_storage_source`，`is_current`、`status`、`update_time` 都不变
- [ ] 库里造几条 `QUEUED` 与 `RUNNING` 且链属于其他存储源的任务 → 两个计数与之一致
- [ ] 链的存储源取不到（档案行缺失）的任务不计入两个数字
- [ ] 确认弹窗点「确认启用」→ 提示「已启用<存储源名称>」，下拉选中项与信息块一起换成新存储源
- [ ] 启用后核对 `wb_storage_source`：只有目标行 `is_current = 1`，启用前的那一行变 0（先清后置，不出现两行同时为 1）
- [ ] 绕过界面直接调预览接口，目标行 `status = 'DISABLED'` → 回 `40458`（「已停用，请先启用再切换」）；`id` 查不到 → 回 `40457`
- [ ] 库里删掉目标行一个必填参数后调预览 → 回 `40001`，消息逐个报出缺的参数名；把该行 `storage_type` 改成未知码值 → 回 `40455`
- [ ] 探测失败（目标端点不可达）时确认启用 → 回 `40459`，`is_current` 不变、信息块仍是切换前那个存储源

## 切换后的实际效果

- [ ] 启用另一存储源后上传一份新文档 → 字节落在新存储源（`local` 落在它的存储根下，MinIO 落在它的桶里），`wb_file_object.storage_source_id` 等于新存储源 ID、`storage_type` 与之一致
- [ ] 切换前上传的对象**仍可下载、详情仍打得开**（读路径按记录里的数据源 ID 走）
- [ ] 在切换前写入的那条链上点任一环节的触发 → 回 `40453`，消息含链的数据源名与当前启用的数据源名
- [ ] 排队补投后才执行到的旧链任务在写产物那一步失败 → 任务状态 `FAILED`、`wb_knowledge_pipeline_task.error_code = TASK_STORAGE_MISMATCH`
- [ ] 把当前启用切回那条链所属的存储源 → 用**新的执行键**触发该环节不再被拒（换上游产物 / 换策略版本），任务可跑完
- [ ] 知识库级索引构建在切换后仍可执行（这条路径不设数据源门禁）
- [ ] 切换后旧头像仍能显示（读取按 `wb_user.avatar_storage_source_id` 走），再上传头像则落新存储源

## 重启与 fail-fast

- [ ] 空表：清空 `wb_storage_source`（或重建库）后启动后端 → **启动失败**，错误信息提示先执行初始化脚本；表里不会自动出现新行
- [ ] 首启正常：`init.sql` 已插入两行后启动 → 当前启用那一行探活通过，启动日志出现「当前启用的数据源 = <名称>」
- [ ] 首启后进页面 → 下拉默认选中库里的当前启用行，信息块展示同一行
- [ ] 启用另一存储源后重启后端 → 下拉默认选中项与信息块仍是重启前那一行，启动日志的当前启用与库一致
- [ ] 当前启用是 `local` 且 MinIO 没起 → 应用能正常启动
- [ ] 当前启用是 MinIO 时停掉 MinIO 再重启后端 → **启动失败**（当前启用那一行探活不过），库中该行 `last_probe_ok = 0`
- [ ] 把全部行改成 `DISABLED`（直接改库）后重启 → **启动失败**，不会按配置伪造当前数据源
- [ ] 启动不连未启用的存储源：MinIO 没起、当前启用是 `local` 时应用能启动，启动日志里没有 MinIO 的连接失败记录

## 探测结论、审计与页面边界

- [ ] 启动初始化回写：首启后核对当前启用那一行 `last_probe_ok = 1`、`last_probe_at` 非空，信息块块头显示「已接入」与这个时间
- [ ] 设为当前回写：确认启用后核对目标行 `last_probe_ok = 1`、`last_probe_at` 被刷新，信息块块头跟着变
- [ ] 探测结论只有两处会变：重启后端与确认启用；在库里手工改坏某行参数后刷新页面，块头仍显示上一次的结论
- [ ] 页面上没有新增 / 编辑 / 停用 / 删除 / 连接测试入口：卡内找不到这些控件，也没有表单与行操作列
- [ ] 绕过界面直接调六条已删接口：`GET /system/storage-sources/{id}`、`POST /system/storage-sources/{id}`、`POST /system/storage-sources/{id}/status`、`DELETE /system/storage-sources/{id}`、`POST /system/storage-sources/test` 都回 `404`，`POST /system/storage-sources` 回 `405`（该路径只映射了 GET）；`wb_storage_source` 与 `wb_audit_log` 都不变
- [ ] `GET /system/storage-sources` 的响应 `params` 里含 `accessKey` 与 `secretKey` 的明文取值，与库里 `config_json` 一致；响应里没有 `credentialConfigured` 字段
- [ ] 后端日志只出现参数名与数据源名：启用一次存储源后翻日志，找不到 `accessKey` / `secretKey` 的取值
- [ ] `wb_audit_log` 只多切换一条：动作 `STORAGE_SWITCH`，对象类型 `STORAGE_SOURCE`，对象 ID 是目标存储源 ID，前摘要是「当前启用 <切换前名称>」，后摘要含「当前启用 <目标名称>」与本次两个计数
- [ ] `wb_system_setting` 全程不被本页读写：启用与重启之后这张表的行数与内容都不变
