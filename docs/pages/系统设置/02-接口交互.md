# 接口交互

三个接口都是管理员接口（`StorageSourceController` 的三个方法各自标了 `@AdminOnly`），非管理员调用回 `40104`；本页的菜单与路由对所有登录用户可见，接口权限不随页面的可见性放开。业务失败同样是 HTTP 200 + `R.code`，提示由请求层拦截器弹出，页面代码只看成功分支（`catch {}` 留空）；通用口径（响应体形状、错误码分段、401 处理）见 `../../README.md` 的「全局约定」章。

| 触发                   | 前端调用链                                                                     | 接口                                                | 请求体 | 响应 `data`                 |
|------------------------|--------------------------------------------------------------------------------|-----------------------------------------------------|--------|-----------------------------|
| 进页面 / 启用成功后    | `SystemSettingView.loadSources` → `api/system.getStorageSourceList`            | `GET /system/storage-sources`                       | —      | `StorageSourceVO[]`（清单） |
| 点「启用」（第一步）   | `SystemSettingView.handleEnable` → `api/system.getStorageSourceCurrentPreview` | `POST /system/storage-sources/{id}/current/preview` | —      | `StorageSwitchPreviewVO`    |
| 确认弹窗点「确认启用」 | `SystemSettingView.confirmEnable` → `api/system.updateStorageSourceCurrent`    | `POST /system/storage-sources/{id}/current`         | —      | `StorageSwitchResultVO`     |

三个接口的路径都挂在 `@RequestMapping("/system/storage-sources")` 下，`/system` 前缀已在 Vite 代理里配好（`../vite.config.ts` 的 `^/system/`，与 SPA 路由 `/settings` 靠 `bypass` 区分）。

数据源的新增、编辑、启停、删除、连接测试与单条详情六条接口不在 Controller 里，页面上也没有对应入口：数据源由 `config/workbuddy-file.yml` 的 seed 或库内 SQL 维护，页面只做列举与启用。

成功响应的 `R.msg`：清单与预览用默认文案「操作成功」，设为当前回「切换成功」。

ID 类字段按全站的 Long 阈值口径下发（见 `../../README.md` 的「前后端契约的硬口径」）：雪花 ID 超过 JS 安全整数上界时是字符串，`queuedCount` / `runningCount` 这类计数仍是数字。

## 请求字段

三条接口都没有请求体，唯一入参是路径里的 `{id}`（数据源 ID）。`id` 不是数字时类型转换失败，按系统异常兜底回 `40500`。

## 响应字段

### `StorageSourceVO`（清单一项）

| 字段              | 类型                 | 说明                                                               |
|-------------------|----------------------|--------------------------------------------------------------------|
| `id`              | string               | 数据源 ID（雪花 ID 按字符串下发）                                  |
| `name`            | string               | 数据源名称                                                         |
| `storageType`     | string               | 存储类型码值（`minio` / `local`）                                  |
| `storageTypeName` | string               | 存储类型显示名（`MinIO` / `本地`）；码值认不出时回落到码值本身     |
| `status`          | string               | 状态码值（`ENABLED` / `DISABLED`）                                 |
| `current`         | boolean              | 是否当前启用（读行里的 `is_current`）                              |
| `configured`      | boolean              | 必填参数是否齐全（按库里已存值判断，不探活）                       |
| `registered`      | boolean              | 是否已注册进运行时存储路由                                         |
| `probeOk`         | boolean \| null      | 最近一次连接探测结论：`true` 通过 / `false` 失败 / `null` 从未探测 |
| `probeAt`         | string \| null       | 最近一次连接探测时间（ISO-8601 文本）；从未探测为空                |
| `params`          | `Map<string,string>` | 全部参数：**含 `accessKey` 与 `secretKey` 的取值**，键序与库里一致 |

参数字段名按类型定，键名与后端 `StorageSourceDef` 的常量一一对应：`minio` 取 `endpoint` / `accessKey` / `secretKey` / `fileBucket` / `artifactBucket`；`local` 取 `rootDir` / `fileDir` / `artifactDir`。`params` 就是这些键的全部取值，密钥类参数照常下发。

清单按主键升序返回，页面不排序，「当前启用」的判定读每一项的 `current`，没有额外的顶层字段。`registered` 读的是运行时路由的注册表，`probeOk` / `probeAt` 读的是行上最近一次探测的结论，两者都来自这次请求之前的状态（清单接口自身不探活）。

### `StorageSwitchPreviewVO` 与 `StorageSwitchResultVO`

| 字段               | 类型   | 说明                                                                    |
|--------------------|--------|-------------------------------------------------------------------------|
| `targetSourceId`   | string | 目标数据源 ID                                                           |
| `targetName`       | string | 目标数据源名称                                                          |
| `targetType`       | string | 目标数据源的存储类型码值                                                |
| `currentSourceId`  | string | 当前启用的数据源 ID；未启用任何数据源时为空                             |
| `currentName`      | string | 与 `currentSourceId` 同口径的名称                                       |
| `currentType`      | string | 与 `currentSourceId` 同口径的类型码值                                   |
| `queuedCount`      | number | 属于其他数据源且排队中的任务数                                          |
| `runningCount`     | number | 属于其他数据源且执行中的任务数                                          |
| `message`          | string | 影响面文案，页面把它放在确认弹窗正文首行                                |
| `switchedSourceId` | string | **仅切换响应有**：切换后当前启用的数据源 ID（与 `targetSourceId` 一致） |

**`current*` 三个字段在两个响应里指不同时刻**：预览那一份是**切换前**的当前启用值，切换那一份按切换后的生效值回填（等于目标）。页面只用 `message` 与两个计数，切换成功后重新取一次清单，这三个字段不参与渲染。

影响面只统计**属于其他数据源且未落终态的任务**：目标就是当前启用项时两个数字都是 0，切换接口也随即返回，`message` 是「当前启用的已经是 <名称>」。页面在这个情况下把「启用」按钮禁用，这条路径只在绕过界面直接调用时出现。

## 本页可能出现的失败

| code  | 触发场景                                                                         |
|-------|----------------------------------------------------------------------------------|
| 40001 | 目标的必填参数缺项（消息逐个报出缺的参数名）                                     |
| 40104 | 非管理员调用三个接口中的任一个                                                   |
| 40101 | 未认证（令牌缺失或已失效）                                                       |
| 40457 | 路径里的 `id` 查不到行（不存在或已逻辑删除）                                     |
| 40458 | 目标行已停用时调用预览或设为当前                                                 |
| 40459 | 设为当前时的连接探测不通过（消息带数据源名称与底层原因）；预览不落这个码         |
| 40455 | 行里的存储类型码值无法识别：那一行不能设为当前                                   |
| 40500 | 系统异常兜底；路径里的 `id` 不是数字；启动期 `file-center.storage-type` 取值非法 |

非管理员能打开这一页：菜单项与路由都不带管理员标记，页面上只有页标题与一行灰字空态，卡片不渲染；接口仍是管理员接口，绕过界面直接发请求由 `40104` 兜底。
