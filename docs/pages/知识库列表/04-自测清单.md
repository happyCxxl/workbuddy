# 04 自测清单

改完这一页（含后端归属口径与共用骨架样式）要手工验的点。**前端与后端都改过时，"归属"那几条必须用两个账号验**：一个账号自测不出隔离问题。

## 准备

- 后端与前端 dev server 都起来（后端 `localhost:4388`，前端 `127.0.0.1:5173`）。
- 至少两个账号：一个**管理员**（如 `admin`）、一个**普通用户**（如 `test01`）。普通用户最好名下**没有任何知识库**，用来验空态与"看不到别人的库"。
- 库里现存的 `默认知识库`、`演示库-完整链路` 的 `user_id` 为空（早期数据），按口径**只有管理员看得到**，普通用户看不到属正常。

## 一、可见范围（用两个账号交替验）

| 检查点                                 | 期望结果                                                                         |
|----------------------------------------|----------------------------------------------------------------------------------|
| 普通用户打开知识库页                   | 只列出自己创建的库；一个都没有时是「还没有启用的知识库」并提示切到「已停用」查看 |
| 普通用户看统计条                       | 三个数与列表**同一范围**（自己名下），不是全平台的数字                           |
| 普通用户导入文档时看候选库下拉         | 只有自己的库（含停用的，标灰）                                                   |
| 管理员打开知识库页                     | 能看到所有人的库（含两个早期种子库）                                             |
| 普通用户手改地址栏 / 请求他人库的详情  | 报「知识库不存在」（`40401`），**不是**「权限不足」                              |
| 普通用户对他人库调启停 / 删除 / 改绑定 | 同样 `40401`，且库里数据没有任何变化                                             |
| 普通用户拿他人库 ID 提交文档           | `40401`，不产生 `wb_file_result` 行                                              |
| 新建一个知识库后查库                   | 新行 `user_id` = 当前登录用户（不是 NULL）                                       |

## 二、停用 / 启用

| 检查点                       | 期望结果                                                             |
|------------------------------|----------------------------------------------------------------------|
| 卡片上「停用」一个启用中的库 | 二次确认框写明"停用后将拒绝新文件接入与检索"；确认后标签变「已停用」 |
| 停用后再看该卡片             | 操作行显示「启用」；统计条「已启用」−1、总数不变                     |
| 已停用库的导入入口           | 导入弹窗里该库标灰不可选；强行提交报 `40421`                         |
| 点「启用」                   | 状态回到「已启用」，「已启用」计数 +1                                |

## 三、导入文档与幂等键

| 检查点                                      | 期望结果                                                                                                                               |
|---------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------|
| 同一份文件导入两次（同一个库）              | **两条归档记录**：`wb_file_result` / `wb_submit_log` 各多一行（第二行 `request_id` 不同）；后端日志**不应**出现对应第二行的 `幂等回放` |
| 同一份文件导入到另一个库                    | 目标库正常建档；返回的 `submitLog.knowledgeBaseId` 是**当前库**而不是上一次的库                                                        |
| 同一次提交重试（断网/超时后点「开始导入」） | 沿用同一个 `requestId`，后端打 `幂等回放`，**不重复建档**（三张表行数不变）                                                            |
| 移出列表后再加回同一份文件                  | 视为新的一次提交（新 `requestId`），会正常新建档                                                                                       |
| 弹窗关闭再重开                              | 列表清空；重新选中的同一份文件也是新的一次提交                                                                                         |

> 一句话口径：**幂等键防的是"同一次请求被重复送达"，不是"同一个文件被提交两次"**。同一份文件重新上传会拿到新的 `fileId`，对系统就是两份文件（见 `docs/README.md` 全局约定「幂等键」）。

## 四、页面骨架与交互回归

| 检查点               | 期望结果                                                                                                                                              |
|----------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------|
| 点刷新               | 卡片**不消失**、不闪成「加载中…」；滚动位置与容器高度不变，刷新图标旋转                                                                               |
| 进页面默认视图       | 落在「已启用」芯片上，列表只有启用中的库（停用的**不出现**）；页脚「共 N 个」= 启用数                                                                 |
| 同屏计数             | 只有页脚一处显示总数（工具条里不重复）                                                                                                                |
| 新建入口位置         | 网格**左上角第一位**的虚线卡，无需滚动即可见                                                                                                          |
| 虚线卡高度           | **有数据与无数据两种情况一样高**（约 340px）；切到「已停用」这种没有数据的视图时，也不塌成 180px 的小方块                                             |
| 切状态芯片           | 只有「已启用 / 已停用」两枚、**没有「全部」**；切到「已停用」只看到停用的库，且回到第 1 页                                                            |
| 换排序               | 回到第 1 页；工具条与页脚的内边距和其它列表页（用户管理）**一致**                                                                                     |
| 每页条数             | 页脚**只有**「共 N 个知识库」+ 分页（上一页 / 当前页 / 下一页，不列全部页码），**没有条数选择器**；每页固定 12 条（2/3/4 列下都能整除，末行不留空位） |
| 停用后当前列表       | 卡片从「已启用」视图**立刻移出**，toast 写明「已停用，已移出「已启用」列表」                                                                          |
| 空态（默认视图）     | 没有启用的库时文案是「还没有启用的知识库」+ 指向「已停用」的提示，**不**显示「清除筛选」                                                              |
| 空态（偏离默认）     | 有关键字或切到「已停用」时，文案是「没有符合当前筛选条件的知识库」并有「清除筛选」按钮；点它回到「已启用」+ 空关键字                                  |
| 说明为空的知识库卡片 | 显示「暂无业务场景说明」，不留空白                                                                                                                    |
| 库名与状态标签       | 把库名填到上限（14 个汉字）时：库名**整行显示完整、不截断**，状态标签仍是一行且完整显示「已启用 / 已停用」；卡片不出现横向溢出                        |
| 名称长度上限         | 弹窗里名称框最多输入 **14 字**（右下角 `n/14`）；粘贴超长内容后保存被规则拦下并提示「知识库名称最长 14 字符」                                         |
| 说明长度上限         | 弹窗里说明框最多输入 **64 字**（右下角字数计数器 `n/64`），继续打字进不去；粘贴超长内容后保存被规则拦下并提示                                         |
| 卡片操作行宽度       | 六个入口在一行内不折行（窗口缩到最窄也不折）                                                                                                          |
| 卡片点击 / 操作按钮  | 点卡片进处理链页；点操作按钮**不**跳转                                                                                                                |
| 编辑弹窗三件套       | 「不绑定」时三个下拉禁用但仍可见；弹窗高度不随开关切换而跳                                                                                            |
| 「绑定」但没选全     | 保存时提示点名缺哪个类型，不提交                                                                                                                      |
| 与用户管理页对照     | 两页的主按钮/次按钮/刷新按钮外观一致（样式已上移到 `page-shell.css`）                                                                                 |

## 五、构建与检查

| 检查点       | 命令                                | 期望                                                                   |
|--------------|-------------------------------------|------------------------------------------------------------------------|
| 后端         | `mvn -o -pl knowledge-biz -am test` | 全绿（含归属规则的正/反用例）                                          |
| 后端全量门禁 | `mvn -o verify`                     | 构建成功，checkstyle / PMD / SpotBugs 0                                |
| 前端         | `cd web && pnpm lint`               | 八项检查全过（含 `check-spec` 的未用样式类、`check-table` 的表格口径） |
| 推送前       | `git push`                          | 钩子按改动范围跑检查，逐步打印进度                                     |

## 六、已知不覆盖（不要当成缺陷）

- 环节页 / 索引页 / 评测页按 ID 访问的接口**未加归属校验**（见 `README.md` 待定项）。
- 批量查绑定接口 `GET /knowledge-base/strategy-bindings` 仍返回全平台绑定行（响应不含库名与内容）。
- 筛选条件不持久（刷新后回到「已启用 + 默认排序」）。
- 种子数据里两个 `user_id` 为空的知识库仍在库里，按口径仅管理员可见。
