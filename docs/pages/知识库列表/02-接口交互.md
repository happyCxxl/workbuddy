# 02 接口交互

封装位置：列表/统计/详情/增删改启停在 `../../../web/src/api/knowledge-base.ts`，策略绑定下拉与提交绑定在 `../../../web/src/api/strategy.ts`，导入弹窗用 `../../../web/src/api/file.ts`。三者都只是 `http`（`web/src/api/http.ts`）的薄封装，响应解包成业务数据由拦截器统一完成（见 `../../README.md` 的「全局约定」）。

## 调用时机总表

| 时机                                   | 接口                                                                                         |
|----------------------------------------|----------------------------------------------------------------------------------------------|
| 进入页面（`onMounted`）                | `GET /knowledge-base/page` + `GET /knowledge-base/stats`                                     |
| 查询 / 切状态 / 切排序 / 翻页 / 点刷新 | `GET /knowledge-base/page`（切筛选时页码回 1）                                               |
| 点刷新、增删改与启停之后               | `GET /knowledge-base/stats`                                                                  |
| 打开新建弹窗（首次）                   | `GET /strategy-versions` ×3（三件套，只取启用中）                                            |
| 打开编辑弹窗                           | 先填列表快照，再 `GET /knowledge-base/{id}`                                                  |
| 保存新建                               | `POST /knowledge-base/create`（+ 开关为绑定时 `PUT /knowledge-base/{id}/strategy-bindings`） |
| 保存编辑                               | `PUT /knowledge-base/{id}`（+ 同上）                                                         |
| 卡片「停用 / 启用」                    | `POST /knowledge-base/{id}/disable` / `.../enable`                                           |
| 卡片「删除」                           | `DELETE /knowledge-base/{id}`                                                                |
| 导入弹窗打开                           | `GET /knowledge-base/page`（`size=500`，一次拉全库）                                         |
| 导入弹窗「开始导入」                   | 每个文件 `POST /files` → `POST /knowledge-base/{id}/submit`                                  |

## 一、`GET /knowledge-base/page`

分页查询。**接口不接受"创建人/归属"参数** —— 可见范围由服务端按登录用户决定（见 `README.md`）。

| 参数      | 类型   | 必填 | 说明                                                                                    |
|-----------|--------|------|-----------------------------------------------------------------------------------------|
| `current` | number | 否   | 当前页，默认 1                                                                          |
| `size`    | number | 否   | 每页条数，默认 10；本页**固定传 12**（无条数选择器）；导入弹窗传 500                    |
| `name`    | string | 否   | 名称模糊关键字                                                                          |
| `status`  | number | 否   | 1 启用 / 0 停用；接口层不传即不过滤，但**本页总是传**（界面只有这两态、默认「已启用」） |
| `sort`    | string | 否   | `DEFAULT` / `UPDATED` / `NAME`；**未知值按默认**（不报错）                              |

响应 `data` 是 `PageResult<KnowledgeBaseVO>`（`records` / `total` / `size` / `current` / `pages`）。单条字段中前端用到的：

| 字段                                                                          | 说明                                                                       |
|-------------------------------------------------------------------------------|----------------------------------------------------------------------------|
| `id`                                                                          | 雪花 ID，**字符串**（超过 JS 安全整数的一律字符串化，全局口径）            |
| `name` / `description`                                                        | 名称 / 业务场景说明（说明可为 null）                                       |
| `status`                                                                      | 1 启用 / 0 停用                                                            |
| `documentCount`                                                               | 该库的 `wb_file_result` 行数（= 已建档文档数，同一文件重复提交会各占一行） |
| `publishedIndexVersion`                                                       | 已发布索引版本号（如 `v3`；未发布为 null，界面显示「未发布」）             |
| `preprocessStrategyVersion` / `chunkStrategyVersion` / `embedStrategyVersion` | 三条绑定摘要（`name-version` 合成串；无绑定为 null）                       |
| `strategyBindingEnabled`                                                      | 策略绑定开关：1 开启 / 0 关闭（关时策略摘要显示「开关已关闭」）            |
| `updateTime`                                                                  | 最近更新时间（ISO 字符串）                                                 |

**列表接口不下发策略版本的 ID**（只有摘要串），ID 只在详情接口里 —— 编辑弹窗要用 ID 回填下拉，编辑时须再取一次详情。

## 二、`GET /knowledge-base/stats`

无参数。响应三个字段都是**数字**（计数不字符串化）：

| 字段                 | 说明                   |
|----------------------|------------------------|
| `knowledgeBaseCount` | 可见范围内知识库总数   |
| `enabledCount`       | 其中启用中的数量       |
| `documentCount`      | 可见库下的已建档文档数 |

三个数与 `page` 同一可见范围：普通用户只数自己创建的库，管理员数全部。

## 三、`GET /knowledge-base/{id}`

查单个库详情。比列表多三个字段：`preprocessStrategyVersionId` / `chunkStrategyVersionId` / `embedStrategyVersionId`（绑定版本行 ID，无绑定为 null），并带 `documentCount`。

**别人的库与不存在的库都返回 `40401`**（按"不存在"处理，不区分"存在但无权"）。

## 四、`POST /knowledge-base/create`

| 字段                     | 类型   | 必填 | 说明                                                                                |
|--------------------------|--------|------|-------------------------------------------------------------------------------------|
| `name`                   | string | 是   | ≤14 字符，超长报 `40001`「知识库名称最长 14 字符」（上限口径见 `01-页面功能.md`）   |
| `description`            | string | 否   | ≤64 字符，超长报 `40001`「业务场景说明最长 64 字符」（上限口径见 `01-页面功能.md`） |
| `strategyBindingEnabled` | number | 是   | 必填，只接受 1 开启 / 0 关闭；缺失、null 或越界报 `40001`                           |

响应 `data` 是**新建知识库 ID 的字符串**（不是对象）。前端拿到后，若开关为「绑定」就用它调一次绑定接口。

**创建一律默认启用**：`status` 不接受入参；归属取当前登录用户，无登录上下文直接 `40101`。

## 五、`PUT /knowledge-base/{id}`

只改名称 / 说明 / 策略绑定开关。请求体里的 `id` 必须与路径一致（后端会用路径值覆盖），字段与创建相同（开关同样必填，只接受 1 开启 / 0 关闭，缺失或越界报 `40001`）。**状态与策略绑定不在这里改**，各有独立接口。

## 六、`POST /knowledge-base/{id}/disable` 与 `.../enable`

无请求体，响应 `data` 为 `true`。两者都是**严格状态迁移**：

| 情况               | 结果                     |
|--------------------|--------------------------|
| 停用一个已停用的库 | `40402 知识库状态不合法` |
| 启用一个启用中的库 | `40402 知识库状态不合法` |

卡片按当前状态只渲染其中一个入口，正常操作不会撞上这两条；撞上说明状态已被别处改过，刷新即可。

## 七、`DELETE /knowledge-base/{id}`

逻辑删除（`del_flag` 置 `DelFlag.DELETED`，即 1），**无恢复接口**。删除后该库及其下文档任务在界面上都不可见。

## 八、`PUT /knowledge-base/{id}/strategy-bindings`

一次设置整套三件套绑定：

```json
{ "bindings": [
  { "strategyType": "PREPROCESS", "strategyVersionId": "…" },
  { "strategyType": "CHUNK",      "strategyVersionId": "…" },
  { "strategyType": "EMBED",      "strategyVersionId": "…" }
] }
```

**必须一次给全三件套且每项都有版本**，不满足时 `40001`（错误信息会说明缺什么）。本接口表达"确定了一套策略组合"，不是逐类型增量改；"开关开着但还没绑"由**不调用**本接口表达。此外：未知策略类型、请求内类型重复、版本已停用、库关闭了策略绑定开关，都会 `40001`。

## 九、`GET /strategy-versions`

新建/编辑弹窗的数据源，按类型逐个查（三件套 = 3 次请求，可并发）：

| 参数              | 说明                                                       |
|-------------------|------------------------------------------------------------|
| `type`            | `PREPROCESS` / `CHUNK` / `EMBED`                           |
| `includeInactive` | 本页固定传 `false` —— 后端会拒绑已停用版本，列出来也选不了 |

前端把三次结果按 `type` 分组，下拉文案是 `name-version`（同名多版本靠版本号区分）。

## 十、导入文档（弹窗）

| 接口                               | 请求                                     | 响应                            |
|------------------------------------|------------------------------------------|---------------------------------|
| `POST /files`                      | `multipart/form-data`，字段名固定 `file` | `data` = fileId（字符串）       |
| `POST /knowledge-base/{id}/submit` | `{ "fileId": "…", "requestId": "…" }`    | `{ submitLog, pipelineTaskId }` |

- `POST /files` 先校验后落库：扩展名白名单 → 大小上限 → 空文件 → 魔数识别（真实内容与白名单），失败不落库，回 `40422`（原因入 detail：格式不在允许范围 / 文件超过大小上限 / 文件已损坏 / 文件已加密 / 图片类型暂不支持）。

- `requestId` 是**幂等键，一次提交一个**（**不按文件去重**）：同一份文件重新上传会拿到新的 fileId，对系统来说就是两份文件，要新建档；这个键只用来防"同一次请求被重复送达"（网络重试、并发重发）——**同一次提交的重试沿用同一个值**，换一次提交（移出列表再加回、重开弹窗）换新值。为空报 `40420`。
  契约以服务端为准：`WbSubmitLog.requestId`「一次提交唯一」、`FileSubmitDTO.requestId`「提交端生成，通常 UUID；网络重试沿用同一值」。若把它写成「文件名 + 大小 + 修改时间」之类的文件指纹，等于按文件去重：同一份文件再导入会撞同一个键，后端幂等回放直接返回首次记录 —— 界面显示成功、实际一行未建；把同一份文件导入另一个库时更隐蔽（返回的是**第一个库**那条记录）。
- `pipelineTaskId` 首次提交时为 null —— 只建档不建任务，解析要在执行链页手动触发。
- `submitLog.failReason` 是码值（`FileValidationFailReason` 枚举名），`submitLog.failReasonLabel` 是后端下发的中文名；界面直接展示中文，前端不维护码值映射表。
- 上传前前端会做一次**提示性**预检（扩展名 / 大小 / 空文件），最终判定仍在后端（按 Tika 魔数识别真实格式，不看扩展名）。单文件上限 100MB，接受 pdf / doc / docx / xls / xlsx。

## 本页会遇到的错误码

| code  | 触发场景                                                | 前端表现                           |
|-------|---------------------------------------------------------|------------------------------------|
| 40001 | 名称超长、绑定缺项/重复、绑已停用版本、库关闭了绑定开关 | 提示后端 `msg`                     |
| 40101 | 令牌失效 / 未认证                                       | 拦截器清令牌并跳登录页             |
| 40401 | 库不存在、已删除，**或不是当前用户可访问的库**          | 提示「知识库不存在」               |
| 40402 | 重复启停                                                | 提示后端 `msg`                     |
| 40420 | 提交缺少幂等键                                          | 提示「缺少幂等键」                 |
| 40421 | 向已停用的库提交文档                                    | 提示「知识库未启用，不可提交文档」 |
| 40500 | 系统异常                                                | 拦截器统一提示                     |

页面里的 `catch {}` 留空是正常写法：失败提示由拦截器负责，页面只处理成功分支。
