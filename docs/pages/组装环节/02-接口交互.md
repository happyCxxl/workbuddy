# 接口交互

本环节用到三个接口，都由请求层统一处理：业务失败也是 HTTP 200 + `R.code`，提示由拦截器弹出，页面代码只看成功分支。通用口径（响应体形状、错误码分段、401 处理、`stage-content` 的分页参数）见 `../../README.md` 的「全局约定」章与 `../解析环节/02-接口交互.md`，本页只写组装特有的部分。

| 触发                                   | 前端调用链                                                                   | 接口                                      | 请求                                                                   | 响应 `data`                      |
|----------------------------------------|------------------------------------------------------------------------------|-------------------------------------------|------------------------------------------------------------------------|----------------------------------|
| 点「触发下一环节」并确认（下游）       | `PipelineStageView.onTriggerConfirm` → `api/pipeline.addStageTrigger`        | `POST /file-results/{id}/preprocess`      | `strategyVersionId`（可选）、`upstreamProductId`（必填，= 本组装产物） | `{pipelineTaskId, …}`            |
| 从解析卡片触发组装                     | 同上，`stage` 传 `STRUCTURE`                                                 | `POST /file-results/{id}/structure`       | `upstreamProductId`（必填）                                            | `{pipelineTaskId, fileResultId}` |
| 点「详情」（组装卡片）                 | `StageDetailDrawer` 的 watch → `api/pipeline.getStageDetail('STRUCTURE', …)` | `GET /file-results/{id}/structure-detail` | 查询参数 `taskId`（可选）                                              | `StructureDetailVO`              |
| 点「详情」/ 翻页 / 切页签 / 结构树滚动 | `api/pipeline.getStageContent`                                               | `GET /file-results/{id}/stage-content`    | 查询参数 `stage=STRUCTURE`、`taskId`、`current`、`size`                | 产物内容分页                     |

`taskId` 一律传**被点的那张卡片**的任务 ID：不传会取该环节最新任务，抽屉是从某张卡打开的，不传就会显示成「最新一次」而不是「这一张」。

## `POST /file-results/{id}/structure`

| 参数                | 必填 | 说明                                    |
|---------------------|------|-----------------------------------------|
| `upstreamProductId` | 是   | 指定上游 **PARSE** 产物；未指定 → 40436 |

响应 `{pipelineTaskId, fileResultId}`：异步接口，只登记任务，结果要轮询血缘。

**触发语义**（五个环节同一套：先校验存储一致性，再按执行键查重）：

- 执行键 = 文件结果 + `STRUCTURE` + 上游解析产物 ID + 0（组装无策略，策略位写 0 哨兵）；
- 查到（任何状态，含执行中）→ **40431**，消息「组装任务已创建（taskId=…，状态 …），请勿重复触发」，**不返回既有结果**；
- 查不到 → 新建一条 `QUEUED` 任务并入队；
- 想再组装一次就**换上游产物**：从另一张解析卡片发起（执行键不同 = 新链路），旧任务与旧产物保留；从同一张解析卡片反复触发只会拿到 40431。

## `GET /file-results/{id}/structure-detail`

查询参数 `taskId`（可选，缺省取该环节最新任务）。

| 字段                                                | 说明                                                                                                                                                               |
|-----------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `fileResultId` / `taskId` / `stage` / `status`      | 文件结果、任务与状态（`PipelineTaskStatus` 枚举名）                                                                                                                |
| `errorCode` / `errorMsg`                            | 失败时非空：任务级码（`STRUCTURE_EMPTY` / `STRUCTURE_UPSTREAM_UNREADABLE` / `STRUCTURE_FAILED` / `TASK_ENQUEUE_FAILED`）                                           |
| `startedAt` / `finishedAt`                          | 起止时间（ISO 串），未开始/未结束为空                                                                                                                              |
| `artifactId` / `contentHash` / `capabilitySnapshot` | 产物引用与内容指纹；能力快照是 JSON 文本，页面不消费                                                                                                               |
| `steps[]`                                           | 子步骤：`stepName` / `status` / `duration` / `warningCount` / `error`                                                                                              |
| `stageStats`                                        | 组装统计（读产物现算，见下）；**产物不可读时为 null**                                                                                                              |
| `stageSummary`                                      | 结论一句话；取值规则见下                                                                                                                                           |
| `summary`                                           | 组装统计视图：`elementCount` / `titleCount` / `paragraphCount` / `tableCount` / `imageCount` / `relationCount` / `conflictCount` / `warningCount`；无产物时为 null |
| `warnings[]` / `conflicts[]`                        | 质量告警文案、冲突记录（`primaryElementId` / `backupElementId` / `message`）；无产物时为空列表                                                                     |
| `outline[]`                                         | 文档内容大纲（统一文档元素、按阅读顺序全量）；无产物时为空列表                                                                                                     |

### `stageStats` 的键

计数一律是**数字**（前端按数字格式化千分位）；`schemaVersion` 是字符串；`durationMs` 在起止时间缺失时为 null。

| 键                           | 类型   | 单位 | 含义                                                              |
|------------------------------|--------|------|-------------------------------------------------------------------|
| `elementCount`               | 数字   | 个   | 元素总数（顶层元素）                                              |
| `titleCount`                 | 数字   | 个   | 标题元素数                                                        |
| `chapterCount`               | 数字   | 层   | 章节层数：有 `SECTION` 节点时按章节节点数计，没有时按一级标题数计 |
| `level1Count`                | 数字   | 个   | 一级标题数（`level` 空或 ≤ 1）                                    |
| `level2Count`                | 数字   | 个   | 二级标题数                                                        |
| `level3PlusCount`            | 数字   | 个   | 三级及以下标题数                                                  |
| `parentChildCount`           | 数字   | 条   | 章节树父子关系数                                                  |
| `continuationCount`          | 数字   | 处   | 续表数（全部 `CONTINUATION_OF` 关系条数）                         |
| `suspectedContinuationCount` | 数字   | 处   | 疑似续表数（放宽规则命中，关系 `detail` 标「疑似」）              |
| `tracedCount`                | 数字   | 个   | 溯源齐备的元素数（文件引用 + 定位路径都有）                       |
| `provenanceCoverage`         | 数字   | %    | 溯源覆盖率（四舍五入取整；无元素记 0）                            |
| `durationMs`                 | 数字   | 毫秒 | 本次运行耗时（起止时间相减，缺失为 null）                         |
| `withoutBboxCount`           | 数字   | 个   | 无坐标元素数（阅读顺序按「坐标排 + 无坐标按原序追加」）           |
| `repeatedSegmentCount`       | 数字   | 段   | 重复段数（元素 `marks` 含 `REPEATED_SEGMENT`）                    |
| `repeatedPageCount`          | 数字   | 页   | 重复页数（页 `marks` 含 `REPEATED_PAGE`）                         |
| `noisePageCount`             | 数字   | 页   | 噪声页数（页 `marks` 含 `NOISE_PAGE`）                            |
| `pageCount`                  | 数字   | 页   | 页总数（Word / Excel 无页概念时为 0）                             |
| `continuationFromPage`       | 数字   | 页   | 疑似续表涉及的最小页（一条都取不到时**不下发该键**）              |
| `continuationToPage`         | 数字   | 页   | 疑似续表涉及的最大页（同上）                                      |
| `schemaVersion`              | 字符串 | —    | 产物 schema 语义化版本（产物里没有该字段时不下发）                |

共 19 个键：16 个必给，最后三个视产物内容条件给。

### `stageSummary` 的取值规则

| 情形                      | 文案                                                                                    |
|---------------------------|-----------------------------------------------------------------------------------------|
| 失败 / 已取消             | `errorMsg`，为空时「组装失败」                                                          |
| 进行中 / 排队中           | null                                                                                    |
| 成功 / 部分成功，统计缺失 | **null**（产物不可读时不陈述结论）                                                      |
| 成功 / 部分成功，空树     | 「无任何可组装元素（空树）」                                                            |
| 成功 / 部分成功，无异常项 | 「结构可用」                                                                            |
| 成功 / 部分成功，有异常项 | 「结构可用 · 溯源偏低 N% · 疑似续表 N 处 · 重复与噪声待处置」（只陈述异常项，顺序固定） |

### `outline[]` 元素字段

| 字段                         | 说明                                                                                         |
|------------------------------|----------------------------------------------------------------------------------------------|
| `elementId`                  | 产物元素 ID（左栏文档块与右栏列表行按它对齐）                                                |
| `type` / `text`              | 元素类型（`UnifiedElementType` 枚举名）与文本                                                |
| `level`                      | 标题层级（`TITLE` 专属，1 起）                                                               |
| `page` / `pageRange`         | 单页元素的页码 / 跨页元素的页码范围（跨页元素保留首页 `page`，`pageRange` 列出覆盖的全部页） |
| `rows` / `cols` / `cells[]`  | 表格行列数与单元格（`row` / `col` / `text` / `isHeader`，行列从 0 起）                       |
| `conflictStatus` / `caption` | 冲突状态（`PRIMARY` / `BACKUP`）与图注                                                       |

大纲按阅读顺序全量下发（不分页），只过滤掉文档根与表格单元格；表格的单元格明细在 `cells` 里，前端不再另取内容接口拼表。

## `GET /file-results/{id}/stage-content?stage=STRUCTURE`

参数、响应结构与分页口径与解析环节完全一致（见 `../解析环节/02-接口交互.md` 与 `03-接口逻辑.md`），本环节的差异只有两点：

- `docPage` 对本环节无实际意义（左栏不是按页预览，前端不会传）；
- `extra` 的键：`level`（标题层级）、`page`、`rows` / `cols`、`bbox`（跨页表格合并后 `bbox` 为空，没有坐标）。类型与其他环节同为 `StageContentExtraVO`，本环节只用这几个字段。

`items[]` 的 `alignKey` 是产物元素 ID、`status` 是冲突状态；`display` 是元素文本（表格通常为空，列表侧回落「表格 R 行 × C 列」占位）。

## 本环节可能出现的失败

| code  | 触发场景                                                           |
|-------|--------------------------------------------------------------------|
| 40001 | 环节不在白名单；`taskId` 不属于该文件该环节                        |
| 40101 | 未认证（令牌缺失或已失效）                                         |
| 40401 | 越权访问别人的文件结果（与「不存在」响应一致）                     |
| 40431 | 触发时该执行键上已有组装任务（任何状态都拒）                       |
| 40432 | 文件结果不存在；指定的上游产物不存在 / 环节不对 / 不属于该文件结果 |
| 40436 | 触发组装时没给 `upstreamProductId`（下游环节必填）                 |
| 40453 | 链的源文件所在数据源与当前启用的数据源不一致                       |
| 40500 | 系统异常兜底                                                       |

任务级错误码（落在 `errorCode`，不是接口返回码）：`STRUCTURE_EMPTY`（空树）、`STRUCTURE_UPSTREAM_UNREADABLE`（上游解析产物缺失 / 读不到 / 反序列化失败）、`STRUCTURE_FAILED`（执行异常兜底）。

## 与后端不一致 / 需注意的地方

- **`stats` 是整份替换，不是增量合并**：组装节点的 `stats` 全部由组装统计给出（含 `schemaVersion`），通用统计里的切片 / 向量化字段在组装节点上不存在。
- **`schemaVersion` 在 `stats` 里，不在 `capability` 里**：卡片身份行对组装环节取 `stats.schemaVersion`；`capabilitySnapshot` 是 JSON 文本且组装卡片不消费它。
- **`outline` 与 `stage-content` 是同一份元素的两种下发**：都来自该次运行产物顶层的元素、顺序一致，`stage-content` 分页给（每页 100 条），`outline` 一次给全量并带 `cells`。
- **`total` 的口径随 `docPage` 变**：解析环节传 `docPage` 时 `total` 是该页条数；组装不传，`total` 是全文条数。
- **`truncated` 是「这一页之后还有内容」**：不能按 `current × size < total` 理解，最后一页不满时两者结论不同。
- **组装详情不下发上游产物 ID**：左栏是组装产物本身，不再做上游对照；要表达「基于哪次解析」用链图的边。
- **前端关键字过滤只作用于当前页**：后端按页给内容，跨页搜索要后端加 `keyword` 参数。
