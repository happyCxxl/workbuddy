# 接口交互

本环节用到五个接口，都由请求层统一处理：业务失败也是 HTTP 200 + `R.code`，提示由拦截器弹出，页面代码只看成功分支。通用口径（响应体形状、错误码分段、401 处理）见 `../../README.md` 的「全局约定」章。

| 触发                                 | 前端调用链                                                            | 接口                                   | 请求                                                     | 响应 `data`                      |
|--------------------------------------|-----------------------------------------------------------------------|----------------------------------------|----------------------------------------------------------|----------------------------------|
| 进入执行链页 / 轮询 / 触发后刷新     | `PipelineStageView.refresh` → `api/pipeline.getLineage`               | `GET /file-results/{id}/lineage`       | —                                                        | 血缘（节点 + 边）                |
| 点「详情」                           | `StageDetailDrawer.loadSource` → `api/pipeline.getSourceFile`         | `GET /files/{fileId}`                  | —                                                        | **原始字节流**                   |
| 点「详情」                           | `StageDetailDrawer` 的 watch → `api/pipeline.getParseDetail`          | `GET /file-results/{id}/parse-detail`  | 查询参数 `taskId`（可选）                                | `ParseDetailVO`                  |
| 点「详情」/ 翻页 / 切页签 / 左栏翻页 | `api/pipeline.getStageContent`                                        | `GET /file-results/{id}/stage-content` | 查询参数 `stage`、`taskId`、`docPage`、`current`、`size` | 产物内容分页                     |
| 点「触发下一环节」并确认             | `PipelineStageView.onTriggerConfirm` → `api/pipeline.addStageTrigger` | `POST /file-results/{id}/parse`        | 无请求体（解析**不接受**可选参数）                       | `{pipelineTaskId, fileResultId}` |

`taskId` 一律传**被点的那张卡片**的任务 ID：不传会取该环节最新任务，抽屉是从某张卡打开的，不传就会显示成「最新一次」而不是「这一张」。

## `GET /file-results/{id}/parse-detail`

| 字段                                       | 说明                                                                              |
|--------------------------------------------|-----------------------------------------------------------------------------------|
| `taskId` / `stage` / `status`              | 任务标识与状态（`QUEUED` / `RUNNING` / `SUCCESS` / `PARTIAL_SUCCESS` / `FAILED`） |
| `errorCode` / `errorMsg`                   | 失败时的错误码与说明，成功为空                                                    |
| `startedAt` / `finishedAt`                 | 起止时间（ISO 串），未开始/未结束为空                                             |
| `steps[]`                                  | 子步骤：`stepName` / `status` / `duration` / `warningCount` / `error`             |
| `warnings[]`                               | 告警文案列表；**无任务或无产物时是空列表，不是 null**                             |
| `parseStats`                               | 解析统计（见下）；**产物不可读时为空对象/空值**，页面按缺项显示 `—`               |
| `parseSummary`                             | 结论一句话；解析进行中为空；**产物不可读时也为空，不陈述「无异常」**              |
| `productId` / `artifactId` / `contentHash` | 产物引用，无产物时为空                                                            |

`parseStats` 的字段：`pageCount` / `elementCount` / `bodyCount` / `tableCount` / `imageCount` / `headerFooterCount` / `failedUnitCount` / `durationMs`。

**易踩的地方**：`parseStats` 与 `parseSummary` 都可能为空（无任务、无产物、产物读不出来），页面不能把它当一定有值；`warnings` 是空列表而不是 null，但前端仍按「可能为 null」处理。

## `GET /file-results/{id}/stage-content`

查询参数：

| 参数      | 必填 | 说明                                                                 |
|-----------|------|----------------------------------------------------------------------|
| `stage`   | 是   | 环节白名单：`PARSE` / `STRUCTURE` / `PREPROCESS` / `CHUNK` / `EMBED` |
| `taskId`  | 否   | 缺省取该环节最新任务                                                 |
| `docPage` | 否   | 只取该**文档页**的元素（从 1 起）；解析/组装环节才有页概念           |
| `current` | 否   | 页码，从 1 起，缺省 1                                                |
| `size`    | 否   | 每页条数；缺省用后端默认上限（200），上限 1000                       |

响应：

| 字段               | 说明                                                                                      |
|--------------------|-------------------------------------------------------------------------------------------|
| `latest`           | 该次运行产物是否可用（false 时 `items` 为空）                                             |
| `items[]`          | 当前页内容项：`alignKey` / `seq` / `type` / `status` / `display` / `normalized` / `extra` |
| `total`            | 总条数（**按 `docPage` 过滤后为该页条数**，不受 `current`/`size` 影响）                   |
| `current` / `size` | 本次生效的页码与每页条数                                                                  |
| `truncated`        | 本次响应是否还有内容未返回                                                                |
| `docPage`          | 本次生效的文档页过滤（未过滤时为空）                                                      |

### `extra` 里的字段

`extra` 是环节专属字段的容器（`Map<String, Object>`），本环节用到的：

| 键                    | 类型                         | 来源     | 用途                                                                                                                                                                            |
|-----------------------|------------------------------|----------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `source` / `provider` | 字符串                       | 解析产物 | 元素列表上标注来源与解析器                                                                                                                                                      |
| `page`                | 数字                         | 解析产物 | 元素所属文档页（PDF 页码；Office 结构路径元素可能没有）                                                                                                                         |
| `rows` / `cols`       | 数字                         | 解析产物 | 表格行列数，列表上显示为 `行×列`                                                                                                                                                |
| `cells`               | 字符串（JSON 数组）          | 解析产物 | `TABLE` 的单元格明细（含文本与行列）；解析详情按行列渲染网格，**内容原样下发、不截断**                                                                                          |
| `bbox`                | 对象 `{x, y, width, height}` | 解析产物 | 原文高亮框；**单位点（pt）、左上角原点**，与 pdf.js `getViewport({ scale: 1 })` 同口径 —— **已含裁剪框基准与页旋转**（旋转 90/270 时框本身是转过的）。**Office 元素没有该字段** |
| `style`               | 字符串                       | 解析产物 | Word 段落样式名（`w:pStyle` 的值），Word 段落定位用                                                                                                                             |
| `sheetName`           | 字符串                       | 解析产物 | Excel 工作表名，Excel 定位与切表用                                                                                                                                              |
| `row` / `col`         | 数字                         | 解析产物 | Excel 单元格坐标，**0 基**（与表格区域高亮同一口径）                                                                                                                            |
| `rowSpan` / `colSpan` | 数字                         | 解析产物 | 合并单元格跨度，缺省视作 1                                                                                                                                                      |
| `isHeader`            | 布尔                         | 解析产物 | 是否表头单元格                                                                                                                                                                  |

字段按非空并入：元素没有坐标就没有 `bbox`，不是 null 值。

**`row` / `col` / `rowSpan` / `colSpan` / `isHeader` 当前取不到**：这五个字段只存在于 `TABLE_CELL` 元素上，而解析环节的条目只下发顶层元素（单元格内嵌在 `TABLE.cells` 里，不作为独立条目）。单元格内容改由 `cells` 下发并渲染成网格；要做单元格级定位（点某格高亮该格）时，需要先把单元格展开成条目。

**易踩的地方**：`row`/`col` 是 **0 基**；`bbox` 是**左上角原点、裁剪框基准、旋转已施加**（PDF 原生坐标系是左下原点且不含页旋转，换算已在解析侧做完，前端把它当 pdf.js 视口坐标直接用）；`page` 与 `row`/`col` 的类型都是数字，比较时注意后端 `docPage` 走的是大整数（见 `03-接口逻辑.md`）。

## `GET /files/{fileId}`

- **直出字节流**，没有 `R` 信封；下载失败时后端仍以 **HTTP 200 + JSON 错误信封**应答，前端按 `Content-Type` 含 `json` 识别并把 `code`/`msg` 展示到左栏；
- 该接口要 `Authorization` 头，**不能用普通链接打开**（JWT 过滤器只认请求头，不认查询参数），所以走统一 axios 实例取 blob，并带 `rawResponse` 标记**跳过统一响应体解包**（否则 Blob 上的 `code` 读成 `undefined`，每次下载都被判成失败）；
- 同一次请求也用于底部「下载原文件」按钮（取到 blob 后触发浏览器保存）。

## 本环节可能出现的失败

| code  | 触发场景                                         |
|-------|--------------------------------------------------|
| 40001 | 环节不在白名单；`taskId` 不属于该文件该环节      |
| 40101 | 未认证（令牌缺失或已失效）                       |
| 40401 | 越权访问别人的文件结果（与「不存在」响应一致）   |
| 40431 | 触发解析时该文件结果已有解析任务（任何状态都拒） |
| 40432 | 文件结果不存在                                   |
| 40453 | 链的源文件所在数据源与当前启用的数据源不一致     |
| 40500 | 系统异常兜底                                     |

## 与后端不一致 / 需注意的地方

- **关键字过滤只作用于当前页**：后端按页给内容，前端只过滤已取回的当页；需要跨页搜索要后端加 `keyword` 参数。
- **`docPage` 是文档页，`current` 是元素分页**：两者可同时传，语义分别是「哪一页文档」与「该页元素的第几批」。
- **`total` 的口径随 `docPage` 变**：传了 `docPage` 时 `total` 是该页条数，不是全文条数。
- **Word / Excel 的锚点依赖 `extra` 的新字段**（`style` / `sheetName` / `row` / `col`）：产物里本来就有这些事实，只是读取侧新透出；产物结构未变。
