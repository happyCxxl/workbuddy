# 接口逻辑

本文件写「后端拿到请求之后到底做了什么」：校验顺序、落库、副作用、边界条件，以及本页相关的异常出口与表结构。机制口径见 `../../README.md` 的「全局约定」章第六节「限流与登录防护」。

## `POST /auth/login`

`AuthController.login` → `AuthServiceImpl.login`：

1. 先取客户端 IP 并查是否已被锁定（失败计数达阈值）——命中直接抛 `40111`，**不查库、不跑 BCrypt**（BCrypt 为慢哈希）。
2. `UserDbService.findActiveByUsername(username)` —— 查 `kb_user` 的 `username = ? AND status = 1`，逻辑删除条件由 `@TableLogic` 自动补上。
3. `PasswordEncoder.matches(raw, hash)` 做 BCrypt 比对。**用户不存在、密码错、账号停用都返回同一个 40103**，不区分是哪一个——避免账号枚举；凭据不匹配时对「账号 + IP」与「IP」两个维度各记一次失败。
4. 登录成功清零账号维度的失败计数（IP 维度保留）。
5. `JwtUtil.sign(userId, username, role, tokenVersion, ttl)` 签发令牌（Hutool JWT），载荷 `sub` / `username` / `role` / `tv` / `exp`；`ttl` 由请求的 `remember` 选档。
6. 返回 `LoginVO`（9 个字段，见 `02-接口交互.md`），外层 `R.ok` 即 `code=0`、`msg="操作成功"`。

## `POST /auth/register`

`AuthController.register` → `AuthServiceImpl.register`：

1. 先按用户名查重（`existsByUsername`，**不按状态过滤**——与停用账号同名时唯一键同样会冲突），命中则抛 40102。
2. 组装 `User`：真实姓名、邮箱、手机号原样落库，密码 BCrypt 编码、`status` 取 `UserStatus.ENABLED`、`role` **固定为 USER**（管理员只能由既有管理员在用户管理中调整）。
3. `UserDbService.save(user)` 插入 `kb_user`；`id` 由雪花算法生成，`del_flag`（`DelFlag.NORMAL`，码值 `0`）/ `create_time` / `update_time` 由自动填充写入，此时无认证上下文，`create_by` 为 null。
4. 返回 `R.ok(null, "注册成功")`。

## 登录失败防护与接口限流

`/auth/login` 上有两道独立的防线，都落在 Redis 上：

1. **接口级限流**：`AuthController.login` 上标 `@RateLimit()`（走注解默认值，按 IP 每分钟 20 次），超限在进入 Controller 前就被切面拦下并返回 `40201`。注解是契约（`../../../workbuddy-common/annotation`），切面与令牌桶实现在 `../../../workbuddy-infra/ratelimit`。
2. **登录失败防护**：`LoginAttemptGuard` 按两个维度计数——「账号 + IP」为主、「IP」为辅（跨账号，防喷洒撞库）。计数对不存在的用户名同样生效。

配置项（`config/workbuddy-auth.yml` 的 `knowledge.auth.guard`）：

| 键                  | 默认 | 含义                                             |
|---------------------|------|--------------------------------------------------|
| `enabled`           | true | 是否启用失败防护                                 |
| `fail-threshold`    | 5    | 「账号 + IP」维度的失败阈值                      |
| `ip-fail-threshold` | 20   | IP 维度的失败阈值（跨账号，防喷洒）              |
| `lock-minutes`      | 15   | 计数窗口与锁定时长（自首次失败起算，期间不续期） |

## 每个请求都过的 `JwtAuthFilter`

`Authorization` 头以 `Bearer ` 开头时：`JwtUtil.parse` 验签并查过期（失败即视为未认证）→ 用载荷里的用户 ID 查库比对令牌版本 → 库中查不到（用户已删除）或版本不等（改密码 / 改角色 / 停用 / 删除时递增）就清空安全上下文 → 通过则把 `ROLE_<role>` 写入 Spring Security 上下文。

登录与注册是放行接口，通常不带令牌；这个过滤器对本页的两个请求实际是空转。

## 本页相关的异常出口

| 出口                           | 处理                                                                                     |
|--------------------------------|------------------------------------------------------------------------------------------|
| `GlobalExceptionHandler`       | 业务异常回它自己的 code 与 message；参数校验失败回 40001；未知异常回 40500，堆栈只进日志 |
| `RestAuthenticationEntryPoint` | 未登录访问受保护接口 → 40101 + HTTP 200                                                  |
| `RestAccessDeniedHandler`      | 已登录但角色不够 → 40104 + HTTP 200                                                      |

## 涉及的表

`kb_user`（建表与变更脚本：`src/main/resources/sql/init.sql`）：

| 字段                                                      | 说明                                                             |
|-----------------------------------------------------------|------------------------------------------------------------------|
| `id`                                                      | 主键，雪花，应用显式传入                                         |
| `username`                                                | 登录用户名，唯一键 `uk_username`                                 |
| `display_name`                                            | 真实姓名                                                         |
| `email`                                                   | 邮箱（**不唯一**）                                               |
| `phone`                                                   | 手机号（**不唯一**）                                             |
| `password`                                                | BCrypt 哈希                                                      |
| `status`                                                  | 1 启用 / 0 停用                                                  |
| `role`                                                    | `ADMIN` / `USER`                                                 |
| `token_version`                                           | 令牌版本，递增即让该账号已签发令牌失效                           |
| `del_flag`                                                | 逻辑删除标记，`DelFlag`：0 正常（`NORMAL`）/ 1 已删（`DELETED`） |
| `create_by` / `create_time` / `update_by` / `update_time` | 留痕字段，自动填充                                               |
