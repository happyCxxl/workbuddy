# 接口交互

三个接口都由请求层统一处理：业务失败也是 HTTP 200 + `R.code`，提示由拦截器弹出，页面代码只看成功分支。通用口径（响应体形状、错误码分段、401 处理）见 `../../README.md` 的「全局约定」章。

三个接口都**不加 `@AdminOnly`**——它们作用于本人，任何登录用户都能调用。

| 触发                   | 前端调用链                                                   | 接口                 | 请求体                        | 响应 `data`      |
|------------------------|--------------------------------------------------------------|----------------------|-------------------------------|------------------|
| 进入页面 / 保存资料后  | `ProfileView.loadProfile` → `api/user.getProfile`            | `GET /user/profile`  | —                             | `UserVO`（见下） |
| 点「保存」（基本信息） | `ProfileView.handleSaveInfo` → `api/user.updateProfile`      | `PUT /user/profile`  | `{displayName, email, phone}` | `null`           |
| 点「保存」（修改密码） | `ProfileView.handleSavePassword` → `api/user.updatePassword` | `PUT /user/password` | `{oldPassword, newPassword}`  | 新令牌（字符串） |

## `GET /user/profile` 的响应字段（`UserVO`）

| 字段                                                  | 说明                                            |
|-------------------------------------------------------|-------------------------------------------------|
| `id` / `username`                                     | 主键（按字符串下发）与登录名，只读展示          |
| `displayName` / `email` / `phone`                     | 真实姓名与联系方式，可空（库中为空时是 `null`） |
| `status` / `role`                                     | 状态码值 1/0 与角色码值 `ADMIN` / `USER`        |
| `createBy` / `createTime` / `updateBy` / `updateTime` | 留痕字段；页面只用后两个显示时间                |

**不含密码字段**。

## 请求侧的两个细节

- 基本信息三个字段**总是全量提交**（不是增量）：邮箱 / 手机号留空时传空串，后端把「只有空白」的输入按 `null` 存。
- 修改密码只提交当前密码与新密码两个字段；确认新密码**只在前端做一致性校验，不上送**。

## 头像：两个写接口，URL 直连对象存储

| 触发                   | 前端调用链                                                 | 接口                  | 请求                                 | 响应               |
|------------------------|------------------------------------------------------------|-----------------------|--------------------------------------|--------------------|
| 点「更换头像」并选文件 | `ProfileView.handleAvatarChange` → `api/user.updateAvatar` | `POST /user/avatar`   | `multipart/form-data`，字段名 `file` | 对象存储的公开 URL |
| 点「移除」             | `ProfileView.handleRemoveAvatar` → `api/user.deleteAvatar` | `DELETE /user/avatar` | —                                    | `null`             |

- 两个写接口**只改当前登录用户**（userId 取自安全上下文，**请求里不接受 userId**），且都要求登录；
- 头像 URL 随登录响应与用户资料下发，浏览器 `<img src>` **直连对象存储**；应用层没有头像读接口，也不代理图片字节；
- 公开读只放开对象存储的 `avatar/*` 前缀，同桶的文件与产物对象保持私有；URL 每次上传都变，可长缓存；
- 本地磁盘后端没有公开读能力：上传会返回 `40001` 并提示切换对象存储，不会落一个不可渲染的地址；
- 失败：文件为空 / 超 2MB / 不是 PNG、JPG、WebP → `40001`（按**文件头魔数**判定，Content-Type 可以伪造）。

## 本页可能出现的失败

| code  | 触发场景                                                                                      |
|-------|-----------------------------------------------------------------------------------------------|
| 40105 | 本人账号在库里查不到（已被删除）                                                              |
| 40110 | 改密时当前密码不正确                                                                          |
| 40001 | 改密时新密码与当前密码相同，或长度不合规；保存资料时真实姓名为空 / 超长、邮箱或手机号格式不对 |
| 40101 | 未认证（令牌缺失或已失效）                                                                    |
| 40500 | 系统异常兜底                                                                                  |
