# 接口逻辑

切片是执行链的**第四个环节**：上游是预处理派生的清洗结果（`PreprocessView`），下游是向量化。它把进检索的文本切成检索命中的最小单元（`Chunk`），原文与清洗结果都不改动。执行器与读取侧分工：`ChunkTaskRunner` 管落库与产物（产物 JSON + `kb_chunk_set` / `kb_chunk`），`ChunkPipeline` 是纯算法（不碰 DB、不碰对象存储、确定性执行）。

## 一、控制面（触发）

`KnowledgeFileChunkController` 只有两个方法：触发与详情。归属校验与任务解析复用各环节共用的守卫：`FileResultAccessGuard` 在**服务层入口**按 `kb_file_result.knowledge_base_id` 反查知识库再走 `KnowledgeBaseRules.checkAccessible`，越权与不存在同样返回 `KB_NOT_FOUND`（40401），未登录 40101；`TaskDetailSupport` 统一解析"被查看的那次运行"。

### 触发顺序

1. **归属校验**（越权 / 不存在 → 40401）；
2. **解析策略版本**（两档：显式指定的 `strategyVersionId` → 知识库绑定的策略版本）：显式指定档校验存在 / 类型匹配 / 启用，任一不满足给 **40433**；两档都不命中（绑定开关关闭、未绑定、绑定行缺失或已停用）一律 **40438**，文案形如「切片未绑定策略，请显式选择策略后触发」或「切片绑定的策略已停用或不存在，请重新绑定或显式选择策略」。**不做兜底**：既没有「取库内启用中最新」，也没有代码内置的默认策略，策略一律来自 `kb_pipeline_strategy_version` 表（`init.sql` 里有 `chunk-hybrid` 等种子行）；
3. **上游校验**：`upstreamProductId` 必填，未给或传 0 → **40436**；按它取产物并校验存在、环节为 `PREPROCESS`、且属于该文件结果（任一不满足 → **40432**）；**下游门禁**：产物的产出任务须为 `SUCCESS` 或 `PARTIAL_SUCCESS`，否则 **40439**（挡孤儿产物，`PARTIAL_SUCCESS` 放行并 warn）；任务行缺该引用时执行期落 `FAILED`(`TASK_UPSTREAM_MISSING`)；上游产物读不到 / 反序列化失败 / 无元素都会在任务里落 `CHUNK_EMPTY`。**执行期不再"取该环节最新产物"**，兜底已删；
4. **执行键查重**（`TaskTriggerSupport.trigger` 的第一行是存储一致性校验，不一致 → **40453**；随后按「文件结果 + `CHUNK` + 上游产物 ID + 策略版本 ID」查任务）：**查到就抛 40431**（任何状态，含执行中；消息「切片任务已创建（taskId=…，状态 …），请勿重复触发」，**不返回既有结果**）；
5. **新建任务**：查不到才新建一条 `QUEUED` 任务，写入策略版本 ID、策略快照（capabilitySnapshot）与上游产物引用，入队；**入队写不进队列时**该任务立刻落 `FAILED`（`TASK_ENQUEUE_FAILED`，文案"任务入队失败，请重试"），异常继续抛出。

**失败即终局，不允许原地重跑**：想重来一次有两条路——**换上游产物**（从另一张预处理卡片发起）或**换策略版本**（下拉里选另一个版本）；执行键不同即新链路，旧任务与旧产物保留。**补投完全归 `TaskStartupCompensator`**：启动补偿一次 + 低频周期扫描（`knowledge.task.low-freq-sweep-enabled`，默认开启、间隔 1 分钟，多实例用 Redis 锁防重），触发入口不再承担唤醒。

**服务停机**：先停领批 → 给在跑任务最多 `knowledge.task.shutdown-wait`（默认 30s）完成 → 到点中断并把仍未结束的任务显式置 `FAILED(TASK_SHUTDOWN_INTERRUPTED)`（条件更新，runner 已写终态则不覆盖）；`kill -9`/断电等硬停不做任何收尾，仍由启动时的 RUNNING 孤儿恢复兜底。两个池是具名 `ThreadPoolTaskExecutor` bean（`taskWatchdogExecutor` / `taskRunnerExecutor`），上面那句"最多等 `knowledge.task.shutdown-wait`"就落在它们的 `awaitTerminationSeconds` 上；环节超时取值同样按归一化环节名查（`knowledge.task.timeout.*`）。Spring Boot 自动给这两个池打点 `executor.*` 指标；`/actuator/health` 与 `/actuator/metrics` 当前都免认证（本地排查用，对外暴露前请自行收紧），端点暴露范围由 `management.endpoints.web.exposure.include=health,metrics` 决定。

## 二、切片链路（逐步）

`ChunkPipeline` 先按策略解析结果建切片上下文（元素索引、标题栈、各算法参数），再按元素顺序走下面这条链路；**每个切片器外层 try/catch 隔离**，异常只影响该元素的产物并计入告警（任务落 `PARTIAL_SUCCESS`）。

| #  | 步骤（子步骤名） | 口径与默认值                                                                                                                                                                                                                                                                              |
|----|------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1  | 跳过不长片的元素 | 处置状态属于**不进切片**那批的视图元素直接跳过（剔除态与重复份，与预处理侧同一份名单）                                                                                                                                                                                                    |
| 2  | 标题只切章不成片 | `TITLE` 元素只维护标题栈与章节边界（`titlePath`，层级上限 `titlePathMaxLevel` 默认 3），自身不产出片                                                                                                                                                                                      |
| 3  | 内容路由         | `TABLE` → 表格路、`IMAGE` → 图片路、其余文本 → 正文路；兜底**不是路由目标**，是正文路超长元素的降级模式（`tableInBodyFlow=ON` 时表格改并入正文流）                                                                                                                                        |
| 4  | 正文聚合         | 段落聚合（`paragraph-aggregate`）：元素进缓冲，累计达到目标片长（`targetMaxLen` 默认 **800**）在元素边界结算；单元素超过软上限（`softMaxLen` 默认 **1000**）先结算缓冲再走兜底；空文本元素丢弃                                                                                            |
| 5  | 超长兜底         | 递归长度降级（`recursive-length`，`len` 默认 **500**、`overlap` 默认 **50**）：优先在句边界切，单句仍超长才按固定长度 + 重叠硬切；产出片标 `contentType=FALLBACK` 与 `fallbackReason`（取值：`超长段落递归降级` / `标题边界超长降级`，由正文各策略共用的降级入口写入）                    |
| 6  | 表格切片         | 行级切片（`row-slice`）：行字符数少于阈值（`groupThreshold` 默认 30）按每 `groupSize`（默认 3）行一组，长行单行成片；**表头随片**，内容为 Markdown 管道表                                                                                                                                 |
| 7  | 图片切片         | 图注占位（`caption-placeholder`）：图片按引用 + 图注成片                                                                                                                                                                                                                                  |
| 8  | 后置链（逐章）   | 固定顺序：① 结构重叠（`structureOverlap` 默认 **0 = 不处理**，>0 时把上一片末尾 N 字符前缀到本片）→ ② 碎片合并（`minMergeLen` 默认 **300**，正文片短于它并入紧邻的前一个正文片，跨表格 / 图片 / 章节不合并）→ ③ 标题入正文（`titleInContent` 默认 ON，非父片 content 首行拼 `titlePath`） |
| 9  | 父子片           | `parentChild` 默认 **ON**：每个标题切出的章生成一条 `contentType=SECTION` 的**父片**（= 该章全部子片 content 换行拼接，`sourceElementIds` / `pageRange` 取子片并集），随后把 `parentChunkId` 挂到该章的子片                                                                               |
| 10 | 编号与 token     | 集合内顺序号从 `chunk-0001` 起；**编号顺序是"父片全部在前、子片随后、孤儿片最后"，属归档序不是阅读序**；`tokenCount = ceil(字符数 ÷ 1.5)`（除数 `tokenDivisor`）                                                                                                                          |

无章节归属的片（标题栈为空时切出的片）成为**孤儿片**：没有 `parentChunkId`，也不计入子片数。

**对下游的影响**：`includeParent`（向量化侧策略，默认 **OFF**）决定父片是否也产向量——默认只向量化子片，于是**父片计入片数却不产向量**，片数看起来比检索条数多。切片片长超过向量化模型的窗口允许字符数时，向量化直接失败（`EMBED_MODEL_INCOMPATIBLE`）。

### 参数范围（保存校验口径）

范围与说明的**单一事实源**是 `../../../workbuddy-common/.../enums/chunk/ChunkParam`（按「算法 + 参数键」索引）；参数键的序列化常量在 `ChunkParamKeys`，默认值来源是 `ChunkProperties`（application.yml 同名 kebab-case 键）。

| 算法                              | 参数                                          | 范围                        |
|-----------------------------------|-----------------------------------------------|-----------------------------|
| 段落聚合 / 结构混合 / 句子聚合    | `targetMaxLen`                                | 100 ~ 5000                  |
| 同上                              | `softMaxLen`                                  | 100 ~ 8000                  |
| 标题边界                          | `maxLen`                                      | 100 ~ 20000                 |
| 正文固定窗口                      | `len` / `overlap`                             | 100 ~ 5000 / 0 ~ 1000       |
| 表格行级（`row-slice`）           | `groupThreshold` / `groupSize`                | 5 ~ 500 / 1 ~ 20            |
| 表格行组（`row-group`）           | `groupSize` / `maxLen`                        | 1 ~ 50 / 100 ~ 5000         |
| 整表一片（`whole-table`）         | `maxLen`                                      | 100 ~ 20000                 |
| 表 + 引导段落（`context-merged`） | `leadMaxLen` / `groupThreshold` / `groupSize` | 0 ~ 1000 / 5 ~ 500 / 1 ~ 20 |
| 兜底递归 / 兜底固定窗口           | `len` / `overlap`                             | 100 ~ 5000 / 0 ~ 1000       |

三条跨参数约束（保存校验一起做）：`softMaxLen ≥ targetMaxLen`（正文聚合三算法）、`overlap < len`（兜底路）、`tableInBodyFlow=ON` 与表格算法 `context-merged` 互斥。未知参数键按前向兼容透传，不报错也不生效。

### 口径补充（容易误读的六点）

1. **`tokenCount` 是字符估值**：`ceil(字符数 ÷ 1.5)`，不是模型 token；与嵌入模型的真实 token 不是一回事。开源做法（Docling）建议切片器与嵌入模型共用同一 tokenizer，我们当前用字符估值，接入真分词登记为待定。
2. **目标上限不是硬约束**：`targetMaxLen` 是"累计到它就结算"的结算点，单元素超过软上限走**兜底降级**（保内容不丢），于是可能出现长于目标上限的片——用统计里的 `overTargetMaxCount` / `overSoftMaxCount` 观察。
3. **结构重叠默认关**：`structureOverlap` 默认 0，要相邻片重叠得显式调大（开源多数默认开，我们取更保守的默认）。
4. **整表降级的分组不可调**：`whole-table` 超限降级为行级切片时固定用 30 字符短行阈值 + 3 行一组，不读 `row-slice` 的 `groupThreshold` / `groupSize`（该算法不暴露这两个参数）。
5. **编号是归档序不是阅读序**：片序为"父片全部在前 → 子片 → 孤儿片"；阅读序（父片与子片成组）由左栏按 `parentChunkId` 重组，对齐键是片 ID。
6. **欠长片是正常产物**：碎片合并只做一次、且不跨表格 / 图片 / 章节，合并后仍可能有短片（多为合并尾巴）；统计里的 `underMinMergeCount` 与 `minMergeLen` 就是用来观察它的。开源同样承认这一现象（Docling 明说合并后可能有欠长尾巴片）。

## 三、片的状态与失败

产物落库时机与状态判定：

| 时机                  | 落什么                                                                                                                  |
|-----------------------|-------------------------------------------------------------------------------------------------------------------------|
| 执行成功 / 部分成功   | 切片集合产物（`ChunkSet` JSON，`artifactId` = 内容 sha256）+ `kb_chunk_set` 一行 + `kb_chunk` 每片一行 + 六条子步骤记录 |
| 上游视图为空 / 不可读 | **不落产物**，任务落 `CHUNK_EMPTY` 与失败说明                                                                           |
| 无可切内容            | 同上（元素都被剔除或全无文本）                                                                                          |
| 执行异常              | 任务落 `CHUNK_FAILED`（兜底码），错误摘要截断后落到任务与步骤上                                                         |
| 某个切片器异常        | 产物照常落，任务落 `PARTIAL_SUCCESS`，异常进对应步骤的告警                                                              |

涉及的表：`kb_pipeline_task`（任务与策略快照；唯一键 `uk_exec` = 文件结果 + 环节 + 上游产物 + 策略版本，0 表示"没有上游"与"该环节无策略"两档）、`kb_pipeline_product`（产物引用与内容指纹）、`kb_pipeline_step_log`（六步子步骤）、`kb_chunk_set`（集合：片数 / 总字符 / 产物引用）、`kb_chunk`（每片：片 ID / 父片 ID / 内容 / 类型 / 标题路径 / 页码范围 / 表格引用 / 顺序号 / 字符数 / token / 策略版本）、`kb_pipeline_strategy_version`（策略版本）。切片不写 `kb_file_result`，也不改上游清洗结果产物。

## 四、读取侧：统计、对齐键与标题路径

- **统计在读取侧现算、不落产物**：`ChunkStatsSupport` 读切片产物（+ 上游预处理视图 + 策略快照）算出统计与结论，执行树卡片与详情共用同一份口径；
- **节点侧并入落位**：执行树节点先落通用统计（其中 `chunkCount` 由 `kb_chunk_set` 聚合而来），随后把切片统计**并入**（`putAll`）——顺序反过来或整份替换会把 `chunkCount` 覆盖掉；
- **对齐键是片 ID**：`stage-content` 的 `alignKey` 与详情的 `chunkId` 同值（都是 `chunk-0001` 这种）；`seq` / `orderNo` 只作展示。左栏是阅读序（父片与子片成组、孤儿片在末尾），换页定位按片自己的 `orderNo` 算；
- **详情侧的片列表来自 `kb_chunk`**，来源元素个数与兜底原因由切片产物补齐（`kb_chunk` 无这两列）；`stage-content` 的过滤（类型 / 兜底 / 父子）与分页都下推 DB，`total` 与 `truncated` 按过滤后的口径给；
- **标题路径**在切片时写入每片（`titlePath`，` > ` 连接，层级上限由策略控制），列表与左栏的说明列直接取它，不额外拼装。

## 五、上游与边界

- 上游 `PreprocessView` 的**剥离状态**决定谁进切片：`EXCLUDED_*` / `BACKUP_SKIPPED` / `REPEATED` 不进（同一份名单在预处理侧叫"不进切片"），`MARKED_*` 与 `NOISE` 仍进——它们只是被标注；
- 片内容取 `normalizedText` 口径（检索用文本）：剔除态元素为 null，它们即便被路由也切不出片；
- 切片**不修改**上游产物，也不回写预处理任务；一次运行的片只属于该次运行的集合（多套策略 = 多个集合并存，平行候选）；
- 读取侧按 `taskId` 精确取"被查看的那次运行"的集合：`taskId` 缺省取该环节最新任务，传了但不属于该文件该环节给 40001；文件结果不存在或没有该环节任务时，产物内容返回 `latest=false` 与空列表。
