# 接口交互

两个接口都是 `GET`、都只读、都不需要额外的角色（登录即可）。业务失败也是 HTTP 200 + `R.code`，提示由拦截器统一弹出，页面代码只看成功分支 —— 通用口径见 `../../README.md` 的「全局约定」章。

## 调用时机

| 触发            | 前端调用链                                               | 接口                       | 请求参数          | 响应 `data`                 |
|-----------------|----------------------------------------------------------|----------------------------|-------------------|-----------------------------|
| 进入页面        | `HomeView.loadSummary` → `api/home.getHomeSummary`       | `GET /home/summary`        | —                 | `HomeSummaryVO`（见下）     |
| 进入页面 / 翻页 | `HomeView.loadSubmits` → `api/home.getHomeRecentSubmits` | `GET /home/recent-submits` | `current`、`size` | `IPage<HomeRecentSubmitVO>` |

- 两个请求在挂载时各自发出，互不依赖；
- 翻页只重拉提交记录，资产速览不动；每页固定 10 条（`HomeView.PAGE_SIZE`）；
- **窗口尺寸变化不触发任何请求**（页长是常量，容器高度由布局决定）。

## 可见范围（重要）

`GET /home/recent-submits` **只返回当前登录用户的记录**：

- 请求里**没有**"提交人"参数 —— 提交人由后端从安全上下文取（过滤 `wb_submit_log.user_id`）；
- **前端无法通过传参看到别人的提交**，隔离在服务端做；
- 安全上下文缺失时返回 `40101`（正常路径到不了：该接口本身要求认证）。

## `GET /home/summary` 的响应字段（`HomeSummaryVO`）

八个计数字段，**全是数字**（不是字符串）：后端按「超过 JS 安全整数才字符串化」的全局口径处理，计数永远在小数值区间。

| 字段                        | 说明                                                                    |
|-----------------------------|-------------------------------------------------------------------------|
| `knowledgeBaseCount`        | 知识库总数（含已停用；**只数当前用户可见的**，见下）                    |
| `enabledKnowledgeBaseCount` | 启用中的知识库数（同一可见范围）                                        |
| `strategyVersionCount`      | **可用**策略版本数（四类合计，只含 `ACTIVE`；与知识库无关，是全平台的） |
| `preprocessVersionCount`    | 预处理策略版本数（只含 `ACTIVE`）                                       |
| `chunkVersionCount`         | 切片策略版本数（只含 `ACTIVE`）                                         |
| `embedVersionCount`         | 向量化策略版本数（只含 `ACTIVE`）                                       |
| `retrievalVersionCount`     | 检索策略版本数（只含 `ACTIVE`）                                         |
| `documentCount`             | 已建档文档数（可见库下的 `wb_file_result` 行数，不含校验失败）          |

**知识库与文档两类计数按可见范围过滤**：普通用户只统计自己创建的知识库（及其下文档），管理员统计全部。口径与[知识库列表](../知识库列表/README.md)页**完全一致**（同一个 `KnowledgeBaseRules.visibleOwnerId`）。策略版本数不按知识库归属过滤 —— 策略是平台级资产，人人都能选。

索引版本的两个计数**不在响应里**：界面不展示，后端也不做这两次 count 查询。

## `GET /home/recent-submits` 的响应字段（`HomeRecentSubmitVO`）

| 字段                | 说明                                                                                                    |
|---------------------|---------------------------------------------------------------------------------------------------------|
| `id`                | 提交日志主键（雪花 ID，按字符串下发）                                                                   |
| `fileName`          | 文件名；取不到时是**空串**（列 NOT NULL），前端显示占位文案                                             |
| `fileType`          | 文件类型（`FileFormat` 枚举名：PDF / DOCX / XLSX …）；**校验失败的行取不到，下发 `null`**，界面显示 `—` |
| `knowledgeBaseId`   | 所属知识库 ID（字符串）                                                                                 |
| `knowledgeBaseName` | 后端反查的库名；库已删除时回落成 `知识库 {ID}`                                                          |
| `status`            | 提交校验结果：`PASS` / `FAIL`                                                                           |
| `failReason`        | 失败原因码值（PASS 时为 `null`）                                                                        |
| `failReasonLabel`   | 失败原因中文（后端下发，PASS 时为 `null`）                                                              |
| `createTime`        | 提交时间（界面显示到分钟，带年份）                                                                      |

**不下发 `operator`**：表格只展示本人记录，没有「提交人」列。

## 请求侧的细节

- 分页参数由前端固定传 `size = 10`，与后端 DTO 的默认页长一致；
- 没有筛选参数：需要筛选时再加，避免留下"传了也没人用"的死参数。

## 本页可能出现的失败

| code  | 触发场景                                                                               |
|-------|----------------------------------------------------------------------------------------|
| 40101 | 未认证（令牌缺失或已失效）→ 拦截器清令牌并回登录页；安全上下文缺失时提交列表也回这个码 |
| 40500 | 系统异常兜底                                                                           |

两个接口都是只读查询，没有 4xx 业务错误码。
