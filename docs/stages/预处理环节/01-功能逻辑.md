# 预处理环节 · 功能逻辑

本文记环节内部口径：九步管线、三层文本、处置状态、剔除与统计口径、策略模型、判定边界、失败语义、阈值清单与产物契约。页面与接口在 `../../pages/预处理环节/`。

## 一、九步管线（顺序固定，只可开关与调参）

`PreprocessPipeline` 先把文档级信息预计算一次，再逐元素建派生副本，按 `order` 依次执行启用的规则，最后组装视图。

| # | 步骤（`stepName`） | 规则名（轨迹里的 `rule`）                                                                                                                         | 动作要点                                                                                                                                          |
|---|--------------------|---------------------------------------------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------|
| 1 | 编码规范化         | `encoding-clean-v1`                                                                                                                               | 字符级整理（空白 / 换行 / 乱码）产出 `displayText`，并给出 `normalizedText` 基座（+ Unicode NFKC 全角转半角）；表格单元格同样处理；`rawText` 不动 |
| 2 | 段落/表格文本整理  | `text-tidy-v1`                                                                                                                                    | 六项子规则：空白与首尾、**折行段落合并**（同段内硬折行合成一行，段间与列表项不动）、标点与引号、软连字符、项目符号、链接与邮箱；只动文本不动结构  |
| 3 | 页眉页脚           | `HeaderFooterRule`                                                                                                                                | 解析识别出的 `HEADER` / `FOOTER` 元素按档处置；页码文本随页眉页脚一起走（**没有独立的页码规则**）                                                 |
| 4 | 目录               | `TocRule`                                                                                                                                         | 组装标记的目录行先按阈值判定（PDF 用页内行数，Word 无页概念用连续窗口），命中后按档处置；**阈值对三种处置都生效**                                 |
| 5 | 重复               | `RepeatRule`                                                                                                                                      | 组装标记的重复页与重复段（除首份外）按档处置                                                                                                      |
| 6 | 字段规范化         | `field-normalize-v1`（轨迹里是 `amount-cn-v1` / `thousand-sep-v1` / `chinese-date-v1` / `date-sep-v1` / `unit-normalize-v1` / `cert-extract-v1`） | 金额 / 日期 / 面积 / 证号四类子开关，产出 `normalizedFields` 并改写检索文本                                                                       |
| 7 | 噪声               | `NoiseRule`                                                                                                                                       | 组装标记的噪声页上的元素按档处置；噪声页计数来自组装环节，与本档位无关                                                                            |
| 8 | 自定义规则         | `custom-clean-v1`                                                                                                                                 | 链尾：按策略里的正则列表顺序施加（移除 / 替换 / 提取），正则由管线预编译一次                                                                      |
| 9 | 视图组装           | —                                                                                                                                                 | 组装 `PreprocessView`：视图元信息（含策略版本与扁平化 `options`）+ 元素 + 每步步骤日志（8 条规则 + 视图组装）                                     |

**预计算一次的内容**（避免逐元素重复算）：

- 重复页 / 噪声页集合：读 `pages[].marks` 里的 `REPEATED_PAGE` / `NOISE_PAGE`；
- 目录计数与窗口：有页概念的元素按页累计 `TOC_LINE` 行数；无页概念（Word）维护连续 `TOC_LINE` 窗口，窗口长度达 `runMinLength` 才收进候选集合；
- 自定义规则正则：逐条 `Pattern.compile`，编译失败只告警并跳过（保存校验已拦截非法正则，这里是防御）。

**逐元素的两条短路**（在规则之前）：组装判为冲突被裁决方（`conflictStatus = BACKUP`）的元素直接置 `BACKUP_SKIPPED`、清检索文本与单元格检索文本、写一条剔除轨迹；图片元素置 `IMAGE_REF_ONLY`（OCR 预留，预处理不改动）。

**逐元素 try/catch 隔离**：某条规则对某个元素抛异常时只影响该规则的产出，异常计入该步骤的告警与错误摘要，任务落 `PARTIAL_SUCCESS`（部分成功，不是失败）。

## 二、三层文本与派生视图契约

| 层         | 字段                                      | 是否可变 | 用途                                                  |
|------------|-------------------------------------------|----------|-------------------------------------------------------|
| 原文层     | `rawText`                                 | 从不修改 | 回溯原文、展示"改写前"                                |
| 展示层     | `displayText`                             | 可整理   | 阅读口径：空白 / 换行 / 明显乱码整理 + 全角转半角     |
| 检索层     | `normalizedText`                          | 可改写   | 检索口径：字段标准化后的文本；**剔除态为 `null`**     |
| 表格单元格 | `cells[].text` / `cells[].normalizedText` | 同上     | 单元格展示文本永在；剔除时单元格检索文本一并置 `null` |

元素还带 `normalizedFields`（`field` / `value` / `unit` / `rule`）与 `preprocessTrace`（`rule` / `field` / `action` / `before` / `after` / `evidence`）。轨迹动作取值：`MARK` / `REPLACE` / `EXCLUDE` / `KEEP` / `EXTRACT` / `MANUAL_REVIEW`；读取侧只下发非 `KEEP` 条目。

## 三、处置状态与两套剔除口径

处置状态（`ViewElementStatus`，落库与落产物都用 `name()`）：

- 正常：`NORMAL`；
- 仅标记（仍进检索内容流）：`MARKED_HEADER` / `MARKED_FOOTER` / `MARKED_TOC` / `NOISE` / `MARKED_REPEAT`；
- 剔除（不进检索内容流、不进切片）：`EXCLUDED_HEADER` / `EXCLUDED_FOOTER` / `EXCLUDED_TOC` / `EXCLUDED_NOISE`；
- 重复份的剔除档：`REPEATED`；
- 其他：`IMAGE_REF_ONLY`（图片仅保留引用）、`BACKUP_SKIPPED`（组装冲突被裁决方）。

| 口径                                      | 包含                                 | 谁在用                                                                                  |
|-------------------------------------------|--------------------------------------|-----------------------------------------------------------------------------------------|
| `PreprocessViewRules.EXCLUDED_STATUSES`   | 四个 `EXCLUDED_*` + `BACKUP_SKIPPED` | `summary.excludedCount`、统计条「剔除」格                                               |
| `PreprocessViewRules.CHUNK_SKIP_STATUSES` | 上面这些 + `REPEATED`                | 切片决定哪些元素不进内容流；`chunkSkippedCount`、卡片「剔除元素」、详情「剔除内容」页签 |

两者差一个 `REPEATED`：**重复档选「标记」或「保留」时，重复份不在 `REPEATED` 里**，照常进切片。三态规则的三档统一由 `MarkDisposeSupport` 实现：剔除档置剔除态 + `normalizedText = null` + 清单元格检索文本；保留档状态回落 `NORMAL`（只统计）；其余（含未配置）置标记态。

## 四、策略模型

策略快照（`PreprocessStrategy`）= 类型 / 名称 / 版本 + `rules`（七条固定规则）+ `custom`（自定义规则组）。快照在**触发时**固定进任务，执行只读快照。

| 规则键         | 语义         | 取值形态                        | 未配置时的生效默认 |
|----------------|--------------|---------------------------------|--------------------|
| `headerFooter` | 页眉页脚处置 | 三态                            | 标记               |
| `toc`          | 目录处置     | 三态 + 两个阈值参数             | 标记（阈值 3 / 3） |
| `noise`        | 噪声处置     | 三态                            | 标记               |
| `repeat`       | 重复处置     | 三态（**兼容旧开关**）          | 剔除               |
| `field`        | 字段规范化   | 开关 + 四类字段子开关           | 开（四类全开）     |
| `tidy`         | 文本级整理   | 开关 + 六项子规则               | 开（六项全开）     |
| `encoding`     | 编码清理     | 开关                            | 开                 |
| `custom`       | 自定义规则组 | 总开关 + 有序规则列表（≤20 条） | 开（列表为空）     |

参数目录（`PreprocessParam`）是**单一事实源**：键、归属规则、数值范围（`toc.minLinesPerPage` 与 `toc.runMinLength` 取 1~50，支持小数）、默认值、说明；保存校验与前端表单范围都以它为准。

**归一化与校验**（`PreprocessAlgorithmSpec`）：`normalize` 补全缺失规则、缺失动作 / 开关与缺失参数（参数默认值取自 `PreprocessProperties`）；`validate` 校验处置取值、开关取值、参数范围、自定义规则的条数上限（20）、正则长度（≤200 字符）与可编译性、动作与替换文本约束。

**旧开关格式兼容**：`repeat` 历史上只有 `enabled` 开关。只给 `enabled` 的旧快照按 **ON = 剔除 / OFF = 保留** 换算（解析与执行两条路径同口径，`PreprocessRule.legacyToggle()` 标记这条规则）；同时给 `action` 与 `enabled` 的配置在保存时报错，新配置只写 `action`。

**生效时点**：改完策略要按**新的执行键**触发预处理才生效（换策略版本即换执行键）；同一张上游产物 + 同一个策略版本已有任务时触发一律 40431，旧任务与旧产物保留。

## 五、判定与处置的边界

| 判定（谁算）       | 在哪里判                                                                   | 本环节怎么用                      |
|--------------------|----------------------------------------------------------------------------|-----------------------------------|
| 页眉页脚（含页码） | 解析环节：PDF 取页顶 / 页底带内跨页重复文本与页码模式；DOCX 取页眉页脚部件 | 只看元素类型 `HEADER` / `FOOTER`  |
| 目录行             | 组装环节标记 `TOC_LINE`                                                    | 按阈值复核整页 / 连续窗口后再处置 |
| 重复页 / 重复段    | 组装环节标记 `REPEATED_PAGE` / `REPEATED_SEGMENT`                          | 除首份外按档处置                  |
| 噪声页             | 组装环节：无元素页 / 仅图片页 / 页文本乱码率超阈值，标记 `NOISE_PAGE`      | 按页集合处置元素                  |
| 冲突被裁决方       | 组装环节 `conflictStatus = BACKUP`                                         | 直接不进内容流                    |

上游阈值（`knowledge.parse.*`、`knowledge.structure.*` 与两处代码常量）**不在预处理策略里**：策略页与本节都不提供"识别阈值"入口，要改判定得改上游环节。

## 六、规则逐条口径

**① 编码规范化**：字符级整理（空白 / 换行 / 乱码）落在 `displayText`；`normalizedText` 基座额外做 Unicode NFKC（全角转半角）。原文不改；表格单元格同口径。实现细节在 `preprocessing/impl/TextBase`。

**② 文本级整理**：六项独立开关，全部只改文本不改结构。折行段落合并按"同段内硬折行"处理：以空行分段，段内多行合成一行；两侧都不是中日韩字符时补一个空格，行首是项目符号或编号的行不参与合并。

**③ 页眉页脚**：三档。剔除档清检索文本（含单元格检索文本），展示文本保留。

**④ 目录**：先判定再处置。PDF 按"该页 `TOC_LINE` 行数 ≥ `minLinesPerPage`"，Word 按预计算的连续窗口；命中后按档处置。阈值对三档都生效，非目录页上的特征行不受影响。轨迹里写清判定依据（行数 + 阈值）。

**⑤ 重复**：三档，默认剔除。剔除档只保留首份（重复份不进切片）；标记档重复份留在内容流里并加状态；保留档只统计。重复份计数来自组装标记，与本档位无关。

**⑥ 字段规范化**：执行顺序 = 优先级（金额 > 日期 > 单位 > 证书号），规则幂等（已规范化的文本重复执行无副作用）。中文大写金额**只提字段不改写**（大写是合规原文）；千分位去逗号、中文日期与分隔符日期转 ISO、`㎡` 族统一"平方米"会改写检索文本；证书号只提取。拿不准时不改写并记 `MANUAL_REVIEW`（计入该步告警），覆盖：复杂财务表达（多个"亿"或两个以上"万"）、干支纪年、中文日期解析失败、**日期越界或日期不存在**（如 2 月 30 日，日历合法性交 `LocalDate` 判定，不会写出假日期）。

**⑦ 噪声**：三档。保留档只统计不处置；标记档加状态仍进内容流；剔除档不进检索内容流与切片。空白页没有元素可处置，只在任务告警里计一笔。

**⑧ 自定义规则**：链尾按列表顺序执行。三种动作：`REMOVE` 命中内容整体移除；`REPLACE` 按替换文本改写（支持 `$1` 组引用，替换文本必填）；`EXTRACT` 只保留命中（多个命中以空格连接，无命中保持原文）。作用于元素展示文本与单元格检索文本，改过展示文本的元素会重算检索文本基座。

## 七、统计与结论（读取侧现算）

`PreprocessStatsSupport` 读产物现算，不落库；执行树的预处理节点与详情共用同一份口径。

| 键                                   | 口径                                                            |
|--------------------------------------|-----------------------------------------------------------------|
| `elementCount`                       | 视图元素总数                                                    |
| `retainedCount` / `retentionPercent` | 保留数 = 总数 − 不进切片数；占比四舍五入取整（无元素记 0）      |
| `excludedCount`                      | 剔除态元素数（`EXCLUDED_*` + `BACKUP_SKIPPED`，**不含重复份**） |
| `repeatedCount`                      | 重复份的剔除档数量（`REPEATED`；标记档的重复份计入仅标记）      |
| `chunkSkippedCount`                  | 不进切片总数 = `excludedCount` + `repeatedCount`                |
| `markedCount`                        | 仅标记元素数（页眉 / 页脚 / 目录 / 噪声 / 重复份）              |
| `fieldCount` / `fieldTypeCounts`     | 标准化字段总数与按类型分布                                      |
| `changedCount`                       | 检索文本非空且与展示文本不同的元素数                            |
| `encodingCount` / `tidyCount`        | 轨迹里命中对应规则名前缀的元素数（一个元素命中多档只计一次）    |
| `statusCounts`                       | 状态名 → 元素数（缺失状态归 `UNKNOWN`）                         |
| `pageFrom` / `pageTo`                | 被处置或有改写 / 提字段的元素所在页的始末页（取不到时不下发）   |
| `durationMs`                         | 运行起止时间差                                                  |

结论文案：按统计陈述异常项（`N 项仅标记、仍在检索内容流；M 项已剔除出检索内容流；重复份 K 已剔除`）；空视图给"无任何可处理的元素（空视图）"；没有任何异常项时给"未剔除内容，全部进入切片"；产物不可读时不陈述结论。

## 八、失败语义与告警

| 情形                                   | 结果                                                                              |
|----------------------------------------|-----------------------------------------------------------------------------------|
| 上游产物缺失或为空                     | 任务落 `PREPROCESS_EMPTY`（失败），给对应建议                                     |
| 某条规则对某元素抛异常                 | 该元素该步记错，`warnings` 累加，任务落 `PARTIAL_SUCCESS`，其余元素与其他规则照常 |
| 自定义正则编译失败                     | 只告警并跳过该条（保存校验本应拦下）                                              |
| 拿不准的字段（含日期不存在）           | 不改写 + 写 `MANUAL_REVIEW` 轨迹，计入该步告警数                                  |
| 有元素处于非 `NORMAL` 状态或文本被改写 | 视图照常产出，统计与结论体现差异                                                  |

## 九、阈值与默认值清单

| 位置                                             | 键                            | 默认             | 作用                                                   |
|--------------------------------------------------|-------------------------------|------------------|--------------------------------------------------------|
| `PreprocessProperties`（`knowledge.preprocess`） | `tocMinLinesPerPage`          | 3                | 目录页判定：该页 `TOC_LINE` 行数下限（策略参数可覆盖） |
| `PreprocessProperties`                           | `tocRunMinLength`             | 3                | Word 无页概念时连续目录行数下限（策略参数可覆盖）      |
| `PreprocessAlgorithmSpec`                        | 自定义规则上限 / 单条正则长度 | 20 条 / 200 字符 | 保存校验强制                                           |
| `PreprocessAlgorithmSpec`                        | 各规则默认档与默认开关        | 见第四节表       | 归一化时补全                                           |

上游相关阈值（不在本环节）：解析 `headerAreaRatio` / `footerAreaRatio` / `runningTextMinPages` 与两个页码判定常量（`HeaderFooterDetector`）；组装 `noiseGarbledRatio`（默认 0.4）、`repeatPageJaccard`、`repeatSegmentSimilarity`、`repeatSegmentMinLen`。

## 十、调用链

1. 控制面：策略版本（`wb_knowledge_pipeline_strategy_version`）保存时 `validate` 校验；绑定与生效版本解析在 biz 侧。
2. 触发：`KnowledgeFilePreprocessController` → 解析生效策略版本 → `PreprocessStrategyParser.parse` 归一化 → 快照进任务（`capabilitySnapshot`）→ 入队。
3. 执行：`PreprocessTaskRunner` 领任务 → 读组装产物 → 构造 `PreprocessContext` → `PreprocessPipeline.preprocess` → 写产物行与九条子步骤记录 → 回写终态与结论文案。
4. 读取：`PreprocessControlServiceImpl` 与控制面详情接口读产物（归一化后的策略对象下发）；页面统计按产物现算。
