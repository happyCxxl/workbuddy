# 切片环节 · 功能逻辑

本文记环节内部口径：四路由与算法目录、切片链路、正文聚合与降级、表格与图片、后置链、父子与编号、统计、参数目录、失败语义、默认值清单与调用链。页面与接口在 `../../pages/切片环节/`；市面做法对照见 `../../research/切片环节-开源方案调研.md`。

## 一、四个路由与算法目录

`ChunkAlgorithm` 是算法目录（单一事实源）：每个 `(route, key)` 一个常量，携带序列化键、支持状态与"正文聚合是否在表格/图片边界结算"（flush）语义。当前 19 项 = **13 项上线 + 6 项预留**（预留项前端置灰并写明原因）。

| 路由 | 上线算法                                                                                                           | 预留算法                                      |
|------|--------------------------------------------------------------------------------------------------------------------|-----------------------------------------------|
| 正文 | 段落聚合（默认，flush 开）／标题边界（flush 关）／结构混合（flush 关）／句子聚合（flush 开）／固定窗口（flush 开） | 语义切片（依赖嵌入能力）                      |
| 表格 | 行级切片（默认）／行组切片／整表一片／表 + 引导段落                                                                | —                                             |
| 图片 | 图注占位（默认）                                                                                                   | 图注 + 上下文／OCR 文字／视觉摘要／多模态向量 |
| 兜底 | 递归降级（默认）／固定窗口硬切／不兜底                                                                             | 语义断点（依赖嵌入能力）                      |

**兜底不是路由目标**：元素类型（`TABLE` / `IMAGE` / 其余文本）决定走哪条路由；兜底是正文路超长元素的**降级切片模式**，由所选兜底算法执行。上线新算法的口径是三步：① 新增常量（`supported=false`）② 实现切片器并声明该常量 ③ 改 `supported=true`（前端随之解除置灰）。

## 二、切片链路（逐元素，异常按元素隔离）

| #  | 步骤             | 口径                                                                                                                                                                                            |
|----|------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1  | 跳过不长片的元素 | 状态属于 `PreprocessViewRules.CHUNK_SKIP_STATUSES`（剔除态 + 重复份，与预处理同一份名单）直接跳过                                                                                               |
| 2  | 标题只切章不成片 | `TITLE` 元素只维护标题栈与章节边界（`titlePath`，层级上限 `titlePathMaxLevel` 默认 3），自身不产片                                                                                              |
| 3  | 路由分派         | `TABLE` → 表格路、`IMAGE` → 图片路、其余文本 → 正文路；`tableInBodyFlow=ON` 时表格先按表格算法 Markdown 化，再逐片作为内联单元交给正文算法（并入正文流，不再独立路由）                          |
| 4  | 正文聚合         | 见第三节；正文算法 `flushOnContentBoundary=true` 时，遇到表格/图片先把缓冲结算，避免正文跨表格合并                                                                                              |
| 5  | 超长兜底         | 见第三节；降级片标 `contentType=FALLBACK` 与 `fallbackReason`                                                                                                                                   |
| 6  | 表格切片         | 见第四节                                                                                                                                                                                        |
| 7  | 图片切片         | 见第五节                                                                                                                                                                                        |
| 8  | 后置链（逐章）   | 见第六节                                                                                                                                                                                        |
| 9  | 父子片           | `parentChild` 默认 ON：每个标题切出的章生成一条 `contentType=SECTION` 父片（= 该章全部子片 content 换行拼接，`sourceElementIds` / `pageRange` 取子片并集），随后把 `parentChunkId` 挂到该章子片 |
| 10 | 编号与 token     | 集合内顺序号从 `chunk-0001` 起；**编号顺序是"父片全部在前 → 子片 → 孤儿片"，属归档序不是阅读序**；`tokenCount = ceil(字符数 ÷ tokenDivisor)`（默认 1.5，字符估值）                              |

无章节归属的片（标题栈为空时切出的片）成为**孤儿片**：没有 `parentChunkId`，也不计入父片数。

## 三、正文聚合与超长降级

四种聚合算法共用 `AbstractBodySliceStrategy` 骨架：以 `SliceContext.bodyBuffer` 做跨元素缓冲，空文本元素丢弃，累计到上限结算，单元素超限走兜底。

| 算法             | 结算口径                                                     | 超长处理                                                                                |
|------------------|--------------------------------------------------------------|-----------------------------------------------------------------------------------------|
| 段落聚合（默认） | 累计达到 `targetMaxLen`（默认 800）在元素边界结算            | 单元素超过 `softMaxLen`（默认 1000）先结算缓冲，再走兜底降级（原因 `超长段落递归降级`） |
| 结构混合         | 标题边界 + 段落聚合混合，累计达到目标片长结算                | 同段落聚合                                                                              |
| 句子聚合         | 跨元素按句聚合，累计达到目标片长结算                         | 超长句走兜底降级                                                                        |
| 标题边界         | 只在 TITLE 边界与文档末尾结算，一节一片                      | 一节文本超过 `maxLen`（默认 3000）整节走兜底降级（原因 `标题边界超长降级`）             |
| 固定窗口         | 缓冲到边界后按 `len`（默认 500）+ `overlap`（默认 50）窗口切 | 不标兜底降级（本身就是窗口切）                                                          |

**降级唯一入口**：`BodyChunkSupport.fallbackChunks(text, sourceIds, pages, context, reason)` —— 按所选兜底算法切片、逐片标 `FALLBACK` 与原因；两处调用（聚合骨架与标题边界）共用它，原因常量为 `REASON_PARAGRAPH_TOO_LONG` / `REASON_TITLE_BOUNDARY_TOO_LONG`。

**兜底三算法**：递归降级（默认，先按 `[。！？；换行]` 句边界切，超长句再按 `len` + `overlap` 硬切）／固定窗口硬切（不看句边界）／不兜底（超长原样单片）。

## 四、表格切片

表格按 Markdown 管道表序列化（`TableMarkdownSupport`），**表头随片**（每片带表头行与分隔行）。

| 算法             | 口径                                                                                                                                                           |
|------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 行级切片（默认） | 行文本短于 `groupThreshold`（默认 30）按每 `groupSize`（默认 3）行一组；长行单行成片                                                                           |
| 行组切片         | 数据行依次入组，行数 ≥ `groupSize`（默认 5）**或**组内字符累计 ≥ `maxLen`（默认 600）即结算                                                                    |
| 整表一片         | 整表一片；总长 > `maxLen`（默认 2000）时**降级为行级切片**（固定用 30/3 回退口径，不读行级参数）                                                               |
| 表 + 引导段落    | 行级切片基础上，每片 content 首行前缀"该表前最近一个非空正文段"（截断到 `leadMaxLen` 默认 200，超长加省略号）；与流程开关 `tableInBodyFlow` 互斥（保存校验拦） |

跨页续表在组装环节已接续成单表，切片侧按整表处理。

## 五、图片切片

图注占位（唯一上线算法）：片内容 = 图注占位说明（有图注时拼接 `｜图注：…`），来源元素含图片元素，图片与图注保持关联；不解析图片内容、不建多模态向量。OCR / 视觉摘要 / 多模态向量均为预留（识别能力归解析环节）。

## 六、后置链（逐章执行，顺序固定）

| 顺序 | 处理器                      | 口径                                                                                                                |
|------|-----------------------------|---------------------------------------------------------------------------------------------------------------------|
| ①    | `StructureOverlapProcessor` | `structureOverlap` 默认 **0 = 不处理**；>0 时把上一片末尾 N 字符前缀到本片（正文 / 表格片）                         |
| ②    | `MinMergeProcessor`         | `minMergeLen` 默认 300：短于它的正文碎片并入**同章紧邻的前一个正文片**；跨表格 / 图片 / 章节不合并                  |
| ③    | `TitleInContentProcessor`   | `titleInContent` 默认 ON：非父片 content 首行拼 `titlePath`（父片是子片拼接、子片已带标题，跳过），`charCount` 重算 |

顺序由 `@Order(1/2/3)` 显式声明（`ChunkPostProcessor` 的契约注释也写明"注册顺序即执行顺序"）。合并只做一次且不跨内容类型，于是**合并后仍可能有欠长片**（统计里的 `underMinMergeCount` 就是观察它的）。

## 七、片的状态与失败语义

| 情形                                 | 落什么                                                                                                                                  |
|--------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------|
| 执行成功 / 部分成功                  | 切片集合产物（`ChunkSet` JSON，产物引用 = 内容 sha256）+ `wb_knowledge_chunk_set` 一行 + `wb_knowledge_chunk` 每片一行 + 六条子步骤记录 |
| 上游视图为空 / 不可读                | 不落产物，任务落 `CHUNK_EMPTY` 与失败说明                                                                                               |
| 无可切内容（元素都被剔除或全无文本） | 同上                                                                                                                                    |
| 执行异常                             | 任务落 `CHUNK_FAILED`（兜底码），错误摘要截断后落到任务与步骤上                                                                         |
| 某个切片器异常                       | 产物照常落，任务落 `PARTIAL_SUCCESS`，异常进对应步骤的告警（`warnings`）                                                                |

子步骤共六条：内容路由 / 正文切片 / 表格切片 / 图片切片 / 兜底切片 / 父子关系补充；capability 取算法枚举键（如 `paragraph-aggregate`，不带版本号）。**兜底切片的耗时恒 0**：兜底在切片器内部触发，无法单独计时（`matched` 与长度仍按 `contentType=FALLBACK` 计数）。

## 八、统计口径（读取侧现算，24 个键）

`ChunkStatsSupport` 读切片产物（+ 上游视图 + 策略快照）现算，不落库；执行树节点与详情共用同一份口径。键的分组：

| 组           | 键                                                                                                                                        |
|--------------|-------------------------------------------------------------------------------------------------------------------------------------------|
| 片数与类型   | `chunkCount`（含父片）、`sectionCount`、`paragraphCount`、`tableCount`、`imageCount`、`fallbackCount`                                     |
| 父子与孤儿   | `parentCount`（被挂子片的父片数）、`orphanCount`                                                                                          |
| 长度         | `totalChars`、`avgChars`、`maxChars`、`overTargetMaxCount`、`overSoftMaxCount`、`minMergeLen`、`underMinMergeCount`（欠长片数，父片不计） |
| 元素         | `routedElementCount`（进入切片）、`skippedElementCount`（被跳过）                                                                         |
| 溯源         | `multiSourceChunkCount`、`avgSourceElementCount`                                                                                          |
| 策略参数回显 | `targetMaxLen`、`softMaxLen`、`fallbackLen`、`fallbackOverlap`                                                                            |
| 耗时         | `durationMs`                                                                                                                              |

策略快照不可解析时，策略参数回显与依赖它的键（`minMergeLen` / `underMinMergeCount` 等）**不下发该键**，页面按 `—` 展示。执行树节点先落通用统计（`chunkCount` 来自 `wb_knowledge_chunk_set` 聚合），再把切片统计 `putAll` **并入**——顺序反了会把 `chunkCount` 覆盖掉。

## 九、参数目录与跨参数约束

**键**在 `ChunkParamKeys`（JSON 契约常量），**范围与说明**在 `ChunkParam`（按 `(算法, 参数键)` 索引，唯一事实源，保存校验与页面提示同源），**默认值**在 `ChunkProperties`（application.yml 同名 kebab-case 键，归一化时由 `ChunkAlgorithmSpec.defaultParams` 补进快照）。

| 算法                           | 参数与范围                                                    |
|--------------------------------|---------------------------------------------------------------|
| 段落聚合 / 结构混合 / 句子聚合 | `targetMaxLen` 100~5000、`softMaxLen` 100~8000                |
| 标题边界                       | `maxLen` 100~20000                                            |
| 正文固定窗口                   | `len` 100~5000、`overlap` 0~1000                              |
| 表格行级                       | `groupThreshold` 5~500、`groupSize` 1~20                      |
| 表格行组                       | `groupSize` 1~50、`maxLen` 100~5000                           |
| 整表一片                       | `maxLen` 100~20000                                            |
| 表 + 引导段落                  | `leadMaxLen` 0~1000、`groupThreshold` 5~500、`groupSize` 1~20 |
| 兜底两算法                     | `len` 100~5000、`overlap` 0~1000                              |

跨参数约束（保存校验一起做）：`softMaxLen ≥ targetMaxLen`（正文聚合三算法）、`overlap < len`（兜底路）、`tableInBodyFlow=ON` 与表格算法 `context-merged` 互斥。未知参数键按前向兼容透传，不报错也不生效。

## 十一、口径补充（容易误读的六点）

1. **`tokenCount` 是字符估值**（`ceil(字符数 ÷ 1.5)`），不是模型 token；开源建议切片器与嵌入模型共用 tokenizer，我们当前用估值，接入真分词登记为待定。
2. **目标上限不是硬约束**：`targetMaxLen` 是结算点，超软上限走**降级**（保内容不丢），于是可能出现长于目标上限的片——用 `overTargetMaxCount` / `overSoftMaxCount` 观察。
3. **结构重叠默认关**（0），要相邻片重叠得显式调大。
4. **整表降级分组不可调**：固定 30/3，不读行级参数（该算法不暴露这两个参数）。
5. **编号是归档序不是阅读序**：阅读序由页面按 `parentChunkId` 重组，对齐键是片 ID。
6. **欠长片是正常产物**：合并只做一次且不跨内容类型，`underMinMergeCount` 与 `minMergeLen` 用于观察。

## 十二、调用链

1. 控制面：策略版本保存时 `ChunkAlgorithmSpec.validate` 校验（算法支持集 + 参数范围 + 三条不变量）；绑定与生效版本解析在 biz 侧。
2. 触发：`KnowledgeFileChunkController` → 策略**两档**解析（显式指定 → 知识库绑定；两档都不命中拒 40438，没有"库内最新"与"内置默认"兜底）→ `ChunkStrategyParser.parse` 归一化 → 快照进任务 → 按执行键（文件结果 + `CHUNK` + 上游产物 + 策略版本）查重（已有任务一律 40431）→ 入队。
3. 执行：`ChunkTaskRunner` 领任务 → 读上游预处理视图 → 构造 `ChunkContext` → `ChunkPipeline.chunk` → 落产物与六条子步骤 → 回写终态与结论文案。
4. 读取：`ChunkControlServiceImpl` 与控制面详情接口读产物；`stage-content` 的过滤与分页下推 DB（`wb_knowledge_chunk`），来源元素个数与兜底原因由产物补齐。
