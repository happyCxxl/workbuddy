# ADR-0001：统一响应体与 HTTP 恒 200

| 项   | 值                                                             |
|------|----------------------------------------------------------------|
| 状态 | 接受                                                           |
| 日期 | 补录（口径确立早于本目录建立，依据 docs/README.md 全局约定一） |

## 背景

前后端需要统一的错误表达。浏览器会把裸 4xx/5xx 渲染成「HTTP ERROR 403」整页，前端拦截器拿不到结构化错误码，无法区分未登录跳转、无权限提示、业务失败提示三类处置。

## 决策

全部接口统一响应体 `R<T>`（code / msg / data / timestamp）；HTTP 状态码恒为 200（网络层故障除外），错误语义全由 code 表达。三处出口共同保证：`GlobalExceptionHandler`（Controller 异常）、`RestAuthenticationEntryPoint`（未登录）、`RestAccessDeniedHandler`（无权限，后两者在 Controller 之前）。新错误码必须登记 `ErrorCode.java` 并按分段落号。

## 备选与否决原因

- 标准 RESTful（4xx/5xx + Problem Details）：浏览器整页渲染吞掉响应体，拦截器拿不到结构化码，前端处置链复杂化。

## 后果

- 前端拦截器统一解包与提示，页面只处理成功分支（`catch {}` 留空是正常写法）。
- 网关与监控不能按 HTTP 状态码统计业务错误率，需按 `R.code` 口径另看。
