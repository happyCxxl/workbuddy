# ADR-0003：「根 + 功能域就近」双层 AGENTS.md 规范体系

| 项   | 值                               |
|------|----------------------------------|
| 状态 | 接受                             |
| 日期 | 本目录建立当日（以提交日期为准） |

## 背景

代码量增长后进入跨会话、跨电脑、多人 + AI 协作开发，出现三类缺口：AI 新会话不自动加载任何项目规范（知识散在 docs/ 与 tools/ 多份文档里，靠人工喂上下文）；规范迭代无机制（取舍无记录、规则无演进日志）；门禁只在本地钩子，`--no-verify` 可绕过。市场调研（AGENTS.md 开放标准、Anthropic / Cursor 官方建议、美团与字节的 AI 编码实践）的共识：入口文件要薄（官方建议 200 行以内）、规则要可判定、细节下沉正典文档、机器兜底。

## 决策

- 分层入口：根 `AGENTS.md` 只放跨功能域的 6 条 Never 与路由表（行数预算 ≤80）；功能域就近建子入口（首个：`web/AGENTS.md`）；正典仍是既有文档（`docs/README.md` 全局约定、`web/docs/前端开发规范.md`、`tools/*/README.md`），入口只路由不复述。
- 人机分治：`AGENTS.md` 写代理行为，`CONTRIBUTING.md` 写人的流程，口径同源互指。
- 迭代机制：踩坑驱动——每犯一个不该犯的错就加一条可判定 Never 并记演进日志；结构变更同步路由表；`tools/check-agents.mjs` 机器校验指针；重大取舍写 ADR（本目录）。
- 后端红线不集中提炼：动 Java 后端前必读两份正典（`docs/README.md` 全局约定 + `tools/backend/README.md`），不建第三份重叠清单。
- 个人偏好与团队规范分离：`AGENTS.local.md` / `CLAUDE.local.md` 进 .gitignore。

## 备选与否决原因

- 单份大而全的 AGENTS.md：超出行数预算，指令越多遵循度整体下降（调研结论），且与正典重复维护。
- 新建 `docs/standards/backend.md` 集中后端红线：与两份既有正典重叠，多一处同步点；且 `docs/` 定位是业务文档，工程治理内容不混入。
- `.cursorrules` / 各工具私有规则：官方已定性 legacy，互不通用；AGENTS.md 是 20+ 工具兼容的中立标准（Linux 基金会治理）。

## 后果

- 任何工具的新会话自动获得同一份入口与同一套路由；贡献者换工具零迁移成本。
- 规范有唯一生长路径（踩坑 → Never → 演进日志），指针关系靠机器校验维持。
- 代价：入口与正典之间的引用关系需要 `check-agents.mjs` 维护；新增功能域多一套「入口 + 正典 + 门禁」的固定动作（CONTRIBUTING §7）。
