# ADR-0006：前端规范拆分为 4 份并建立编号

| 项   | 值             |
|------|----------------|
| 状态 | 接受           |
| 日期 | 以提交日期为准 |

## 背景

- 前端规范原为单文件 202 行、13 节，有【必须】【应该】【可以】三级但**没有任何编号**：无法统计多少条生效、无法在评审里精确引用、无法逐条挂执行者。
- A-03 定为「只给【必须】编号」，A-06 定为「单份条款文档 ≤150 行」。两项叠加后，原 202 行必须拆分。
- 原规范含 59 条【必须】、8 条【应该】、1 条【可以】。

## 决策

1. 拆为四份：`00-规则索引.md`（索引）、`01-工程与命名.md`、`02-组件与样式.md`、`03-异步与测试.md`，每份 ≤150 行。
2. 只给【必须】编号，格式 `WEB-<域>-<三位序号>`；定稿 48 条，分 12 个域（MACHINE / LANG / DIR / API / NAME / STYLE / DOC / COMP / CSS / ROUTE / ASYNC / ENG）。
3. **纯机器强制条款合并**：prettier、eslint、stylelint、ls-lint 已 100% 覆盖的约 10 条格式与文件命名条款，合并为一条 `WEB-MACHINE-001`，不逐条编号。理由是编号的价值在追踪执行者与状态，工具已强制的内容没有状态可追。
4. 退役两条：原 §5.6「组件 `data` 必须是返回对象的函数」属 Vue 2 写法；`WEB-NAME-006`（`this` 暂存用 `self`）在 `<script setup>` 下无 `this`，且无出处。
5. `WEB-COMP-006`（SFC 顶层顺序）退役编号并降为【应该】：Vue 指南列为 C 级，两种顺序均合法，本项目只固定其中一种。
6. 索引新增「来源」列，标注每条出处的等级（见下）。

## 调研结论

对照 Vue 官方风格指南 A/B/C 三级清单与 Google TypeScript Style Guide：

| 来源           | 条数                                            |
|----------------|-------------------------------------------------|
| Vue Priority A | 5（组件相关）                                   |
| Vue Priority B | 4（组件相关）                                   |
| Google TS      | 4（命名大小写、禁缩写、等值判断、通用语言约定） |
| 工具强制       | 1（WEB-MACHINE-001）                            |
| **项目约定**   | **34**                                          |

- **修正一处与官方冲突**：原「禁 `x === undefined`」与 Google TS 相反，Google 要求一律用 `===`、仅 `== null` 例外，已按 Google 改写。
- **新增一条**：Google 有而原规范没有的语言约定（命名导出、禁 `namespace`/`require`、`as` 断言、`switch` default、空 catch 注释），合并为 `WEB-LANG-001`。
- 官方指南只覆盖语言与框架通用部分；分层、接口映射、表格口径、三态等 35 条属**项目约定**，来源列留空，不再默认它们是行业标准。
- 未采用为依据：Airbnb JS 规范近年停更且被 typescript-eslint 取代；typescript-eslint 本次未逐条核对。


## 备选与否决原因

| 备选                     | 否决原因                                                       |
|--------------------------|----------------------------------------------------------------|
| 59 条全部编号            | 索引膨胀到 60 余行，且其中十余条永远处于"生效"，编号只产生噪音 |
| 不拆分，继续单文件       | 违反 A-06 的 150 行上限；加编号后只会更长                      |
| 只保留索引、正文并入索引 | 条款正文与正反例会撑爆单文件，仍然超限                         |
| 把调研来源留在索引文件   | 索引超出 150 行上限                                            |

## 后果

- 前端规则与后端规则结构一致：索引 + 分主题正文 + 编号 + 执行者 + 状态。
- 四份文档需要同步维护：新增规则先编号、再落正文、再登记索引。
- `web/AGENTS.md` 的必读指针改为 `00-规则索引.md`；其余引用（`checkers/`、`docs/`、`java/03`）同步更新。
- 调研来源：Vue 官方风格指南（[v3 中文](https://vueframework.com/docs/v3/cn/style-guide/)）、[Airbnb JavaScript Style Guide](https://github.com/airbnb/javascript)、[腾讯云《前端开发规范》](https://developer.cloud.tencent.cn/article/2321847?policyId=1003)、[eslint-config-tencent](https://www.npmjs.com/package/eslint-config-tencent)。
