# standards — workbuddy 工程规范正典

> 本目录只放**实现形态**：怎么写、怎么分层、怎么命名、怎么测试。
> 业务文档在 `docs/`，接口契约在 `docs/README.md`「全局约定」，检查器在 `tools/`，取舍在 `.agent/adr/`。

## 1. 体系四层

| 层   | 位置                                              | 职责               | 读者        |
|------|---------------------------------------------------|--------------------|-------------|
| 入口 | `AGENTS.md`、`web/AGENTS.md`                      | 薄入口：禁令与路由 | AI 编码代理 |

## 4. 三条硬约束

1. **每条【必须】都要有执行者**：机器检查或评审项，二者必居其一；没有执行者的条款不得标【必须】。
2. **规范先于代码**：确认需要的偏离，先改本目录并通过评审，再改代码；个人习惯让位于规范。
3. **本目录只写现状**：不记录沿革与取舍理由，那部分在 `.agent/adr/`。

## 5. 与入口文件的关系

根 `AGENTS.md` 行数预算 ≤80，只放跨功能域的 Never 与路由表；本目录的条款在入口里只留一行指针，正文不外溢。
`web/AGENTS.md` 同理，前端条款归 `frontend/前端开发规范.md`。
