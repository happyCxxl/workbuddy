# 规则模板

> 复制本文件起草一条规则。编号按语言前缀（`COMMON-` / `JAVA-` / `VUE-`），并入对应文档后在 `00-索引.md` 登记。

## <LANG>-<域>-<序号> <一句话标题>

| 项   | 值                                                               |
|------|------------------------------------------------------------------|
| 等级 | 必须 / 应该 / 可以                                               |
| 判定 | 机器检查名 / 正反例 / 评审                                       |
| 依据 | 外部出处（阿里 §x / Google §x / 框架文档章节）或本项目决策的理由 |
| 适用 | 全部，或点名模块与包                                             |

### 解决什么问题

写根因，不写现象。例：不是「有人把 DTO 叫成 Request」，而是「同一概念有多个名字，读代码要先猜」。

### 行业怎么做

- 阿里手册：条款号 + 结论
- Google：条款号 + 结论
- 两者冲突时写明采用哪一家，以及另一家为何不适用

### 我们怎么做

一句可判定的陈述。含「禁止」「一律」「必须」的写法要能落到具体语法或文件位置。

### 怎么保证

- 机器：检查器名 + 触发点（首选）
- 或：正例与反例（次选）
