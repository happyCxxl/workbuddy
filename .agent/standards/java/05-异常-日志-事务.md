# 05 · 异常、日志与事务

> 本文件只写规则，与具体类名无关。

## 1. 异常

（JAVA-ERR-001）业务拒绝经统一守卫抛出，错误码集中登记。

- 业务拒绝（参数非法、状态不允许、权限不足）用业务异常，携带错误码。
- 内部缺陷（不该发生的分支）用 JDK 异常或运行时异常，不改成业务异常。
- 守卫方法的入参是「条件 + 错误码/异常」，不在调用处手写 `if + throw`。

（JAVA-ERR-002）内部缺陷不得包装成业务异常，也不得改写 JDK 异常类型。

（JAVA-ERR-003）入口层不捕获异常，统一由全局异常出口处理；出口负责把异常转成响应外壳。

（JAVA-ERR-004）禁止空 catch；捕获后必须转错误码，或记日志并重抛。

（JAVA-ERR-005）新增错误码必须在契约文档登记，代码与文档同一次提交。

依据：阿里《异常日志》规约；OWASP Error Handling——对外只给错误码与可读提示，不泄露堆栈。

## 2. 日志

（JAVA-LOG-001）用日志框架输出，禁止 `System.out`、`System.err`、`printStackTrace`。

- 类上使用统一的日志注解或静态 logger，不手写工厂。

（JAVA-LOG-002）级别约定：

| 场景                           | 级别          |
|--------------------------------|---------------|
| 业务拒绝（可预期）             | warn          |
| 系统异常（不可预期）           | error，带堆栈 |
| 流程节点（任务领取、状态切换） | info          |
| 细节与排查用                   | debug         |

（JAVA-LOG-003）日志不含密码、令牌、密钥与完整个人敏感信息；定位需要时打印标识而不是原值。

（JAVA-LOG-004）编排层与异常出口使用统一前缀，方便按前缀检索。

（JAVA-LOG-005）循环体内不写 info 级日志；需要逐条记录时用 debug 或聚合后输出一条。

依据：阿里《日志规约》；OWASP Logging Cheat Sheet。

## 3. 事务

（JAVA-TX-001）事务注解只标在应用服务的 public 方法上，不标在类上、不标在数据访问层。

（JAVA-TX-002）事务内不调用外部 IO：HTTP、对象存储、向量库、消息发送都在事务外完成。

（JAVA-TX-003）同类自调用不走事务代理；需要合并的事务改成跨类调用，或把公共部分合并为一次调用。

（JAVA-TX-004）唯一键冲突在服务端转幂等回放，不向上抛系统异常。

（JAVA-TX-005）只读查询不开事务。

依据：Spring 官方文档——`@Transactional` 默认基于代理，自调用与 private 方法不生效；事务内做远程调用会拉长锁持有时间。
