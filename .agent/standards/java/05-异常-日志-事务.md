# 05 · 异常、日志与事务

> 条款编号见 `00-总则与规则索引.md` §5.4–§5.6。

## 1. 异常的两条口径

（JAVA-ERR-001）（JAVA-ERR-002）**业务拒绝**与**内部缺陷**分开表达：

| 类别     | 含义                                   | 表达方式                                                        | 出口处理                         |
|----------|----------------------------------------|-----------------------------------------------------------------|----------------------------------|
| 业务拒绝 | 请求不满足业务条件，用户可理解、可修正 | `ThrowUtil.throwIf(cond, ErrorCode)` 或 `KnowledgeException`    | warn 级日志，`R.code` 返回业务码 |
| 内部缺陷 | 编程错误、开发期校验、不该发生的状态   | `ThrowUtil.throwIf(cond, () -> new IllegalStateException(...))` | error 级日志带堆栈，返回 `40500` |

正例：

```java
ThrowUtil.throwIf(NullUtil.isNull(kb), ErrorCode.KB_NOT_FOUND);
ThrowUtil.throwIf(existed, ErrorCode.TASK_ALREADY_PENDING, "同一执行键已有任务");
ThrowUtil.throwIf(id <= 0, () -> new IllegalArgumentException("任务 ID 必须为正数"));
```

反例：

```java
if (kb == null) {
    throw new RuntimeException("知识库不存在");        // 业务拒绝用系统异常，错误码丢失
}
if (id <= 0) {
    throw new KnowledgeException(ErrorCode.PARAM_INVALID); // 内部缺陷占了业务码
}
```

## 2. 错误码

（JAVA-ERR-005）

1. 错误码只在 `common/error/ErrorCode` 定义，一处登记，业务代码不写码值字面量。
2. 新增错误码同时更新 `docs/README.md` 错误码表（码值、常量名、默认提示语三列）。
3. 分段沿用现状：`40001` 参数、`401xx` 认证、`402xx` 限流、`404xx` 业务、`40500` 系统兜底。
4. 提示语面向使用者，写「怎么做」而不是堆栈或内部标识。

## 3. 抛与捕的边界

（JAVA-ERR-003）（JAVA-ERR-004）

| 位置       | 规则                                                 |
|------------|------------------------------------------------------|
| Controller | 不写 `try/catch`；异常交给 `GlobalExceptionHandler`  |
| Service    | 校验与拒绝在这里抛；不吞异常                         |
| TaskRunner | 捕获后在任务侧归一成任务错误码并落库，再把结果返回   |
| 全局出口   | `GlobalExceptionHandler` 唯一负责 `R` 包装与日志级别 |

禁止：

- `catch (Exception e) { }` 空块，或只 `printStackTrace()`。
- 捕获后返回 `null` 让上层猜。
- 把受检异常包成运行时异常而不保留 `cause`。
- 在 Controller 里自建 `R` 错误响应（错误语义统一由出口产生）。

## 4. 日志

（JAVA-LOG-001、JAVA-LOG-002、JAVA-LOG-003、JAVA-LOG-004、JAVA-LOG-005）

| 级别    | 用途                                   | 例                                                               |
|---------|----------------------------------------|------------------------------------------------------------------|
| `info`  | 流程节点：任务领取、环节完成、状态切换 | `log.info("===> 任务完成 taskId={}, status={}", taskId, status)` |
| `warn`  | 业务拒绝、可恢复异常                   | `log.warn("===> 业务异常 code={}, msg={}", code, msg)`           |
| `error` | 系统异常，带堆栈                       | `log.error("===> 系统异常", e)`                                  |
| `debug` | 字段级细节，默认不输出                 | `log.debug("===> 入参 {}", dto)`                                 |

规则：

1. 用 `@Slf4j` 与 `log` 对象，禁止 `System.out` 与 `printStackTrace`。
2. 占位符用 `{}`，不拼字符串。
3. 编排层与异常出口统一 `===>` 前缀（JAVA-LOG-004）。
4. 不打印密码、令牌、密钥、完整手机号与身份证号；需要定位时打印 ID。
5. 循环体内不写 `info`；批量处理打首尾各一条。
6. 异常日志写 `log.error(msg, e)`，不带堆栈的 `error` 只用于非异常场景。

## 5. 事务

（JAVA-TX-001、JAVA-TX-002、JAVA-TX-003、JAVA-TX-004、JAVA-TX-005）

| 条款   | 口径                                                          |
|--------|---------------------------------------------------------------|
| 位置   | 只在 `biz/service/impl` 的 public 方法上                      |
| 写法   | `@Transactional(rollbackFor = Exception.class)`，统一显式声明 |
| 范围   | 只包住数据库写；外部 IO 在事务外                              |
| 自调用 | 同类方法内部调用不经过代理，事务不生效                        |
| 只读   | 查询不开事务                                                  |

正例：先校验与准备，再进事务写库。

```java
public String create(KnowledgeBaseCreateDto dto) {
    Long ownerId = SecurityUtil.currentUserId();
    return doCreate(dto, ownerId);          // 事务方法由跨类调用或本类 public 入口进入
}

@Transactional(rollbackFor = Exception.class)
public String doCreate(KnowledgeBaseCreateDto dto, Long ownerId) {
    WbKnowledgeBase entity = new WbKnowledgeBase();
    knowledgeBaseDbService.save(entity);
    auditLogDbService.append(...);
    return String.valueOf(entity.getId());
}
```

注意：上例 `create` 调 `doCreate` 属于同类自调用，事务不生效。需要事务时把入口方法本身标事务，或把写库拆到另一个 Bean。

反例：

```java
@Transactional(rollbackFor = Exception.class)
public void importFile(MultipartFile file) {
    storage.put(file);                       // 对象存储写在事务内
    vectorClient.insert(...);                // 远程调用写在事务内
    fileResultDbService.save(...);
}
```

## 6. 幂等与并发

- 提交类写接口用 `requestId` 做幂等，键与语义见 `docs/README.md`「幂等键」。
- 唯一键冲突（`DuplicateKeyException`）在服务端转幂等回放，不向上抛系统异常（JAVA-TX-004）。
- 任务领取用条件更新（`claim`）实现互斥，不依赖先查后改。
- 共享可变的执行池、计数器字段用 `volatile` 或并发容器，并在类注释写明可见性约定。
