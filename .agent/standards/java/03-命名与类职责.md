# 03 · 命名与类职责

> 条款编号见 `00-总则与规则索引.md` §5.2。

## 1. 后缀词表

类名后缀只能取自本表（JAVA-NAME-001）。表外后缀需要新增时，先在本表登记并说明职责边界。

| 后缀            | 是什么                                            | 允许依赖                         | 先例                                            |
|-----------------|---------------------------------------------------|----------------------------------|-------------------------------------------------|
| `Controller`    | HTTP 入口：绑定参数、调 Service、包 `R`           | Service                          | `biz/controller/model/ModelController`          |
| `Service`       | 应用服务接口，一个用例一个方法                    | —                                | `biz/service/ModelService`                      |
| `ServiceImpl`   | 应用服务实现，编排与事务边界                      | DbService、Support、worker 策略  | `biz/service/impl/ModelServiceImpl`             |
| `DbService`     | 单表数据访问门面，CRUD 与查询组装，不含业务判断   | Mapper                           | `biz/service/db/WbSubmitLogDbService`           |
| `DbServiceImpl` | 数据访问实现，继承 `InfraDbService`               | Mapper                           | `biz/service/db/impl/WbSubmitLogDbServiceImpl`  |
| `Mapper`        | MyBatis-Plus 映射接口，只声明 SQL                 | 实体                             | `biz/mapper` 下各接口                           |
| `DTO`           | 请求入参（阿里口径：后缀全大写）                  | 无                               | `common/dto/request/model/ModelSaveDTO`         |
| `VO`            | 响应出参                                          | 无                               | `common/dto/response/model/ModelItemVO`         |
| `Assembler`     | 实体到 VO 的纯映射，不查库、不判断                | 无                               | `biz/service/support/InputVoAssembler`          |
| `Support`       | 无状态辅助：统计、解析、守卫，可注入协作对象      | DbService、其它 Support          | `biz/task/support/TaskRunnerSupport`            |
| `Helper`        | 纯函数集合，只在 `worker` 层                      | 无                               | `worker/pipeline/StepLogHelper`                 |
| `Handler`       | 框架回调：异常出口、拒绝处理、降级                | 视场景                           | `biz/config/GlobalExceptionHandler`             |
| `Provider`      | 可替换的能力实现，多实现按配置选择                | 底层客户端                       | `filecenter/provider/StorageProvider`           |
| `Registry`      | 注册表或查找表，启动期装载、运行期只读            | 无                               | `model/registry/ModelRegistry`                  |
| `Resolver`      | 从多来源解析出单个结果                            | DbService、其它 Support          | `biz/service/support/IndexLineageResolver`      |
| `Runner`        | 环节任务执行器，一个环节一个                      | DbService、worker 策略           | `biz/task/runner/ParseTaskRunner`               |
| `Config`        | Spring 配置类                                     | 无                               | `auth/config/SecurityConfig`                    |
| `Properties`    | 配置绑定对象                                      | 无                               | 各 `*Properties`                                |
| `Util`          | 静态工具，`final` + 私有构造 + 全静态             | 无                               | `common/utils/NullUtil`                         |
| `Exception`     | 业务异常类型                                      | 无                               | `common/exception/KnowledgeException`           |
| `Enum`          | 码值枚举，带 `of()` 解析                          | 无                               | `common/enums` 下各枚举                         |
| `Strategy`      | 可替换的算法实现，同一族共用一个接口，按配置选用  | 无框架依赖                       | `SliceStrategy`、`EmbedStrategy`                |
| `Context`       | 一次执行过程中的可变上下文，在步骤之间传递        | 可持有实体与中间结果             | `ParseContext`、`RuleContext`                   |
| `Result`        | 单步或单算法的产出，只承载结果数据                | 不查库、不含行为                 | `ParseResult`、`LayoutResult`                   |
| `Info`          | 实体或产物的附属信息片段，不含业务行为            | 无                               | `FontInfo`、`QualityInfo`                       |
| `Processor`     | 后置处理步骤，对已有结果再加工一轮                | 输入输出同族                     | `MinMergeProcessor`、`TitleInContentProcessor`  |
| `Record`        | 一次运行或一次冲突的记录行                        | 与表记录对应时放 `common/domain` | `EmbeddingRecord`、`ConflictRecord`             |
| `Snapshot`      | 某一时刻的只读快照，执行期固化、不可变            | 无                               | `CapabilitySnapshot`、`ComboSnapshot`           |
| `Factory`       | 按条件创建实例，内部含分支选择                    | 底层客户端                       | `MilvusClientFactory`、`StorageProviderFactory` |
| `Builder`       | 把多段文本或结构拼装成整体对象                    | 不查库                           | `TextTableBuilder`、`RuledTableBuilder`         |
| `Listener`      | Spring 事件监听器，只做转发                       | Service                          | `AuditEventListener`                            |
| `Client`        | 外部服务客户端，只做协议转换                      | 底层 SDK                         | `AiClient`                                      |
| `Consumer`      | 队列消费者，消费后交给 Service 或 TaskRunner      | Service、TaskRunner              | `PipelineTaskConsumer`                          |
| `Query`         | 领域检索请求对象，不是 HTTP 请求（HTTP 用 `DTO`） | 无                               | `VectorQuery`、`FullTextQuery`                  |
| `Param`         | 算法入参的成组对象，用于缩短参数列表              | 无                               | `ChunkParam`、`PreprocessParam`                 |

表实体以 `Wb` 开头、按表名驼峰命名，不受本表约束。`View`、`Template` 不收录为通用后缀：前者是历史遗留（新响应用 `VO`），后者仅一处、含义未定，待清理。

依据分层：`DTO`、`VO`、`Impl`、`Exception`、`Abstract`/`Base` 开头取自阿里手册命名风格（强制条款）；`Strategy`、`Context`、`Result`、`Info`、`Processor`、`Record`、`Snapshot`、`Factory`、`Builder`、`Listener`、`Client`、`Consumer`、`Query`、`Param` 为本项目决定的角色后缀，依据是职责边界，不引外部标准。

## 2. 请求与响应的命名式

（JAVA-NAME-002）只有两种形态：

| 角色     | 命名式         | 动作词表                                                                       |
|----------|----------------|--------------------------------------------------------------------------------|
| 请求对象 | `Xxx<动作>DTO` | `Create`、`Update`、`Save`、`Query`、`Status`、`Trigger`、`Publish`、`Compare` |
| 响应对象 | `XxxVO`        | 无动作词，按视图命名（`Detail`、`Item`、`Summary`、`Stats`）                   |

禁止新增 `Request`、`Response`、`View`、`Param`、`Filter` 后缀。存量四类按模块逐步并入，新代码不得增加。

（JAVA-NAME-003）`XxxServiceImpl` 实现同名 `XxxService`，一对一对应；不存在一个接口多个实现，也不存在实现类没有接口。

（JAVA-NAME-004）DbService 一表一个：`Wb<表名驼峰>DbService` 与其 `DbServiceImpl`，一个实体表只有一个数据访问门面。

## 3. 命名细则

1. 类名：`UpperCamelCase`，名词或名词短语；不出现拼音、中文、随意缩写。
2. 方法名：`lowerCamelCase`，动词或动词加名词；布尔方法以 `is`、`has`、`can`、`should` 开头。
3. 字段与参数：`lowerCamelCase`；布尔字段用 `isXxx`、`hasXxx`、`xxxEnabled`。
4. 常量：`UPPER_SNAKE_CASE`（JAVA-NAME-008）。
5. 包名：全小写，单数，按域分包，与模块职责表一致。
6. 实体：`Wb<表名驼峰>`，一表一类，字段与列名一一对应。
7. 测试类：`XxxTest`，与被测类同包同模块（JAVA-TEST-001）。
8. （JAVA-NAME-007）工具类放 `common/utils`，单数 `Util`，`final` + 私有构造 + 全静态方法。
9. 领域词汇表：一张表里的业务字段，代码名与本项目既有 `common/enums` 与 `docs/README.md` 错误码表用词一致。

## 4. 类职责边界

（JAVA-NAME-006）一个类只承担 §1 里的一个角色。下列混装一律不合规：

| 混装                              | 应拆成                                          |
|-----------------------------------|-------------------------------------------------|
| 查库 + 业务判断 + 拼 VO           | DbService + Service + Assembler                 |
| Controller 里做校验分支与权限判断 | Controller + Service（`@AdminOnly` 标注在方法） |
| Support 里开事务                  | 上移到 Service                                  |
| Assembler 里查库                  | 查库结果作为入参传入                            |
| Handler 里编排业务流程            | Service，Handler 只做回调出口                   |

## 5. 正例与反例

正例：单一角色、依赖方向明确。

```java
@Component
public class InputVoAssembler {
    public SubmitLogVO toSubmitLogVO(WbSubmitLog log) {
        SubmitLogVO vo = new SubmitLogVO();
        vo.setId(log.getId());
        return vo;
    }
}
```

反例：同一个类里混装查询、判断与映射，且后缀与职责不符。

```java
@Component
public class KnowledgeManager {          // Manager 不在词表内
    public SubmitLogVO build(Long id) {
        WbSubmitLog log = logDbService.getById(id);   // 查库
        if (log == null) { throw new KnowledgeException(ErrorCode.FILE_RESULT_NOT_FOUND); } // 业务判断
        SubmitLogVO vo = new SubmitLogVO();           // 映射
        vo.setId(log.getId());
        return vo;
    }
}
```

## 6. 新增词表项与例外

- 新增后缀：先在 §1 加一行（职责、允许依赖、先例），再写代码。
- `Manager`、`Processor`、`Factory` 不收录为通用后缀；确需使用，先写 ADR 说明与既有后缀的边界差异。
- 存量 `Helper` 出现在 `biz` 层的，随模块收敛迁成 `Support`；新代码不得在 `biz` 层新建 `Helper`（JAVA-NAME-005）。
