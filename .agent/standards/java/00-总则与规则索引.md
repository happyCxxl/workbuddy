# 00 · 总则与规则索引

> 本文件只写规则，与具体产品、具体模块无关；规则正文在 `01`–`08` 各域文档。

## 1. 分级

| 等级     | 含义                   | 违反后果                       |
|----------|------------------------|--------------------------------|
| 【必须】 | 可判定的底线           | 不合规；能机器化的一律机器拦截 |
| 【应该】 | 多数场景更优的写法     | 偏离须在交付说明中写明理由     |
| 【可以】 | 同等选项里取一个作默认 | 保持全库一致即可               |

## 2. 规则编号

`JAVA-<域>-<三位序号>`，域取值：

| 域    | 覆盖                                |
|-------|-------------------------------------|
| META  | 规则体系自身的约束                  |
| LAYER | 模块依赖、包结构、跨层调用          |
| NAME  | 类名后缀、命名细则、类职责边界      |
| DTO   | 请求/响应形态、校验、分页、出参类型 |
| ERR   | 错误码与异常用法                    |
| LOG   | 日志级别、内容、前缀                |
| TX    | 事务边界与并发                      |
| TEST  | 单测与集成测试                      |
| DOC   | 注释与 Javadoc                      |

编号一经分配不复用；规则删除后序号作废。

## 3. 执行者

每条【必须】必须有主执行者；允许「主执行者 + 兜底」两项，索引里写明主执行者。

| 判定值       | 含义                           |
|--------------|--------------------------------|
| `构建期检查` | 编译或打包阶段执行，失败即阻断 |
| `静态分析`   | 源码或字节码扫描，接入推送门禁 |
| `形态检查`   | 命名、结构、import 的约定扫描  |
| `覆盖率`     | 覆盖率工具按阈值判定           |
| `评审`       | 交付前按评审清单逐条核对       |
| `变更门禁`   | 推送或合并时执行               |

（JAVA-META-001）能机器化判定的条款不得标「评审」；**评审项上限 5 条**——指评审清单的条目数，不是规则条数。判定为「评审」的规则必须挂在其中一个条目下。超出上限时先补扫描器，或把该条降为「应该」。

（JAVA-META-002）依据优先外部：阿里手册 > Google Java Style > 框架官方文档；外部无规定时由本项目决定并写明理由；存量实现不得作为立规依据。

### 4.1 分层与依赖

| 编号           | 等级     | 条款                                                             | 判定     |
|----------------|----------|------------------------------------------------------------------|----------|
| JAVA-LAYER-001 | 【必须】 | 模块依赖只能指向已存在的模块，禁止成环与自依赖；具体边由评审把关 | 形态检查 |
| JAVA-LAYER-002 | 【必须】 | 入口层只依赖用例接口，禁止依赖数据访问、映射与实体               | 形态检查 |
| JAVA-LAYER-003 | 【必须】 | 依赖方向只能指向更底层；基础层可被任意模块依赖，反向禁止         | 形态检查 |
| JAVA-LAYER-004 | 【必须】 | 顶层按业务能力分包；新增包先登记职责与允许依赖，再建目录         | 评审     |
| JAVA-LAYER-005 | 【应该】 | 单文件 ≤400 行；超出按数据访问、业务判断、映射三类拆分           | 形态检查 |
| JAVA-LAYER-006 | 【可以】 | 单一实现的用例仍保留接口，实现类用 `Impl` 后缀                   | 评审     |

|---------------|----------|----------------------------------------------------|------------|
| JAVA-NAME-001 | 【必须】 | 类名后缀取自语表，词表外的后缀不得新增             | 形态检查   |
| JAVA-NAME-002 | 【必须】 | 请求对象 `XxxDTO`、响应对象 `XxxVO`，后缀全大写    | 形态检查   |
| JAVA-NAME-003 | 【必须】 | `XxxServiceImpl` 必须实现同名 `XxxService`，一对一 | 形态检查   |
| JAVA-NAME-004 | 【必须】 | 数据访问接口一表一个，命名体现表名                 | 形态检查   |
| JAVA-NAME-005 | 【必须】 | 技术助手的后缀限定所在的层，不得跨层混用           | 形态检查   |
| JAVA-NAME-006 | 【必须】 | `Handler` 只用于框架回调，不做业务编排             | 评审       |
| JAVA-NAME-007 | 【应该】 | 工具类 `final`、私有构造、全静态，放统一的工具包   | 评审       |
| JAVA-NAME-008 | 【必须】 | 常量全大写下划线分隔；字段与参数小驼峰；包名全小写 | 构建期检查 |

## 5. 评审项（上限 5 条，见 JAVA-META-001）

> 评审项指下面清单的条目数，不是规则条数；判定为「评审」的规则必须挂在其中一个条目下，机器能判定的不得挂这里。

交付说明里给出逐项结论，未核对的按未交付处理：

- [ ] **结构与分层**：新增包已登记；跨层调用符合 `01-分层与依赖.md`（LAYER-004、DTO-001）
- [ ] **命名与注释形态**：后缀在词表内；注释无禁词，未写作者与日期（NAME-001/002、DOC-002/003/004）
- [ ] **错误处理**：业务拒绝经统一守卫；错误码已登记并同步契约文档（ERR-001/002/005）
- [ ] **事务**：只标在应用服务的 public 方法；事务内无外部 IO（TX-001/002/003）
- [ ] **测试**：新增接口与错误分支有测试；集成测试打了标签（TEST-003/004）

## 6. 新增、修改、删除一条规则

1. 复制 `../_template.md` 起草，分配编号。
2. 改规范与改代码分开提交：先规范、后代码。
3. 依据写进该规则的「行业怎么做 / 我们怎么做」两段，随提交留痕。
4. 规则必须绑定执行者：能机器化的接检查器，不能的挂进 §5 评审项。
5. 删除：从本索引与正文同时移除，序号作废、不复用。
