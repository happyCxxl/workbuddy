# Java 后端实现规范 · 总则与规则索引

> 本文件是 Java 后端实现条款的总表。分级、编号、状态的规则见 §1–§4；条款正文在 01–06 各域文档。
> 接口契约口径（响应体、错误码、鉴权、限流、分页字段、空值判定）以 `docs/README.md`「全局约定」为准，本目录只引用。

## 1. 分级与判定

| 等级     | 含义                   | 违反后果                       |
|----------|------------------------|--------------------------------|
| 【必须】 | 可判定的底线           | 不合规；能机器化的一律机器拦截 |
| 【应该】 | 多数场景更优的写法     | 偏离须在交付说明中写明理由     |
| 【可以】 | 同等选项里取一个作默认 | 保持全库一致即可               |

## 2. 规则编号

`JAVA-<域>-<三位序号>`，域取值：

| 域    | 覆盖                                |
|-------|-------------------------------------|
| META  | 规则体系自身的约束                  |
| LAYER | 模块依赖、包结构、跨层调用          |
| NAME  | 类名后缀、命名细则、类职责边界      |
| DTO   | 请求/响应形态、校验、分页、出参类型 |
| ERR   | 错误码与异常用法                    |
| LOG   | 日志级别、内容、前缀                |
| TX    | 事务边界与并发                      |
| TEST  | 单测与集成测试                      |
| DOC   | 注释与 Javadoc                      |

编号一经分配不复用，规则退役后序号作废。

## 3. 执行者

每条【必须】必须有且只有一个主执行者：

| 判定值                            | 含义                                            |
|-----------------------------------|-------------------------------------------------|
| `checkstyle` / `PMD` / `SpotBugs` | 既有引擎，`mvn verify` 拦截                     |
| `check-comments`                  | `tools/check-comments.mjs`，pre-push 与本机预跑 |
| `check-java-conventions`          | 待建：词表与形态扫描，pre-push 拦截             |
| `arch-scan`                       | 待建：import 级结构与依赖方向扫描               |
| `评审`                            | 本文件 §6 评审项，交付前逐条核对                |
| `pre-push`                        | `tools/pre-push-gate.sh`，推送时执行            |
| `CI`                              | `.github/workflows/gate.yml`                    |

（JAVA-META-001）能机器化判定的条款不得标「评审」；评审项总数上限 5 条，只保留机器无法判定且后果严重的条款。超出上限时先补扫描器，或把该条降为「应该」。

## 4. 状态

| 状态   | 含义                                 |
|--------|--------------------------------------|
| 生效   | 已实施，违反即拦                     |
| 试用   | 已实施，只报 WARN，不拦              |
| 待落地 | 条款已定，机器检查尚未接入（阶段二） |
| 退役   | 不再适用，索引保留编号               |

## 6. 评审项（上限 5 条，见 JAVA-META-001）

> 下列条目是逐条审计前的存量，收敛目标 5 条；每条归「机器」还是「评审」，在逐条审计中确定。

交付说明里给出逐项结论，未核对的按未交付处理：

- [ ] 新增包已登记进 `01` §3，跨层调用符合 `01` §4
- [ ] 新后缀在词表内；无 Request、Response、View、Param、Filter 后缀（JAVA-NAME-001/002）
- [ ] 业务拒绝经 `ThrowUtil`；错误码已登记并同步 `docs/README.md`（JAVA-ERR-001/005）
- [ ] 事务只在 application service，事务内无外部 IO（JAVA-TX-001/002）
- [ ] 新增接口与错误分支有测试；集成测试标 `@Tag("integration")`（JAVA-TEST-003/004）
- [ ] 注释不含禁词，未新增 `@author`（JAVA-DOC-002/003/004）

## 7. 新增、修改、退役一条规则

1. 复制 `../_template.md` 起草，分配编号。
2. 改规范与改代码分开提交：先规范、后代码。
3. 涉及取舍的写 ADR（`.agent/adr/`）。
4. 机器检查先以「试用」接入，稳定一个迭代后转「生效」。
5. 退役：状态改「退役」，索引行保留。
