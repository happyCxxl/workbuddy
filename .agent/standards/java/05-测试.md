# 05 · 测试

> 条款编号见 `00-总则与规则索引.md` §5.7。

## 1. 两类测试

| 类型             | 注解                                      | 依赖                        | 执行位置              |
|------------------|-------------------------------------------|-----------------------------|-----------------------|
| 单元测试（默认） | `@ExtendWith(MockitoExtension.class)`     | 无容器、无中间件            | `mvn test`、pre-push  |
| 集成测试         | `@SpringBootTest` + `@Tag("integration")` | MySQL、Redis、MinIO、Milvus | 本机手动、CI 单独 job |

（JAVA-TEST-002）单元测试不启动 Spring 容器；只有需要真实容器或跨 Bean 协作时才用集成测试。
（JAVA-TEST-003）集成测试必须打 `@Tag("integration")`，不进 pre-push。

## 2. 命名与结构

（JAVA-TEST-001）测试类 `XxxTest`，与被测类同包同模块：`biz/service/impl/FooServiceImpl` 对应 `biz/service/impl/FooServiceImplTest`。

结构二选一，同一文件内保持一致：

```java
@Test
void 创建知识库_名称为空_抛参数错误() {
    // given
    KnowledgeBaseCreateDto dto = new KnowledgeBaseCreateDto();
    // when
    KnowledgeException e = assertThrows(KnowledgeException.class, () -> service.create(dto));
    // then
    assertEquals(ErrorCode.PARAM_INVALID.getCode(), e.getCode());
}
```

```java
@Nested
class 创建 {
    @Test
    void 名称为空时抛参数错误() { ... }
}
```

规则：

1. 方法名用中文描述「场景 + 条件 + 预期」，与 `given / when / then` 三段对应。
2. 一个测试只断言一件事；断言多段时按段注释。
3. 断言错误码而不是错误消息文案（文案会调整）。
4. 不写 `assertTrue(true)` 之类占位断言。

## 3. 必测清单

（JAVA-TEST-004）

- 新增或修改的错误码分支，每个分支至少一条。
- 边界值：`0`、空、超长、超大页码、空集合。
- 幂等路径：同键重复到达返回首次结果。
- 状态机非法迁移：拒绝并返回对应错误码。
- 事务不可测的部分，在测试方法注释里写明「单测不覆盖事务回滚」并说明由哪层保证。

## 4. mock 口径

只在边界处 mock：

| 类型                                       | 处理                          |
|--------------------------------------------|-------------------------------|
| `DbService`                                | mock，返回构造好的实体        |
| `StorageProvider`、Milvus 客户端、模型网关 | mock                          |
| `Support`、`Assembler`                     | 尽量用真实对象，纯函数不 mock |
| 静态工具（`NullUtil`、`ThrowUtil`）        | 不 mock                       |

规则：

1. mock 数量控制在 5 个以内；超过说明被测类职责过多，先拆类。
2. 不用 `verify` 断言内部调用顺序，只断言外部行为与返回结果。
3. 不打桩「不可能发生的分支」来凑覆盖率。

## 5. 禁止项

（JAVA-TEST-005）

- 依赖执行顺序的测试（共享静态状态、依赖前一个测试造的数据）。
- `Thread.sleep` 等异步结果；需要等待时用轮询断言加超时上限。
- 访问真实外网、真实对象存储桶、生产库。
- 断言日志输出。
- 在测试里读本地绝对路径。

## 6. 文件规模

（JAVA-TEST-006）单个测试文件 ≤400 行；超出按场景抽 `XxxTestSupport`（共享构造与断言助手），不拆碎测试类。

## 7. 现状与收敛

- 现有测试全部是 Mockito 单元测试，规模 167 个文件，最大单文件 1016 行。
- 集成测试从「启动校验、事务边界、任务链路」三类开始补，每次新增一类基础设施依赖时同步补一条。
- 超过 400 行的存量测试文件随模块收敛拆分，不在新功能提交里顺带大改。
