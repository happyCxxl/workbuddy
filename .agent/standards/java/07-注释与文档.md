# 07 · 注释与文档

> 本文件只写规则，与具体类名无关。注释与代码是否一致由评审判定，格式与覆盖由机器判定。

| 小节               | 判定     | 具体怎么判                                                                             |
|--------------------|----------|----------------------------------------------------------------------------------------|
| 1 覆盖面           | 形态检查 | check-javadoc 判 public/protected 类型与方法是否缺 Javadoc                             |
| 2 格式             | 形态检查 | check-javadoc 判标记、摘要、标签顺序与行宽                                             |
| 3 实现注释         | 评审     | 「只写非显然处」无法机器判定                                                           |
| 4 禁止项           | 形态检查 | 作者/日期、TODO 形态由 check-javadoc 判；「变更记录」小节与路径有效性由 check-docs 判；沿革散文无机器判定，靠评审 |
| 5 注释与文档的分工 | 评审     | —                                                                                      |

## 1. 覆盖面

（JAVA-DOC-001）`public` / `protected` 的类型（类、接口、枚举、record）必须有 Javadoc，说明职责。

（JAVA-DOC-002）`public` / `protected` 的方法必须有 Javadoc，写全参数、返回值与抛出的异常。

- 抽象方法与接口方法还必须说明「做什么」。
- 枚举常量必须有注释说明用途。
- 构造器按方法处理。
- **不设例外**：`@Override` 方法、访问器同样要求。
- `private` 成员不要求。

依据：Google Java Style §7.3——每个可见类与成员至少有 Javadoc；阿里注释规约第 1、2、5 条——类、属性、方法强制 Javadoc，抽象方法必须说明做什么。

## 2. 格式

（JAVA-DOC-006）文档注释按下列形态书写：

| 项   | 规则                                                                                    |
|------|-----------------------------------------------------------------------------------------|
| 标记 | 只用 `/** */`；不得用 `//` 充当文档注释                                                 |
| 单行 | 没有块标签且整行 ≤120 字符时，允许 `/** 摘要。 */`                                      |
| 多行 | `/**` 与 `*/` 各占一行；内容行以 ` * ` 对齐                                             |
| 摘要 | 首句是完整句、以句号结尾；不以「该方法」「本方法」「This method」开头                   |
| 分段 | 空 `*` 行分段，段首加 `<p>`                                                             |
| 标签 | 顺序 `@param` → `@return` → `@throws` → `@deprecated`；标签后空一格；续行缩进 4 空格    |
| 完整 | `@param` 覆盖全部参数且非空；非 `void` 必须有 `@return`；`@throws` 与声明的异常一一对应 |
| 行宽 | 每行 ≤120 字符                                                                          |

样板：

```java
/**
 * 按知识库标识查询文档分页。
 *
 * <p>只返回未删除的文档，排序固定为创建时间倒序。
 *
 * @param knowledgeBaseId 知识库标识，不能为空
 * @param query 分页与筛选条件
 * @return 文档分页结果
 * @throws BizException 知识库不存在时抛出
 */
```

依据：Google Java Style §7.1（基本形态、段落、块标签顺序）、§7.2（摘要片段）、§4.4（列宽）；阿里代码格式——单行不超过 120 字符。

## 3. 实现注释

（JAVA-DOC-007）实现注释只写非显然处：前提、不变量、副作用、反直觉的选择。

- 单行 `//` 必须独立成行、位于被注释语句上方，与代码同缩进。
- 多行用 `/* */`，与代码左对齐。
- **禁止行尾注释**：不得在代码行末尾追加 `// ...`。
- 方法体内连续注释超过 3 行，说明该方法需要拆分（评审）。
- 禁止保留注释掉的代码。

依据：Linux 内核风格 §8——注释说 WHAT 不说 HOW，避免在函数体内写注释；阿里注释规约第 4、8 条——单行注释另起一行、注释掉的代码无用即删。

## 4. 禁止项

（JAVA-DOC-003）注释只写契约：做什么、约束、副作用；不写沿革、动机叙事、所处阶段与人员。等级【必须】。

（JAVA-DOC-004）不写 `@author`、`@since` 的人员与日期。

（JAVA-DOC-008）`TODO` / `FIXME` 必须写成 `TODO(负责人): 触发条件`，两项缺一即删除。

（JAVA-DOC-009）文档中不得出现「变更记录」「决策记录」小节。

（JAVA-DOC-010）文档里引用的仓库路径必须指向真实存在的文件：Markdown 链接目标与反引号里的文件路径都算，基准按文档所在目录优先、仓库根兜底。删文件时同步删引用——失效的指针比没有指针更糟。等级【必须】；判定：`check-docs.mjs`。

依据：Google Java Style §4.8.6.2——TODO 必须带上下文，不指向个人；负责人即上下文入口，触发条件即恢复条件。

## 5. 注释与文档的分工

| 载体        | 写什么                       |
|-------------|------------------------------|
| 代码注释    | 这一处为何这样写、有什么约束 |
| 类/方法注释 | 对外契约与用法               |
| 规范文档    | 全项目统一的规则             |
| 业务文档    | 功能、流程、口径             |

同一条信息只写一处；其它位置引用而不复述。
