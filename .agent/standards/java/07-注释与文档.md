# 07 · 注释与文档

> 本文件只写规则，与具体类名无关。

## 1. 写什么

（JAVA-DOC-003）注释只写**做什么**：职责、约束、不变量、副作用、易踩坑处。

不写：

- 谁写的、什么时候写的。
- 从哪来的、改过几次、处于哪个阶段。
- 代码已经表达清楚的内容（`setName` 上的「设置名称」）。

依据：Google Java Style §7；Google eng-practices——注释解释这段代码为何存在，不复述它在做什么。

## 2. 类与方法

（JAVA-DOC-001）每个类有一句话职责注释。

（JAVA-DOC-002）public 方法有注释；非显然参数逐个说明，返回值的约束写清楚。

- 接口的注释写契约：入参约束、返回语义、抛什么异常。
- 实现的注释写差异：与接口不同之处、性能或并发上的取舍。

## 3. 禁止项

（JAVA-DOC-004）不写作者、日期与人员信息（`@author`、`@since` 的人员部分）。

（JAVA-DOC-005）引用类型用链接语法（`{@link}`），不写文件名与行号——行号会漂移。

其它：

- 注释掉的代码一律删除，不留「备用」。
- 待办事项必须带处理人与触发条件；两项缺一即删除。

## 4. 注释与文档的分工

| 载体        | 写什么                       |
|-------------|------------------------------|
| 代码注释    | 这一处为何这样写、有什么约束 |
| 类/方法注释 | 对外契约与用法               |
| 规范文档    | 全项目统一的规则             |
| 业务文档    | 功能、流程、口径             |

同一条信息只写一处；其它位置引用而不复述。
