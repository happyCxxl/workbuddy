# 07 · 注释与文档

> 条款编号见 `00-总则与规则索引.md` §5.8。

## 1. 注释写什么

（JAVA-DOC-001 至 JAVA-DOC-003）注释只写做什么（职责与行为），不写谁写的、缘由、来历、阶段与编号。

| 该写                                       | 不该写                       |
|--------------------------------------------|------------------------------|
| 这个类/方法保证什么行为                    | 谁在什么时候写的             |
| 前置条件与不变量（参数可空、幂等键必传）   | 哪次需求、哪个阶段、第几版   |
| 边界与副作用（会写哪几张表、会发什么事件） | 作者与日期                   |
| 易踩坑处的一句提醒                         | 大段复制自设计文档的业务描述 |

（JAVA-DOC-004）不写 `@author`，不写日期与人员。存量 `@author` 随模块收敛删除，新代码不新增。

## 2. 范围

（JAVA-DOC-002）public 方法必须有 Javadoc；类的 Javadoc 写清职责，方法的 Javadoc 写清行为与副作用。

| 位置         | 要求                                                        |
|--------------|-------------------------------------------------------------|
| 类           | 必须有 Javadoc，第一行一句话职责，空行后写约束与边界        |
| public 方法  | 必须有 Javadoc；非显然参数写 `@param`，有返回值写 `@return` |
| private 方法 | 逻辑超过一屏或含算法步骤时写                                |
| 字段         | 含义不自明时写行尾注释；枚举值逐个注释                      |
| 测试方法     | 方法名表达场景，一般不再写注释                              |

## 3. 写法

（JAVA-DOC-005）

1. 引用类型与字段用 `{@link Foo}`、`{@link Foo#bar()}`，不写文件名与行号。
2. 段落用 `<p>`，列表用 `<ul>/<li>`，代码片段用 `{@code ...}`。
3. 一句话职责不超过两行；细节放第二段。
4. 同一个口径只在一处写全，其余位置用 `{@link}` 指过去。
5. 注释与代码同步修改；删除代码时同步删除注释。

## 4. 正例与反例

正例：一句话职责 + 约束。

```java
/**
 * 知识库应用服务：管理闭环与文档输入编排。
 *
 * <p>写操作在事务内完成，审计与主表同事务；幂等键由调用请求携带，重复到达返回首次结果。
 */
```

反例：写来历与作者，职责缺失。

```java
/**
 * 知识库业务类。
 *
 * 2024 年重构时从旧服务拆出来，当时为了兼容老接口保留了两个方法。
 *
 * @author cxxl
 * @date 2024-06-01
 */
```

## 5. 文档同步

1. 接口契约变化：先改 Controller 与 DTO，再同步 `docs/pages/<页面>/02-接口交互.md`。
2. 错误码变化：同步 `docs/README.md` 错误码表（JAVA-ERR-005）。
3. 端到端行为变化：同步对应环节文档与 `04-自测清单.md`。
4. 规范条款变化：只改 `.agent/standards/` 与入口指针，不在业务文档里复述。
