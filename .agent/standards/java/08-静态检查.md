# 08 · 静态检查

> 本文件只写规则，与具体工具版本、配置文件路径无关。

## 1. 必须执行的检查

（JAVA-META-003）构建期必须执行下列检查，任一不通过即阻断：

| 检查类       | 覆盖                                                                       |
|--------------|----------------------------------------------------------------------------|
| 源码风格     | 命名、导入、括号、空白、行长                                               |
| 源码静态分析 | 未使用成员与参数、可疑写法                                                 |
| 字节码分析   | 空指针、资源泄漏、`equals`/`hashCode`、可疑集合用法                        |
| 重复代码     | 片段重复（阈值统一，全库一致）                                             |
| 覆盖率       | 语句与分支覆盖达标（见 `06-测试.md`）                                      |
| 形态约定     | 后缀词表、请求/响应命名、注释形态、import 分层                             |
| 用例质量     | 恒真断言、无断言、只验交互、缺来源说明（见 `06-测试.md` 的 JAVA-TEST-011） |

用例质量由 `.agent/tools/java/check-test-quality.mjs` 执行：推送门禁只查本次改动的测试文件；全量扫描作为基线报告。变异检查（PIT）挂在核心链路模块的 `mutation` profile，按需执行。

依据：Google《Software Engineering at Google》第 11 章——确定性执行优先于散文；能机器判定的不得靠人记。

## 2. 阻断与豁免

- 构建期检查失败即阻断构建，不提供「先过再修」的开关。
- 不设行内豁免；检查器配置里的排除项必须逐条对应一条编号规则，并在该规则正文写明理由。
- 同一类告警反复出现时，改代码而不是放宽检查。

## 3. 规则集的位置

- 规则集与代码同仓，随版本一起评审。
- 规则集变更属于规范变更：先说明影响面，再改配置。
- 规则集的口径取自外部依据（见 `JAVA-META-002`），不得为迁就存量放宽。

## 4. 与推送门禁的关系

- 推送前执行与构建期相同的检查，范围按改动计算。
- 门禁失败：修到全绿再推；修不动如实报告，禁止绕过。
- 改动只涉及文档或注释时，可跳过编译类检查，但不能跳过 Javadoc、文档结构与编码检查。

## 5. 检查器本身的约束

- 每个检查器只判定一类问题，输出「文件:行 规则 说明」。
- 检查器自身的误报要先修检查器，不在规则集里长期豁免。
- 检查器的输出必须可复跑：失败信息里给出复跑命令。
