# 08 · 静态检查

> 本文件只写规则，与具体工具版本、配置文件路径无关。

## 1. 必须执行的检查

（JAVA-LAYER-003）构建期必须执行下列检查，任一不通过即阻断：

| 检查类       | 覆盖                                                |
|--------------|-----------------------------------------------------|
| 源码风格     | 命名、导入、括号、空白、行长、方法长度              |
| 源码静态分析 | 未使用成员与参数、可疑写法                          |
| 字节码分析   | 空指针、资源泄漏、`equals`/`hashCode`、可疑集合用法 |
| 重复代码     | 片段重复（阈值统一，全库一致）                      |
| 覆盖率       | 语句与分支覆盖达标（见 `06-测试.md`）               |
| 形态约定     | 后缀词表、请求/响应命名、注释禁词、import 分层      |

依据：Google《Software Engineering at Google》第 11 章——确定性执行优先于散文；能机器判定的不得靠人记。

## 2. 阻断与豁免

- 构建期检查失败即阻断构建，不提供「先过再修」的开关。
- 豁免必须逐条、带理由，写在豁免清单里；清单不承载新规则。
- 同一类告警反复出现时，改代码而不是继续加豁免。

## 3. 规则集的位置

- 规则集与豁免清单与代码同仓，随版本一起评审。
- 规则集变更属于规范变更：先说明影响面，再改配置。
- 规则集必须与项目既有代码风格对齐；存量偏离由整改收敛，不为迁就存量放宽规则。

## 4. 与推送门禁的关系

- 推送前执行与构建期相同的检查，范围按改动计算。
- 门禁失败：修到全绿再推；修不动如实报告，禁止绕过。
- 改动只涉及文档或注释时，可跳过编译类检查，但不能跳过注释口径与编码检查。

## 5. 检查器本身的约束

- 每个检查器只判定一类问题，输出「文件:行 规则 说明」。
- 检查器自身的误报要先修检查器，不在规则集里长期豁免。
- 检查器的输出必须可复跑：失败信息里给出复跑命令。
