# 04 · 契约

> 本文件只写规则，与具体类名无关；全局契约（响应外壳、HTTP 状态、错误码、鉴权、限流、分页、ID 序列化、幂等）的规则收在本文件与 `05-异常-日志-事务.md`、`../common/05-安全.md`。项目的契约文档只记录“本项目实际采用了什么、参数是多少、码表是什么”，不重复规则正文。

## 1. 请求与响应

（JAVA-DTO-001）请求对象放 `dto/request/<域>`，响应对象放 `dto/response/<域>`；不得与实体混放。

（JAVA-DTO-006）请求/响应对象只承载字段，不写业务方法、不查库、不做状态判断。

（JAVA-DTO-005）出参字段用具体类型；禁止 `Object`、无约束的 `Map` 作为字段类型。

## 2. 校验

（JAVA-DTO-002）请求体参数一律校验：注解用 `jakarta.validation`，消息用中文。

- 结构校验（非空、长度、格式、范围）写在请求对象上，由入口层触发。
- 业务校验（唯一性、状态、权限）写在用例实现里。
- 内部调用不再重复校验上游已保证的条件。

依据：阿里安全规约第 4 条（强制）；OWASP Input Validation；口径与 `03-反模式.md` 的 `ANTI-02` 一致。

## 3. 分页

（JAVA-DTO-003）分页请求继承统一分页基类，响应返回统一分页结构；参数名固定为 `current` 与 `size`。

- 分页参数必须在服务端做上限约束，不接受无上限的页大小。
- 排序字段必须走白名单，禁止把请求参数直接拼进排序。

依据：阿里安全规约第 4 条（每页数量过大导致内存溢出、恶意排序导致慢查询）。

## 4. 响应形态

（JAVA-DTO-004）返回 JSON 的接口一律用统一响应外壳，不返回框架自带的响应实体，不手动设置 HTTP 状态。返回字节流或文件流的接口用框架响应实体表达响应头，不受本条约束。

- 响应外壳至少包含：状态码、消息、数据。
- 错误语义走响应体的状态码，不靠 HTTP 状态区分。
- 列表与分页必须返回同一结构，前端无需分支处理。
- 二进制接口要带 `Content-Type`、缓存头与验证器（`ETag` 或 `Last-Modified`），由浏览器直接消费，不套 JSON 外壳。

依据：阿里手册没有「接口必须返回统一响应体」的条款，统一外壳是本项目约定，作用于业务数据接口；Spring 参考文档明确 `ResponseEntity<Resource>` 用于文件内容，并示范用 `ResponseEntity.ok().eTag(...)` 表达状态与响应头。

## 5. 全局契约口径

（JAVA-DTO-007）业务接口的 HTTP 状态码恒为 200（网络层故障除外）；业务错误、参数错误、未认证、无权限一律用 200 + 响应体状态码表达。

- 三处出口口径一致：全局异常出口、未认证入口、无权限拒绝处理器；后两者位于 Controller 之前，不经过全局异常出口。
- 不得用 `ResponseEntity.status(...)`、`HttpServletResponse.setStatus(...)` 表达业务失败。
- 二进制/文件流接口不受本条约束，按第 4 节处理。

依据：浏览器会把裸 4xx 渲染成错误页，前端拿不到可判断的业务码；统一出口是本项目决策。

（JAVA-DTO-008）出参 `Long` 按安全整数阈值序列化：超过 `2^53-1` 输出字符串，其余保持数字；请求侧按对应类型反序列化。

- 雪花 ID 一律按字符串下发与回传；计数、字节数、耗时、分页号仍是数字。
- 序列化规则集中在一个配置类，不在字段上逐个加注解。

依据：JavaScript `Number` 的安全整数上限；前端无法可靠比较超界数字。

（JAVA-DTO-009）提交类写接口用幂等键（`requestId`）防重放：一次提交一个值，同一次提交的重试沿用，换一次提交换新值。

- 幂等键只表达“同一次提交”，不得用文件名、大小、修改时间等业务指纹代替。
- 缺失幂等键返回登记的业务错误码；重放返回首次结果，不重复落库。
- 并发撞唯一键时转为回放，不向上抛系统异常。

依据：OWASP 幂等与重放防护；`../common/05-安全.md` 的 `COMMON-SEC-07`。

（JAVA-DTO-010）数据形态统一：主键由应用生成（雪花 + 显式插入）；公共字段按表的生命周期分档启用，不一律铺满；删除方式与表的行为一致。

三档（按该表有没有删除、更新、人为操作判定）：

| 档               | 判定                       | 公共字段                             | 载体                                |
|------------------|----------------------------|--------------------------------------|-------------------------------------|
| 完整             | 有删除、有更新、有人为操作 | 删除标记 + 创建人/时间 + 更新人/时间 | 完整基类（逻辑删除注解 + 自动填充） |
| 只追加且有操作人 | 不删除、不更新，由人创建   | 创建人 + 创建时间                    | 轻量创建基类                        |
| 只追加的系统记录 | 不删除、不更新，由系统生成 | 仅创建时间                           | 单一创建时间字段，不建基类          |

- 基类引入的列必须是表里真实存在的列；表里没有的列不得由基类带入——否则查询与插入会带上不存在的列而失败。
- 表里已有的公共列必须被实体映射并由统一机制维护，不留“有列无字段”的死列。
- 只有存在删除行为的表才用逻辑删除（统一码值枚举 + 逻辑删除注解）。只追加表不设删除标记；确有回收动作时物理删除，但必须有业务前置校验并写审计。
- 只有存在更新行为的表才需要更新人/时间；业务时间列（开始/结束、发布/退役等）比通用更新时间更精确时以它为准，不重复记。
- 公共字段由统一填充器维护；未用基类、只记创建时间的表允许由数据库默认值写入。
- 业务代码不写码值字面量，码值口径见 `JAVA-DTO-011`。

依据：MyBatis-Plus 官方文档（逻辑删除、自动填充、主键策略）；「按行为分档」是本项目决策——一律铺满会给只追加表带上永不使用的删除标记与更新人，而逻辑删除会让已删行继续占用唯一键，删后重建同名记录会插入失败。

（JAVA-DTO-011）码值走枚举：状态、角色、类型等码值只在枚举里定义一处；解析未知码时，写路径抛业务错误码，读路径取最保守语义。

依据：码值散落会导致同一状态在不同入口判定不一致。

（JAVA-DTO-012）二进制资源（头像、图片、视频）存对象存储；应用层只下发对象 URL，不提供字节代理或资源读取接口。

- 公开读范围必须按前缀收窄（如 `avatar/*`），同桶的其余对象保持私有；URL 不带凭据。
- 资源 URL 直接交给浏览器/CDN，缓存头由对象存储/CDN 控制；应用层不再转发图片/视频字节。
- 本地磁盘等没有公开读能力的后端，写路径直接拒绝并提示切换对象存储，不落不可渲染的地址。
- 资源不存在由对象存储返回 `404`；这类接口不属于 JSON 业务接口，不参与「业务接口 HTTP 恒 200」口径。

依据：对象存储官方文档（桶策略、公开读前缀、CDN 直出）；应用服务代理图片/视频会占用带宽与连接，且拿不到 CDN 的边缘缓存。

## 6. 契约变更

- 字段改名、类型变更、错误码调整属于契约变更：先改契约文档，再改实现，最后同步使用方。
- 删除字段前先确认没有使用方；对外契约只增不删，废弃字段标为忽略并保留一个版本。
