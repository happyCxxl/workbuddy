# 06 · 测试（Java）

> 跨语言原则（规模、金字塔、AIR、替身、覆盖率、必测四类）见 `../common/04-测试策略.md`；本文件只写 Java 落地规则。

## 1. 命名与位置

（JAVA-TEST-001）含测试方法的类以 `Test` 结尾，与被测类同包同模块：`Xxx` 对应 `XxxTest`。

- 测试代码只放 `src/test/java`，不放业务目录。
- 测试方法名描述「场景 + 条件 + 预期」，与 `given / when / then` 三段对应。
- 测试支撑类（夹具、构造器、替身工具）不含测试方法，集中在测试支撑包，命名体现用途，不受 `Test` 后缀约束。

依据：JUnit 5 User Guide 把测试类定义为含 `@Test` 系注解的类；Maven Surefire 默认 includes 只覆盖会被执行的类，不覆盖支撑类。

## 2. 单测与集成测试

（JAVA-TEST-002）单测默认不启动容器、不连中间件；只有需要真实容器或跨 Bean 协作时才写集成测试。

（JAVA-TEST-003）集成测试打标签，与单测分开执行，不进推送门禁的默认步骤。

依据：阿里《单元测试》第 1–4 条（AIR：自动化、独立、可重复）。

## 3. 断言

- 断言错误码而不是错误消息文案（文案会调整）。
- 一个测试只断言一件事；断言多段时按段注释。
- 不写 `assertTrue(true)` 之类的占位断言。
- 断言针对可观察结果，不断言内部调用顺序。

## 4. 测试替身

通用口径（替换优先级、只在系统边界替换、不得只验交互）见 `../common/04-测试策略.md` 的 COMMON-TEST-05/06。Java 侧只补充两条：

- 值对象、纯函数、静态工具不 mock；
- `@Mock` 数量超过 5 个按职责过载信号处理（`JAVA-TEST-011`）。

## 5. 禁止项

（JAVA-TEST-005）禁止下列写法：

- 依赖执行顺序的测试（共享静态状态、依赖前一个测试造的数据）。
- 用固定时长休眠等待异步结果；改为轮询断言加超时上限。
- 访问真实外网、对象存储桶、生产库。
- 断言日志输出。
- 在测试里读本地绝对路径。

## 6. 文件规模

（JAVA-TEST-006）单个测试文件超过 400 行属于结构信号，评审时须论证是否该按场景抽共享夹具；不以拆分文件凑数。等级【应该】。

## 7. 验证档位

（JAVA-TEST-007）开发期按改动范围选档，推送前一律全量：

| 改动                 | 验证                        |
|----------------------|-----------------------------|
| 文档、注释、规范     | Javadoc、文档结构、编码、规范边界与入口指针检查 |
| 单个模块的类         | 该模块的测试                |
| 公共模块或跨模块     | 依赖链测试                  |
| 构建文件、跨模块重构 | 全量测试                    |

拿不准时取更全的一档。档位之间的升降时机、失败重跑与超时处置见 `../common/08-验证节奏.md`。

## 8. 集成测试的补充节奏

（JAVA-TEST-008）每新增一类基础设施依赖，同步补一条覆盖该依赖的集成测试；起点是启动校验、事务边界、任务链路三类。

## 9. 覆盖率

（JAVA-TEST-009）用 JaCoCo 统计覆盖率，分母口径与门槛见 `../common/04-测试策略.md` 的 COMMON-TEST-07。落地要求：

- 打开 Lombok 的生成标记（`lombok.config` 里 `lombok.addLombokGeneratedAnnotation = true`），使生成方法不被计入分母。
- 数据载体包（`dto`）在构建文件的覆盖率插件配置里排除，前提是它满足 `02-包结构.md` 的 JAVA-LAYER-007；领域规则与枚举码值解析仍在分母内。
- 语句覆盖由 `mvn verify` 阻断：全库 70%，核心链路所在模块 90%。
- 关键分支 100% 是评审口径，按 COMMON-TEST-07 的四类逐条核对，不靠百分比代替。

- 覆盖率不足时补测试，不得为凑数字写「调用即通过」的测试，也不得改断言迁就实现。

## 10. 推送前

（JAVA-TEST-010）推送前跑全量测试，不通过不推送。

## 11. 用例质量

（JAVA-TEST-011）落地 `../common/04-测试策略.md` 的 COMMON-TEST-11 至 14：

- 用例类 Javadoc 写明守护的规则编号（如 `JAVA-ERR-002`）或错误码；用例方法 Javadoc 写明该用例在什么改动下会失败。
- 核心链路模块（`biz`、`worker`）在 `verify` 里跑变异检查（PIT）：存活的变异逐条评估，补用例或说明「不改行为」。
- 静态扫描 `check-test-quality` 拦恒真断言、无断言用例、只有交互验证的用例、缺来源说明的用例；mock 数量超过 5 个按职责过载信号提示，不阻断。
