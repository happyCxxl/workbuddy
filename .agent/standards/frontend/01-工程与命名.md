# 01 · 工程与命名

> 编号见 `00-规则索引.md` §6.2–§6.3；本文只写条款正文与正反例。

## 1. 目录与文件

工程目录为仓库根的 `web/`，与后端 Maven 模块平级。

```
web/
├── public/            静态资源，原样拷进产物
├── src/
│   ├── api/           接口层，一控制器一文件
│   ├── assets/        经构建处理的资源
│   ├── components/    可复用组件，按领域分目录
│   ├── composables/   组合式逻辑复用
│   ├── layouts/       布局
│   ├── router/        路由与守卫
│   ├── stores/        全局状态
│   ├── styles/        全局样式与设计变量
│   ├── types/         与后端 DTO 对齐的类型
│   ├── utils/         不依赖框架的纯函数
│   └── views/         页面，一页一目录
└── package.json
```

（WEB-DIR-001）`views/` 一页一目录，目录名与路由 path 一致：`views/knowledge-base/` 对应 `/knowledge-base`。

（WEB-DIR-002）`components/` 按领域分目录，目录名 kebab-case。现有领域：`knowledge-base/`、`pipeline/`、`strategy/`；跨领域通用组件放 `common/`。

## 2. 接口层

（WEB-API-001）所有 HTTP 调用只允许出现在 `api/` 目录内，页面与组件不直接写请求。

（WEB-API-002）每个接口函数返回类型显式声明，禁止 `any`。

（WEB-API-003）请求参数与响应结构以后端 Controller 源码为单一事实源（`@RequestMapping`、方法签名、`workbuddy-common` 的 `dto/request` 与 `dto/response`）。字段改名先改后端，再同步 `types/`。

（WEB-API-004）`api/` 文件与后端控制器同名映射：`ModelController` → `api/model.ts`。

（WEB-API-005）后端雪花 ID 一律按字符串处理（后端超过 `2^53-1` 的整数序列化为字符串）。

（WEB-API-006）分页请求固定 `current`（从 1 起）与 `size`；响应只取 `records`、`total`、`size`、`current` 四个字段，其余不得依赖。

（WEB-API-007）时间字段按后端 ISO 格式接收，展示统一经 `utils/` 时间工具格式化为 `yyyy-MM-dd HH:mm:ss`，禁止散落 `new Date(...).toLocaleString()`。

正例：

```ts
export function fetchModels(query: ModelQuery): Promise<PageResult<ModelItem>> {
  return http.get('/model/page', { params: query })
}
```

反例：页面里直接写请求，返回类型缺失。

```ts
// 页面组件内
const res = await axios.get('/model/page')   // 越过 api/，且 res 无类型
```

## 3. 命名

（WEB-NAME-001）变量、函数、参数 lowerCamelCase；常量 UPPER_SNAKE_CASE；类与组件 PascalCase。

（WEB-NAME-002）方法名是动词或动词加名词；增删改查统一用 `add` / `update` / `delete` / `get` / `detail` 五个词。这是本项目的取词约定，与后端 DTO 的动作词对应关系：`add` ↔ `Create`、`update` ↔ `Update`、`get`/`detail` ↔ `Query`/详情、`delete` ↔ 删除接口。

（WEB-NAME-003）禁拼音、拼音英文混用、中文命名；禁随意缩写（`condi`、`absCls`），用完整英文单词。

（WEB-NAME-004）布尔以 `is` / `has` / `can` / `should` 开头；集合用复数或 `List` 后缀；事件回调以 `on` / `handle` 开头。

（WEB-NAME-005）循环、条件、三目嵌套不超过 3 层，超出抽函数。

【应该】函数只做一件事，超过约 50 行拆解；参数超过 3 个改传对象。【应该】`console.log` 不得提交。

## 4. 代码风格

格式类条款不逐条编号，统一由工具强制（WEB-MACHINE-001）：缩进 2 空格、行尾分号、单引号、大括号、字面量、`const` 优先、禁 `for...in`、空行分隔。

（WEB-STYLE-001）一律用 `===` 与 `!==`；与 `null`/`undefined` 比较时可用 `== null`（同时覆盖两者）。这是 Google TS 的口径，比逐字判断 `undefined` 更不易错。

（WEB-LANG-001）通用语言约定按 Google TS 执行：只用命名导出、禁 `default export`；禁 `namespace` 与 `require`；类型断言只用 `as`；非空断言 `!` 必须写明理由；`switch` 必须带 `default`；空 `catch` 必须写注释。

## 5. 注释

（WEB-DOC-001）注释只写做什么（职责与行为），不写谁写的、缘由、来历、阶段与编号，也不记变更过程。

（WEB-DOC-002）组件 props、接口层函数、工具函数的公共入口必须有职责一句话注释。

【应该】复杂算法的关键步骤与易踩坑处补注释；注释与代码同步更新，不保留过期注释。
