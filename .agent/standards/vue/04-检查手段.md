# 04 · 检查手段

> 本文件只写规则，与具体工具版本、脚本名称无关。

## 1. 必须有的检查

前端构建期必须执行下列检查，任一不通过即阻断：

| 检查类     | 覆盖                                       |
|------------|--------------------------------------------|
| 格式化     | 缩进、引号、分号、行宽、文件末尾换行       |
| 静态 lint  | 语言规则、框架规则、可访问性规则           |
| 类型检查   | 全量类型检查，禁止 `any` 逃逸              |
| 命名与结构 | 目录与文件命名、页面与路由一致、接口层唯一 |
| 组件口径   | 组件命名、样式隔离、单文件块顺序           |
| 样式口径   | 禁 `:deep`、字体栈、小数 px、未使用类名    |
| 表格口径   | 骨架类、列宽、列对齐                       |

依据：Google《Software Engineering at Google》第 11 章——确定性执行优先于散文；能机器判定的不得靠人记。

## 2. 阻断与豁免

- 检查失败即阻断构建，不提供「先过再修」的开关。
- 不设行内豁免与豁免清单；判定不适用时改规则，不在代码里打标记。
- 同一类告警反复出现时，改代码而不是放宽检查。

## 3. 规则集的位置

- 规则集与豁免清单与代码同仓，随版本一起评审。
- 规则集变更属于规范变更：先说明影响面，再改配置。
- 规则集必须与既有代码风格对齐；存量偏离由整改收敛，不为迁就存量放宽规则。

## 4. 与门禁的关系

- 提交前只做就地修复，保证提交不被格式问题卡住。
- 推送前做全量校验，范围按改动计算。
- 门禁失败：修到全绿再推；修不动如实报告，禁止绕过。

## 5. 检查器本身的约束

- 每个检查器只判定一类问题，输出「文件:行 规则 说明」。
- 检查器的误报先修检查器，不在规则集里长期豁免。
- 失败信息必须给出复跑命令。
- 前端检查不重复后端已覆盖的检查（Javadoc 只对 Java 生效；Vue 注释按 `01-工程与命名.md` §5 评审）。
