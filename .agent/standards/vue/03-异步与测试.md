# 03 · 路由、异步与工程化

> 本文件只写规则，与具体路由表、具体状态库无关。

## 1. 路由与状态

（VUE-ROUTE-001）路由一律懒加载，首屏不打包非首屏页面。

（VUE-ROUTE-002）path 用 kebab-case 且以 `/` 开头；路由 name 与页面组件名一致。

（VUE-ROUTE-003）页面之间传参用路由参数，禁止借全局状态中转。

（VUE-ROUTE-004）全局状态只放跨页面共享的数据；页面私有状态留在页面内。

（VUE-ROUTE-005）状态变更一律经统一入口（actions），组件不直接改状态字段。

（VUE-ROUTE-006）路由守卫统一处理登录态：未登录访问受保护页跳登录并携带站内回跳参数；已登录访问登录页回首页；无权限访问管理页回首页。回跳参数只接受以单个 `/` 开头且不以 `//` 开头的站内路径。

（VUE-ROUTE-007）菜单可见性与路由可见性必须同源：同一管理页的菜单声明与路由元信息两处同步修改，不得只改一处。

（VUE-ROUTE-008）侧栏菜单最多两级：没有二级项为叶子项，有二级项为分组；下钻页不单独占菜单项，归入所属二级项点亮。

依据：Vue Router 官方守卫文档；开放重定向与菜单越权的常见成因是“两处声明不同步”。

依据：Vue 官方风格指南；状态库官方建议——变更集中、可追踪。

## 2. 异步与错误处理

（VUE-ASYNC-001）异步统一用 `async/await`，不混用回调与 Promise 链。

（VUE-ASYNC-002）请求层统一拦截：超时、鉴权失效、服务端错误在一处处理，页面只处理成功分支。

（VUE-ASYNC-003）页面数据展示必须覆盖三态：加载中、空数据、异常。

（VUE-ASYNC-004）用户可见的写操作必须带二次确认与结果提示。

【应该】并发请求需要取消的，用请求取消机制而不是忽略返回值。【应该】高频输入触发请求时做防抖或节流。

## 3. 工程化

（VUE-ENG-001）Lint 与格式化规则全库统一，禁止个人改规则绕过检查。

（VUE-ENG-002）门禁两段：提交时就地修复，推送时全量校验。

（VUE-ENG-003）提交信息用 Conventional Commits，scope 与模块对应。

（VUE-ENG-004）运行时与包管理器版本钉住，保证本地与流水线一致。

（VUE-ENG-005）构建产物、依赖目录、编辑器文件进忽略清单。

（VUE-ENG-006）新增依赖最小化，引入新库必须写明理由与替代方案。

（VUE-ENG-007）新增后端接口前缀时同步更新开发代理配置；漏加时代理不生效、请求落到单页回退，控制台不报错。

依据：Vite 代理配置按前缀匹配；本项目 `/home`、`/user`、`/model` 同时是路由与接口前缀，靠请求头分流。工程门禁的依据：本项目决策——单人开发、无人工评审，门禁是唯一的强制层（与 `../common/06-协作流程.md` §2 一致）。
