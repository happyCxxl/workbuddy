# 01 · 工程与命名

> 本文件只写规则，与具体目录名、具体业务无关。

| 小节       | 判定            | 具体怎么判                                                                  |
|------------|-----------------|-----------------------------------------------------------------------------|
| 1 目录     | 形态检查 + 评审 | 目录命名由 ls-lint 判；「一页一目录」「按领域分目录」靠评审                 |
| 2 接口层   | 类型检查 + 评审 | 返回类型与 any 由 vue-tsc 判；请求只出现在接口层靠评审                      |
| 3 命名     | 工具 + 评审     | 大小写与嵌套层数由 eslint 强制（camelcase 格式、max-depth）；语义取词靠评审 |
| 4 代码风格 | 工具 + 评审      | prettier 强制格式；LANG-001 的导出/namespace/require/类型断言/switch default 等子条款当前无 eslint 对应规则，靠评审；VUE-MACHINE-001 是「不逐条立规」的元规则 |
| 5 注释     | 评审            | 职责一句话无法机器判定                                                      |

## 1. 目录

（VUE-DIR-001）页面一页一目录，目录名与路由 path 一致。

（VUE-DIR-002）可复用组件按领域分目录，目录名 kebab-case；跨领域通用组件放统一目录。

其它规则：

- 目录按**职责**组织：页面、组件、接口、状态、路由、样式、工具各自独立，不按业务把所有东西塞进一个目录。
- 资源分两类：经构建处理的放资源目录，原样拷贝的放静态目录。
- 类型定义与后端契约对齐，单独成目录，不散落在页面里。

## 2. 接口层

（VUE-API-001）所有 HTTP 调用只允许出现在接口层目录内，页面与组件不直接写请求。

（VUE-API-002）每个接口函数显式声明返回类型，禁止 `any`。

（VUE-API-003）请求参数与响应结构以后端契约为单一事实源；字段改名先改后端，再同步前端类型。

（VUE-API-004）接口文件与后端控制器一一对应。

（VUE-API-005）超出安全整数范围的 ID（如长整型雪花 ID）一律按字符串处理。

（VUE-API-006）分页请求参数与响应字段固定，前端不依赖额外字段。

（VUE-API-007）时间字段按后端格式接收，展示统一经时间工具格式化，禁止就地调用本地化方法。

（VUE-API-008）全站只有一个 HTTP 实例，基地址、超时、令牌注入、响应解包与错误提示集中在请求层；页面与组件不直接使用该实例。

- 业务域接口按领域薄封装，页面只调领域函数。
- 令牌存储键与读取顺序由请求层统一，不在页面里读写存储。

（VUE-API-009）响应拦截统一解包：成功取业务数据并返回给页面；鉴权失效清令牌并携站内回跳参数跳登录；其他业务失败提示服务端消息；网络错误统一提示。

- 页面只处理成功分支，失败提示不由页面重复实现。
- 跳转参数必须校验为站内路径，防止开放重定向。

正例：接口层函数带返回类型。

```ts
export function fetchList(query: ListQuery): Promise<PageResult<ListItem>> {
  return http.get('/list', { params: query })
}
```

反例：页面内直接发请求，且返回值无类型。

```ts
const res = await axios.get('/list')
```

## 3. 命名

（VUE-NAME-001）变量、函数、参数小驼峰；常量全大写下划线；类与组件大驼峰。

（VUE-NAME-002）方法名用动词或动词加名词；增删改查的取词全库统一。

（VUE-NAME-003）禁拼音、中英混拼、中文命名与随意缩写，用完整英文单词。

（VUE-NAME-004）布尔以 `is` / `has` / `can` / `should` 开头；集合用复数；事件回调以 `on` / `handle` 开头。

（VUE-NAME-005）循环、条件、三目嵌套不超过 3 层，超出抽函数。

【应该】函数只做一件事，过长时拆解；参数超过 3 个改传对象；调试输出不得提交。

## 4. 代码风格

（VUE-MACHINE-001）格式类规则由格式化器与 lint 工具强制，不逐条写进规范、不靠人工检查。边界：stylelint 放行 Element Plus 内部 BEM 类名（`__`/`--` 形状），本项目语义类名仍为 kebab-case——放行理由为覆盖其 type 级禁用底色必须允许该第三方前缀形状。

（VUE-STYLE-001）一律用 `===` 与 `!==`；与空值比较时可用 `== null`，同时覆盖 `null` 与 `undefined`。

（VUE-LANG-001）通用语言约定按 Google TS：只用命名导出、禁 `default export`；禁 `namespace` 与 `require`；类型断言只用 `as`；非空断言必须写明理由；`switch` 必须带 `default`；空 `catch` 必须写注释。边界：构建/格式化/lint 等工具配置文件（如 `vite.config.ts`、`eslint.config.mjs`、`stylelint.config.mjs`）不受「只用命名导出」约束，理由由工具约定给出。

依据：Google TypeScript Style Guide；Vue 官方风格指南。

## 5. 注释

（VUE-DOC-001）注释只写做什么（职责与行为），不写谁写的、缘由、来历、阶段与编号，也不记变更过程。

（VUE-DOC-002）组件 props、接口函数、工具函数的公共入口必须有职责一句话注释。

【应该】复杂步骤与易踩坑处补注释；注释与代码同步更新，不保留过期注释。
