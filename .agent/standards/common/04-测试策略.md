# 04 · 测试策略

> 跨语言部分：测试分层、验证时机、必测口径。语言细节见 `java/06-测试.md`、`vue/03-异步与测试.md`。
> 编号 `COMMON-TEST-xx`。

## 1. 分层

（COMMON-TEST-01）只做三层，且默认层最重：

| 层       | 范围                               | 何时跑                 |
|----------|------------------------------------|------------------------|
| 单元测试 | 单个类/函数，不启容器、不连库      | 开发中随时，推送前全量 |
| 集成测试 | 跨层、连真实中间件，只覆盖关键路径 | 推送前可选，CI         |
| 端到端   | 浏览器/全链路                      | 不做                   |

- 端到端不做的理由：单人开发维护不起；三态与交互由页面自查替代。
- 集成测试只覆盖「mock 测不出来」的地方：事务、SQL、序列化、任务链路。

## 2. 验证阶梯

（COMMON-TEST-02）按改动范围选档，推送前一律全量：

| 改动                 | 验证               |
|----------------------|--------------------|
| 文档、注释、规范     | 注释口径与编码检查 |
| 前端                 | `pnpm lint`        |
| 单个模块的类         | 该模块的测试       |
| 公共模块或跨模块     | 依赖链测试         |
| 构建文件、跨模块重构 | 全量测试           |

拿不准时取更全的一档（`COMMON-AI-06`）。

## 3. 测试替身

（COMMON-TEST-03）优先级：**真实实现 > fake（内存实现）> stub > mock**（Google 口径）。

| 依赖                                  | 做法                                     |
|---------------------------------------|------------------------------------------|
| 纯逻辑、值对象                        | 真实对象                                 |
| 数据库                                | 集成测试连真实库；单测可 mock 数据访问层 |
| 外部 HTTP、模型调用、对象存储、向量库 | mock                                     |
| 时间、随机数、当前用户                | 注入或 mock                              |

（COMMON-TEST-04）禁止把被测逻辑的核心依赖 mock 掉，只留下一串 `verify`。这样的测试证明的是「调用顺序」，不是「行为正确」。

## 4. 必测口径

（COMMON-TEST-05）下列五类必须有用例，缺一即视为未完成：

1. 每个新增或修改的错误码分支。
2. 边界值：空、零、超长、超大页码、空集合。
3. 幂等路径：同键重复到达返回首次结果。
4. 状态机的非法迁移。
5. 事务或并发不可测的部分，在测试注释里写明「不覆盖」与由哪一层保证。

## 5. 不追求的东西

（COMMON-TEST-06）不设覆盖率数字门槛。覆盖率可以造假，关键路径不能。

（COMMON-TEST-07）不为凑覆盖率写「调用即通过」的测试；不为让测试变绿而改断言。

## 6. 测试与重构的关系

（COMMON-TEST-08）测试是重构的安全网：没有测试覆盖的行为，不得重构其结构。

- 顺序：先补测试锁住行为，再改结构，再确认测试仍绿。
- 缺少安全网时，优先补测试，而不是直接改。
