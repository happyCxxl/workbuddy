# 03 · 反模式

> 代码的负面清单：不该出现的写法。每条写：表现、根因、依据、正确做法、判定。
> 只收**没有正面规则覆盖**的反模式。已有规则覆盖的（注释、命名后缀、最小改动、验证闭环、如实报告、成功路径），由该规则管，本文件不重复。
> 编号 `COMMON-ANTI-xx`。

## 1. 过度抽象 

（COMMON-ANTI-01）

- 表现：抽象出来之后，没有任何实现点或配置点被真正使用；单一实现也抽接口、工厂、策略；基类只有一个空方法。
- 根因：抽象的价值来自消除重复与隔离变化；没有第二个使用者时，两者都不存在，只剩一层跳转。
- 依据：Google《What to look for in a code review》Complexity 维度点名 over-engineering——把代码做得比需要的更通用，或加了当下并不需要的功能；Fowler 的 Speculative Generality 坏味道与 Rule of Three——同类抽象出现第三次才抽。
- 判据（三问都答不出来即为过度抽象）：
  1. 第二个实现者是谁？能说出具体角色吗（外部插件方、下个迭代要做的某个域、框架强制）？
  2. 它的时间定了吗（本迭代 / 下迭代），还是「将来可能」？
  3. 不提前抽，事后补的代价是否不可接受（已发布契约、影响外部系统）？
- 例外：扩展点本身就是产品需求（插件体系、对外 SPI、框架要求的接口），不受本条约束，但须写明谁来实现、何时实现。
- 正确：三问答不出来，就直接写具体实现，出现第二个实现再抽。
- 判定：评审时按三问逐条回答，答不完整即视为过度抽象。

## 2. 防御性冗余

（COMMON-ANTI-02）

- 表现：同一条件在 DTO、Controller、Service、数据访问层重复校验；已判空后内部再判；内部方法的运行时校验重复挡外部已经挡过的输入。
- 根因：校验点分散后，说不清哪一层对哪条负责；改动时不知道改哪处；重复校验还会掩盖契约本身的缺失。
- 依据：OWASP 输入校验清单——在信任边界校验，并把「信任内部来源」列为常见误区（内部传输不等于满足接收方规则）；Oracle《Programming With Assertions》——公有方法的参数校验用明确异常，内部不变量才用 `assert`，且断言默认关闭、仅在显式开启时生效。
- 正确：边界（对外接口）显式校验并抛明确异常，Java 入参用 `@Valid`；内部依赖上游契约，不再重复运行时校验；内部不变量由测试保证，不用 `assert` 承担生产期防御；确需运行期防御的，只在真正的信任边界上加一次。
- 判定：同一条件在两个层次出现即违规；评审。

## 3. 复制粘贴

（COMMON-ANTI-03）

- 表现：同一逻辑在多个类里各写一遍，只改变量名。
- 根因：一处修改要同步 N 处，漏一处就是缺陷；复制品还会各自演化，逐渐产生细微差异。
- 依据：DRY 原则（Hunt & Thomas, The Pragmatic Programmer）；AI 生成代码的复用率低于人工（More Code, Less Reuse, 2026）。
- 正确：第二处出现即抽公共；抽不动说明职责划分有问题。
- 判定：CPD（45 tokens）。

## 4. 隐藏副作用

（COMMON-ANTI-04）

- 表现：构造方法里发请求或写库；getter/setter 里改状态或做条件运算；`toString()` 触发 IO。
- 根因：外部无法从签名判断代价与顺序，一次「读」可能触发写；测试也必须准备真实依赖。
- 依据：阿里手册 OOP 规约第 11 条（强制：构造方法禁止业务逻辑）、第 16 条（getter/setter 不加业务逻辑）；命令查询分离原则——查询不得改变可观察状态。
- 正确：构造函数只赋值；getter/setter 只读写字段；需要初始化就提供显式的 `init` / `load` 方法，并在命名上体现。
- 判定：评审。

## 5. 判空写法散落

（COMMON-ANTI-05）

- 表现：同一仓库里混用裸 `== null` / `!= null`、直接调用工具类的判空方法、以及项目封装的判空方法；静态分析因此对“被证明为 null”的判空报空指针类误报。
- 根因：判空没有单一入口，参数可空性也没有注解可依；工具类判空方法的参数未标注可空，静态分析无法区分“有意判空”与“空指针风险”。
- 依据：SpotBugs `NP_NONNULL_PARAM_VIOLATION` / `NP_LOAD_OF_KNOWN_NULL_VALUE` 的触发条件；OWASP 输入校验（边界判空一次）。
- 正确：判空统一走项目封装的判空工具（参数标注可空，内部转发 Hutool）；不写裸 `== null`，也不直接调用 Hutool 判空；其它空集合/空串语义按原工具使用。
- 判定：评审 + 静态分析；静态分析豁免清单不接受为这类告警新增例外，撞上就改写判空。
