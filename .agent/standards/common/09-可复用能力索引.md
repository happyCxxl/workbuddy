# 09 · 可复用能力索引

> 本文件规定「动手实现一个能力之前，怎么确认它已经存在」。检索动作与证据要求见 `02-交付行为约束.md` 的 COMMON-WORK-03；重复实现与抽象时机的判定见 `03-反模式.md`；本文件只管**索引这个落点**怎么建、收什么、放哪里。
> 编号 `COMMON-REUSE-xx`。

## 1. 为什么要有索引

（COMMON-REUSE-01）项目必须维护一份可复用能力索引，记录横切能力的入口位置。等级【应该】。

- 问题：通用能力散落各模块的工具类与支撑类里，只有翻过的人知道它存在；新会话的默认动作是"没写过就新建"，于是同一语义出现第二、第三份实现，各自演化。
- 行业：成熟仓库把「能力地图」当作入口文档的一部分（工程手册、服务目录、内部 wiki 的 capability map）——入口文件只放难以自行发现的信息，"某个能力在哪"正是这类信息。
- 我们：按能力查，不按文件名猜；索引是检索的落点，不是文档的全部。
- 判定：评审；索引缺失、或记录的入口已失效，视为未满足 COMMON-WORK-03。

## 2. 收什么

（COMMON-REUSE-02）只收**横切能力**：有明确入口、预期被两个以上业务方使用的通用实现。只被一处使用、或属于某个领域内部的实现，不进索引。等级【应该】。

能力分类（项目按自身技术栈取舍，不在的分类写「无」）：

| 分类             | 典型内容                             |
|------------------|--------------------------------------|
| 空值与默认值     | 判空、默认值、空集合语义             |
| 统一响应与错误码 | 响应包装、错误码登记、异常抛出       |
| 查询与分页       | 分页请求对象、查询条件收口           |
| 对象映射         | 实体 / 入参 / 出参之间的转换         |
| 持久化基类       | 公共字段、逻辑删除、自动填充         |
| 外部系统适配     | 存储、消息、向量库、模型调用的接入口 |
| 访问控制         | 限流、认证注解、权限判定             |
| 启动期校验       | 启动自检、装配校验                   |
| 序列化与标识     | 大整数序列化口径、主键生成           |
| 任务与异步       | 任务触发、幂等键、执行键             |
| 配置绑定         | 配置属性类与默认值                   |
| 日志与审计       | 操作审计、链路标识                   |

- 问题：按类名全量清点会变成第二份事实源，随代码漂移，检索价值反而下降。
- 行业：能力地图只收"入口"，细节留在代码与注释里。
- 我们：只收入口，不抄用法全文。
- 判定：评审——收了领域内部实现即为过宽。

## 3. 格式

（COMMON-REUSE-03）每行三列：**能力 | 入口 | 何时先想到它**。入口写符号（包路径或类全名），不写行号；同一能力有多个入口时分行。等级【必须】。

- 问题：写 `文件:行号` 会随改动失效；写"某处"不可检索。
- 行业：文档指向符号而不是坐标，是长期可维护文档的通行做法。
- 我们：符号名稳定，行号不稳定。
- 判定：文档引用检查（路径有效）+ 评审。

## 4. 放在哪

（COMMON-REUSE-04）索引正文属于**项目事实**，放在项目的事实层（项目档案或契约文档），由项目入口指向。本规范只定格式、分类与维护触发，不记录任何项目的类名、模块名或路径。等级【必须】。

- 问题：把类名写进规范，规范就不能跨项目复用；项目改名或重构后还会静默失效。
- 行业：规则与事实分离——规则可移植，事实随项目刷新。
- 我们：规范给槽位与格式，项目填内容；二者单向引用：项目引用规范，规范不引用项目。
- 判定：规范自包含检查（COMMON-WORK-13）。

## 5. 维护触发

（COMMON-REUSE-05）新增、迁移或废弃横切能力时，同一次提交更新索引。等级【必须】。

- 问题：索引落后于代码后，检索会指向已删的东西，比没有索引更误导。
- 我们：能进门禁的部分（路径有效）由文档检查兜底；条目增删靠评审。
- 判定：文档引用检查 + 评审。
