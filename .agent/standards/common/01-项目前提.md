# 01 · 项目前提

> 本文件给出术语、适用范围与约束，再由约束推出规则（`COMMON-PROJ-xx`）。
> 约束只写「只允许什么」与「变更须先改这里」，不描述此刻的代码形态。

## 1. 术语

| 词     | 含义                                                   |
|--------|--------------------------------------------------------|
| 功能域 | 可独立演进、对外只暴露契约的业务能力                   |
| 模块   | 编译与部署的最小代码单元                               |
| 契约   | 对外承诺的接口与数据形态；实现细节与内部结构不属于契约 |

## 2. 适用范围

1. 本规范约束仓库内的全部代码，以及后续接入的任何功能域与语言。
2. 新功能域在写下第一行代码之前即受本规范约束，不因尚未实现而缩小适用范围。
3. 业务规则、产品设计与运维操作不在本规范范围内，由项目的文档与部署编排承担。

## 3. 约束

| 维度       | 只允许                                            | 变更条件                                             |
|------------|---------------------------------------------------|------------------------------------------------------|
| 后端技术栈 | Java 21、Spring Boot 3.2.5、Maven 多模块          | 换版本或换框架，先修订本行并写明迁移方案             |
| 前端技术栈 | Vue 3、TypeScript、Vite、Element Plus；不使用 JSX | 同上                                                 |
| 存储       | MySQL、Redis、MinIO、Milvus                       | 新增存储，先修订本行                                 |
| 部署形态   | 单体多模块：一个进程、一个 MySQL、一个 Redis      | 拆服务、换队列、改调度语义，先修订本行与 `java/01`   |
| 模块划分   | 见项目的模块清单与依赖白名单                      | 增减模块，先改清单                                   |
| 评审形态   | 没有人工代码评审                                  | 引入评审后，可把部分【必须】改为评审判定，先修订本行 |

## 4. 取舍顺序

规则冲突时按此顺序取舍：

| 优先级 | 目标   | 含义                                           |
|--------|--------|------------------------------------------------|
| 1      | 可维护 | 改一个需求只动该动的地方；新人/AI 能按规范读懂 |
| 2      | 可扩展 | 新功能域、新语言、新存储能接进来而不改老代码   |
| 3      | 可读   | 名字表达意图，结构反映职责，注释只补信息       |
| 4      | 一致   | 同类问题全库只有一种写法                       |

## 5. 规则

（COMMON-PROJ-01）**功能域之间只共享契约**，不得直接调用彼此的域内实现。等级【必须】；判定：`java/01-分层与依赖.md` 的依赖白名单 + `.agent/tools/check-modules.mjs`。

（COMMON-PROJ-02）**不新增第三方依赖**：能用现有依赖解决的禁止引新库；任务明确要求引入时，在交付说明写明理由与替代方案。等级【必须】；判定：评审。

（COMMON-PROJ-03）**约束变更与代码同一次提交**：§3 任一行被改动时，同一次提交内更新受影响文档（如 `java/01`、`00-索引.md`）。等级【必须】；判定：评审。

（COMMON-PROJ-04）**接入新语言必须满足四件事**：建独立规范目录与语言前缀、在 `00-索引.md` 登记、接入 pre-push 与 CI、跨语言条款放 `common/`。等级【必须】；判定：评审 + 目录一致性检查（后续）。步骤见 `06-协作流程.md` §7。

（COMMON-PROJ-05）**一切产出以仓库为准**：口头结论、会话记忆、外部聊天记录都不算数，结论落到文档或代码。等级【应该】；判定：评审。

（COMMON-PROJ-06）**规则冲突按 §4 的取舍顺序判定**。等级【应该】；判定：评审。
