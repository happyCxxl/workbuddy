# 05 · 安全

> 跨语言安全底线；语言实现与框架配置见各语言目录。
> 判定方式为评审；能机器化的在 `07-检查手段.md` 登记。
> 编号 `COMMON-SEC-xx`。

## 1. 密钥与凭据

（COMMON-SEC-01）密钥只来自环境变量或未入库的本地配置；禁止硬编码、禁止提交、禁止写进日志。依据：OWASP Secrets Management。

（COMMON-SEC-02）密钥与内网地址禁止进入 AI 提示词；提交前检查 diff 中是否出现 `secret`、`password`、`token`、内网 IP。依据：本项目决策（AI 工作流特有）。

## 2. 鉴权与授权

（COMMON-SEC-03）鉴权只认服务端；前端的路由守卫与按钮显隐不作为权限依据。依据：阿里安全规约第 1 条；OWASP ASVS 访问控制。

（COMMON-SEC-04）每个对外接口必须有明确访问级别：公开、登录可用、管理员；默认拒绝。依据：OWASP deny by default。

（COMMON-SEC-05）按 ID 访问用户数据必须校验归属：查询条件带当前用户，或显式校验归属，不靠前端隐藏。依据：阿里第 1 条（强制）；OWASP IDOR Prevention。

（COMMON-SEC-06）**有成本或可被滥用的对外接口必须限流**：登录 / 注册、检索、模型调用、导出、任务触发这类会消耗算力、带宽或下游配额的接口，按用户或 IP 限制频率，各自独立配额；纯查询按需评估——一刀切给所有接口加限流会误伤前端轮询与批量请求。依据：阿里第 7 条（强制，有成本操作需保护）；OWASP DoS。

（COMMON-SEC-07）可重放的操作必须防重放：幂等键或一次性凭据；验证码须限次与过期。依据：阿里第 7 条。

## 3. 输入与输出

（COMMON-SEC-08）外部输入在边界校验：类型、长度、取值范围、枚举合法性；业务规则在 Service，内部不重复校验。依据：阿里第 4 条（强制）；OWASP Input Validation；口径与 `03-反模式.md` 的 `ANTI-02` 一致。

（COMMON-SEC-09）SQL 只用参数化绑定或 ORM，禁止拼接；动态排序字段走白名单。依据：阿里第 3、4 条（强制）。

（COMMON-SEC-10）出参只含页面需要的字段；实体、内部状态、密钥类字段不得外泄。依据：OWASP 数据保护。

（COMMON-SEC-11）敏感字段脱敏：手机号、身份证号、邮箱在响应与日志中按规则遮蔽。依据：阿里第 2 条（强制）。

（COMMON-SEC-12）不向 HTML 输出未转义的用户数据：前端禁用 `v-html` 渲染用户内容，后端不拼接 HTML。依据：阿里第 5 条（强制）；OWASP XSS Prevention。

（COMMON-SEC-13）重定向目标必须走白名单，禁止用请求参数直接作跳转地址。依据：阿里第 4 条；OWASP Unvalidated Redirects。

## 4. 文件

（COMMON-SEC-14）上传文件必须校验：扩展名白名单、大小上限、内容类型；存储路径由服务端生成，禁止用客户端文件名拼路径。依据：OWASP File Upload。

（COMMON-SEC-15）下载接口按身份校验归属，禁止仅凭可猜测的 ID 放行。依据：阿里第 1 条；OWASP IDOR。

## 5. 依赖

（COMMON-SEC-16）不引入已知高危漏洞版本的依赖；新增依赖写明版本与用途。依据：OWASP Vulnerable Dependency Management。

## 6. 日志

（COMMON-SEC-17）日志不打印密码、令牌、完整手机号/身份证号、密钥；定位需要时打印 ID。依据：OWASP Logging。

（COMMON-SEC-18）异常不把堆栈或内部标识返回客户端；对外只给错误码与可读提示。依据：OWASP Error Handling。

## 7. 浏览器侧

（COMMON-SEC-19）使用 Cookie 会话时必须做 CSRF 防护；使用 `Authorization: Bearer` 且不依赖 Cookie 时本条不适用（当前属后者，改动认证方式须重新评估）。依据：阿里第 6 条（强制）；OWASP CSRF Prevention。

## 8. 认证会话与限流

（COMMON-SEC-20）令牌自包含且可服务端校验版本：改密、改角色、停用、删除必须让已签发令牌立即失效；签发后不提供单张令牌的提前作废接口，登出由客户端丢弃令牌。依据：OWASP Session Management；无状态令牌的失效只能靠版本比对。

（COMMON-SEC-21）管理类接口逐方法标注管理员授权注解；新增管理方法必须同步标注，漏标即对普通用户开放。依据：OWASP deny by default；`COMMON-SEC-04`。

（COMMON-SEC-22）权限串格式统一为 `ROLE_<role>`，认证过滤器写入的权限串必须与授权表达式一致。依据：Spring Security 方法级授权约定。

（COMMON-SEC-23）接口级限流与登录失败防护分离：接口按 IP + 接口名计数，登录失败按账号 + IP 计数、成功只清账号维度；锁定/限流期间不查库、不比对密码。依据：OWASP Authentication Cheat Sheet；`COMMON-SEC-06`。

（COMMON-SEC-24）客户端 IP 只取连接地址，不信任客户端可伪造的转发头；前面有反向代理时按可信代理白名单解析。依据：OWASP 代理与头注入；限流维度不能被请求头操纵。

（COMMON-SEC-25）**限流是产品决策，不是实现细节**：给哪个接口加 `@RateLimit`、容量与窗口取多少、是否移除，必须先给出建议与影响面（正常用户、前端轮询、批量请求）并由用户确认；未经确认不得自行添加或调整。依据：本项目决策——限流误伤正常用户的代价高于漏防，配额只能由了解业务节奏的人定。
