# 10 · 工作习惯指南

> **指导不是法条**：本文件的条款无法机器判定，也不进评审项，只作为默认工作方式。偏离不需要理由，但按它做通常更快。
> 有执行者的条款在 `02-交付行为约束.md`。编号沿用原编号，不因搬迁改变。

## 1. 先读后写

（COMMON-WORK-01）动某个目录前，先读该目录所属的规范，以及同族最近的一份实现。等级【应该】。

- 问题：靠邻近代码模仿；不读就按通用最佳实践写，与本项目形态冲突。
- 行业：主流编码代理工具要求先读仓库再改；agent 文档写明「代理靠正常探索发现约定」。
- 我们：规范与同族实现各读一份，再动手。
- 自查：能否指出你参照的那份实现。

## 2. 最小改动

（COMMON-WORK-02）只改任务相关文件：不顺手重命名、不重排 import、不格式化无关代码。等级【应该】。

- 问题：无关改动放大阅读成本，把真实意图埋在噪音里。
- 行业：作用域限定是编码代理工具的默认要求；评审实践要求 diff 聚焦。
- 我们：diff 只含任务声明的范围。
- 自查：核对 diff 文件清单。

## 3. 口径不猜

（COMMON-WORK-04）规范未覆盖且有歧义时停下来问，不自行发明口径。等级【应该】。

- 问题：猜出来的口径写进代码后，没人知道它从哪来。
- 行业：通用 agent 实践要求歧义时提问，而不是补全。
- 我们：问一句的代价低于返工。
- 自查：能否指出该口径的出处。

## 4. 依赖不凭记忆

（COMMON-WORK-06）库的用法以仓库现状与一手文档为准；不确定就查，不凭训练记忆写 API。等级【应该】。

- 问题：编造的方法名与配置项能通过编译，在运行期才失败。
- 行业：幻觉 API 是已知的模型失效模式。
- 我们：查仓库现状与官方文档。
- 自查：能否给出该 API 的文档位置。

## 5. 报告如实

（COMMON-WORK-07）未完成、未验证、有已知风险，交付时逐项写明，不用「应该没问题」收尾。等级【应该】。

- 问题：把验证成本转移给下一个会话。
- 行业：agent 实践要求区分「已做 / 未做 / 不确定」。
- 我们：逐项写「已验证 / 未验证 / 已知风险」。
- 自查：交付说明是否出现这三类标签。
