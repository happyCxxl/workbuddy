# 03 · AI 反模式

> 「AI 味代码」的负面清单。每条写：表现、问题、正确做法、发现方式。
> 编号 `COMMON-ANTI-xx`。发现新变体就往本文件加一条，并在 `00-索引` 登记。

## 1. 过度抽象

（COMMON-ANTI-01）

- 表现：单一实现也抽接口、工厂、策略；基类只有一个空方法。
- 问题：多一层跳转，读代码要跨文件；抽象没有第二个使用者就不产生价值。
- 正确：直接写具体实现；出现第二个实现再抽。
- 例外：规范强制的抽象（Service 接口）。
- 发现：评审时问「这个接口有几个实现」。

## 2. 防御性冗余

（COMMON-ANTI-02）

- 表现：已判空处再判空；Controller、Service、DTO 三处重复同一条校验。
- 问题：真正的校验点被淹没，改动时不知道改哪一层。
- 正确：校验只写一次，写在边界——入参用 `@Valid`，业务规则在 Service。
- 发现：同一条件在两层出现即违规。

## 3. 注释复述代码

（COMMON-ANTI-03）

- 表现：`// 设置名称` 标在 `setName` 上；`// 返回列表` 标在 `return list` 上。
- 问题：注释与代码同步腐烂，读的人要过滤一遍噪音。
- 正确：注释写约束、不变量、副作用与易踩坑处。
- 发现：`check-comments` 查禁词，本条的「信息量」靠评审。

## 4. 万能后缀

（COMMON-ANTI-04）

- 表现：Manager、Helper、Util、Processor 语义空心，什么都往里装。
- 问题：后缀是职责声明；没有职责的后缀等于没有类设计。
- 正确：后缀取自 `java/03-命名与类职责.md` §1 的词表，并符合其定义。
- 发现：`check-java-conventions` 词表扫描。

## 5. 复制粘贴

（COMMON-ANTI-05）

- 表现：同一逻辑在三个类里各写一遍，只改变量名。
- 问题：修一处漏两处；AI 生成代码的重复率高于人工。
- 正确：第二处出现即抽公共；抽不动说明职责划分有问题。
- 发现：CPD（45 tokens）与阶段②的重复片段扫描。

## 6. 迎合式重构

（COMMON-ANTI-06）

- 表现：任务只要加一个字段，却顺手重命名三个类、重排 import、调整无关格式。
- 问题：diff 膨胀，评审看不到真正改动；回滚牵连无关代码。
- 正确：最小改动（`COMMON-AI-02`）。
- 发现：diff 中无关文件的占比。

## 7. 幻觉 API

（COMMON-ANTI-07）

- 表现：调用不存在的方法、编造配置项、用错注解属性。
- 问题：编译通过不代表运行正确，反射、SPI、配置绑定都可能失败。
- 正确：以仓库现状与一手文档为准（`COMMON-AI-07`）。
- 发现：编译、启动校验、集成测试。

## 8. 只写成功路径

（COMMON-ANTI-08）

- 表现：新增接口只处理成功分支；错误码、空集合、并发、超时都没考虑。
- 问题：线上出问题的恰好是没写的那些分支。
- 正确：错误码分支与边界是必测项（`java/06-测试.md`）。
- 发现：评审与测试覆盖。

## 9. 报告失真

（COMMON-ANTI-09）

- 表现：「已完成」但没跑测试；用「应该没问题」收尾；失败说成「部分完成」。
- 问题：验证成本被转移给下一个会话，跨会话时没人知道哪里没验证。
- 正确：贴命令与结果（`COMMON-AI-06`、`COMMON-AI-09`）。
- 发现：交付说明缺验证记录即视为未完成。
