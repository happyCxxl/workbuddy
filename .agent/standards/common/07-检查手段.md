# 07 · 检查手段

> 本文件是「谁在执行、查什么」的唯一清单：跨语言脚本、语言侧检查类、阻断与豁免口径都在这里。规则本身在各语言目录，本文件不复述规则内容。
> 语言实现与配置见 `../java/`、`../vue/`；开发期选哪一档、失败后怎么重跑，见 `08-验证节奏.md`。

## 1. 跨语言脚本

| 脚本              | 查什么                                               | 判定                        | 接入点       |
|-------------------|------------------------------------------------------|-----------------------------|--------------|
| `check-encoding`  | 系统编码误读误写：替换字符、GBK 误读序列、乱码特征字 | ERROR 拦下                  | pre-push     |
| `check-docs`      | 文档结构与小节禁项；文档引用的仓库路径是否有效       | 出现即 ERROR                | pre-push、CI |
| `check-modules`   | 模块结构：声明目录存在、依赖无环、无自依赖           | 问题即 ERROR                | pre-push     |
| `check-agents`    | 入口文件里的仓库路径是否有效；行数是否超预算         | 指针失效 ERROR，超预算 WARN | pre-push、CI |
| `check-artifacts` | 已跟踪文件里是否混入构建产物、命令输出与覆盖率报告   | 命中即 ERROR                | pre-push、CI |
| `check-scope`     | 规范正文是否引用了 `.agent/` 之外的路径              | 越界或失效即 ERROR          | pre-push     |

## 2. 各脚本说明

### check-encoding

- 覆盖：仓库内受版本控制的文本文件。
- 典型成因：用 PowerShell 的文本写入命令修改 UTF-8 源码，中文被按系统编码读入再写回。这类破坏不影响编译，类型检查与 lint 都看不出来，只能靠这道门禁拦下。
- 无行内豁免；文档需要举例写出这些序列时改用转义写法（如 `U+FFFD`）。脚本自身已跳过。

### check-docs

- 覆盖：仓库内所有 `.md`。
- 标题为「变更记录」「决策记录」的一律报错——文档只看现状，不留沿革（`JAVA-DOC-009`）。
- 文档里引用的仓库路径必须真实存在（`JAVA-DOC-010`）：Markdown 链接目标，以及反引号里末段带扩展名的文件路径；解析基准先取文档所在目录，再回退仓库根。正文里的包路径片段、路由与 URL 片段不是文件指针，不参与判定。
- 无豁免：删掉小节或更正路径，别让引用指向已删文件。

### check-modules

- 解析仓库内的构建文件：声明的模块目录必须存在且含构建文件；有父模块的模块必须被父模块声明；同 groupId 的依赖必须是仓库内存在的模块；模块间依赖不得成环、不得自依赖。
- 问题即 ERROR，无豁免：改构建文件的模块声明或依赖。

### check-agents

- 覆盖：仓库内任意层级的代理入口文件；行数预算取通用默认值 200 行。
- 检查反引号里出现的仓库路径是否真实存在；失效即 ERROR。
- 无豁免：路径错就改路径，文件没了就删条目。

### check-artifacts

- 覆盖：仓库内所有已跟踪的文件；未跟踪的由忽略清单负责。
- 判定三类形态：构建产物目录、编译产物与临时文件、命令输出与覆盖率报告。
- 无豁免：从索引移除该文件，并把该形态补进忽略清单；命令输出改写到仓库外或已忽略目录。

### check-scope

- 覆盖：`.agent/` 下全部规范文档。
- 本目录要能被别的项目整包复用：正文只允许引用 `.agent/` 内的路径；三个解析基准为文档所在目录、`.agent` 根、仓库根。
- 只判**路径引用**；正文点名外部文件名（构建文件、入口文件等）属评审项，无法客观判定。
- 无豁免：引用外部文件即 ERROR，改为通用表述或在包内新建。

## 3. 语言侧检查类

构建期必须执行下列检查，任一不通过即阻断：

### Java

| 检查类       | 覆盖                                                 | 执行者                 |
|--------------|------------------------------------------------------|------------------------|
| 源码风格     | 命名、导入、括号、空白、行长                         | Checkstyle             |
| 源码静态分析 | 未使用成员与参数、可疑写法                           | PMD                    |
| 重复代码     | 片段重复（阈值全库一致）                             | CPD                    |
| 字节码分析   | 空指针、资源泄漏、`equals`/`hashCode`、可疑集合用法  | SpotBugs               |
| 覆盖率       | 语句与分支覆盖达标（门槛见 `04-测试策略.md`）        | JaCoCo                 |
| 形态约定     | 后缀词表、请求/响应命名、注释形态、import 分层 | check-java-conventions |
| 注释形态     | Javadoc 覆盖与标记、行尾注释、TODO 形态              | check-javadoc          |
| 用例质量     | 恒真断言、无断言、只验交互、缺来源说明               | check-test-quality     |

### Vue

| 检查类     | 覆盖                                    | 执行者                 |
|------------|-----------------------------------------|------------------------|
| 格式化     | 缩进、引号、分号、行宽、文件末尾换行    | prettier               |
| 静态 lint  | 语言规则、框架规则、可访问性规则        | eslint                 |
| 类型检查   | 全量类型检查，禁止 `any` 逃逸           | vue-tsc                |
| 文件命名   | 目录与文件命名规则                      | ls-lint                |
| 命名与结构 | 页面与路由一致、接口层唯一              | check-naming           |
| 组件口径   | 组件命名、样式隔离、单文件块顺序        | check-spec             |
| 表格口径   | 骨架类、列宽、列对齐                    | check-table            |
| 样式口径   | 禁 `:deep`、字体栈、小数 px、未使用类名 | stylelint + check-spec |

依据：Google《Software Engineering at Google》第 11 章——确定性执行优先于散文；能机器判定的不得靠人记。

## 4. 阻断与豁免

- 检查失败即阻断构建，不提供「先过再修」的开关。
- 不设行内豁免与豁免清单；判定不适用时改规则，不在代码里打标记。
- 同一类告警反复出现时，改代码而不是放宽检查。
- 规则集里的排除项必须逐条对应一条编号规则，并在该规则正文写明理由。

## 5. 规则集的位置

- 规则集与豁免清单与代码同仓，随版本一起评审。
- 规则集变更属于规范变更：先说明影响面，再改配置。
- 规则集必须与既有代码风格对齐；存量偏离由整改收敛，不为迁就存量放宽规则。

## 6. 检查器本身的约束

- 每个检查器只判定一类问题，输出「文件:行 规则 说明」。
- 检查器的误报先修检查器，不在规则集里长期豁免。
- 失败信息必须给出复跑命令。
- 检查器文案与配置注释只引规则编号（如 `VUE-COMP-006`），不引小节号：编号稳定可检索，小节号随改版漂移。
- 不重复实现别的层面已覆盖的检查：注释形态只对 Java 生效，前端注释按 `../vue/01-工程与命名.md` 评审。

## 7. 与门禁的关系

- 提交前只做就地修复（格式化），保证提交不被格式问题卡住。
- 推送前做全量校验，范围按改动计算；档位与超时处置见 `08-验证节奏.md`。
- 只涉及文档或注释的改动，可跳过编译类检查，但不能跳过 Javadoc、文档结构与编码检查。
- 门禁失败：修到全绿再推；修不动如实报告，禁止绕过。
- 门禁本体是 `../../tools/common/pre-push-gate.sh`；表格格式化器是 `../../tools/common/format-md.ps1`；Java 档位编排是 `../../tools/java/verify.mjs`。
