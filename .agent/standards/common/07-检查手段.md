# 07 · 检查手段（跨语言）

> `.agent/tools/common/` 下跨语言共用的检查脚本；语言专属的手段在 `tools/java/`、`tools/vue/`，与规范目录同构。规则本身在各语言目录，本文件只说明「谁在执行、查什么、怎么豁免」。
> 语言侧检查器见 `../java/08-静态检查.md`、`../vue/04-检查手段.md`。

## 1. 清单

| 脚本             | 查什么                                                     | 判定                            | 接入点       |
|------------------|------------------------------------------------------------|---------------------------------|--------------|
| `check-comments` | 注释与文档正文里的阶段词、沿革词、因果与目的词、给谁用表述 | ERROR 拦下，WARN 提示           | pre-push     |
| `check-encoding` | 系统编码误读误写：替换字符、GBK 误读序列、乱码特征字       | ERROR 拦下，WARN 提示           | pre-push     |
| `check-modules`  | 模块依赖表与各模块 `pom.xml` 是否双向一致                  | 未登记的边 ERROR，已删的边 WARN | pre-push     |
| `check-agents`   | 入口文件里的仓库路径是否有效；行数是否超预算               | 指针失效 ERROR，超预算 WARN     | pre-push、CI |

## 2. 各脚本说明

### check-comments

- 覆盖：`workbuddy-*/src`、`web/src`、`web/docs`、`docs`、`.agent`、根 `README.md`、`.husky/`。
- 只扫注释与文档正文，不扫字符串字面量；`--strings` 给出只读清单，不判失败。
- 规则出处：`../vue/01-工程与命名.md` §5、`../java/08-静态检查.md`。
- 某行确需保留禁词时写 `口径豁免：<理由>`，脚本跳过该行。

### check-encoding

- 覆盖：各模块 `src`、`web`、`docs`、`.agent/tools`、`docker`、`sql`、根与各模块的 `pom.xml`、`.husky/`。
- 典型成因：用 PowerShell 的文本写入命令修改 UTF-8 源码，中文被按系统编码读入再写回。这类破坏不影响编译，类型检查与 lint 都看不出来，只能靠这道门禁拦下。
- 某行确需举例写出这些序列时写 `编码豁免：<理由>`；脚本自身已跳过。

### check-modules

- 解析仓库内的 `pom.xml`：模块声明的目录必须存在，模块间依赖不得成环、不得自依赖。
- 问题即 ERROR，无豁免：改 `pom.xml` 的模块声明或依赖。

### check-agents

- 扫三个入口及其行数预算：`AGENTS.md`（≤80 行）、`web/AGENTS.md`（≤50 行）、`06-协作流程.md`（≤130 行）。
- 检查反引号里出现的仓库路径是否真实存在；失效即 ERROR。
- 无豁免：路径错就改路径，文件没了就删条目。

## 3. 运行方式

```
node .agent/tools/common/check-comments.mjs            # 全量
node .agent/tools/common/check-comments.mjs --strings  # 附字符串字面量清单
node .agent/tools/common/check-encoding.mjs
node .agent/tools/common/check-modules.mjs
node .agent/tools/common/check-agents.mjs
```

在推送门禁中的顺序与触发条件见 `06-协作流程.md` §2 与 `../java/08-静态检查.md`。门禁脚本本体是 `.agent/tools/common/pre-push-gate.sh`；提交前的 Markdown 表格格式化器是 `.agent/tools/common/format-md.ps1`。
