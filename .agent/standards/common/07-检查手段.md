# 07 · 检查手段（跨语言）

> `.agent/tools/common/` 下跨语言共用的检查脚本；语言专属的手段在 `tools/java/`、`tools/vue/`，与规范目录同构。规则本身在各语言目录，本文件只说明「谁在执行、查什么」。
> 语言侧检查器见 `../java/08-静态检查.md`、`../vue/04-检查手段.md`。

## 1. 清单

| 脚本              | 查什么                                               | 判定                        | 接入点       |
|-------------------|------------------------------------------------------|-----------------------------|--------------|
| `check-encoding`  | 系统编码误读误写：替换字符、GBK 误读序列、乱码特征字 | ERROR 拦下                  | pre-push     |
| `check-docs`      | 文档结构：不得出现「变更记录」「决策记录」小节       | 出现即 ERROR                | pre-push、CI |
| `check-modules`   | 模块结构：声明目录存在、依赖无环、无自依赖           | 问题即 ERROR                | pre-push     |
| `check-agents`    | 入口文件里的仓库路径是否有效；行数是否超预算         | 指针失效 ERROR，超预算 WARN | pre-push、CI |
| `check-artifacts` | 已跟踪文件里是否混入构建产物、命令输出与覆盖率报告   | 命中即 ERROR                | pre-push、CI |

> 用例质量门禁（`check-test-quality`）在语言侧：`tools/java/`，见 `../java/08-静态检查.md`。

## 2. 各脚本说明

### check-encoding

- 覆盖：仓库内受版本控制的文本文件。
- 典型成因：用 PowerShell 的文本写入命令修改 UTF-8 源码，中文被按系统编码读入再写回。这类破坏不影响编译，类型检查与 lint 都看不出来，只能靠这道门禁拦下。
- 无行内豁免；文档需要举例写出这些序列时改用转义写法（如 `U+FFFD`）。脚本自身已跳过。

### check-docs

- 覆盖：仓库内所有 `.md`。
- 标题为「变更记录」「决策记录」的一律报错——文档只看现状，不留沿革。
- 无豁免：删掉小节，或把它移进业务文档的正文。

### check-modules

- 解析仓库内的 `pom.xml`：声明的模块目录必须存在且含 `pom.xml`；有父模块的模块必须被父模块声明；同 groupId 的依赖必须是仓库内存在的模块；模块间依赖不得成环、不得自依赖。
- 问题即 ERROR，无豁免：改 `pom.xml` 的模块声明或依赖。

### check-agents

- 覆盖：仓库内任意层级的 `AGENTS.md`；行数预算取通用默认值 200 行。
- 检查反引号里出现的仓库路径是否真实存在；失效即 ERROR。
- 无豁免：路径错就改路径，文件没了就删条目。

### check-artifacts

- 覆盖：仓库内所有已跟踪的文件；未跟踪的由 `.gitignore` 负责。
- 判定三类形态：构建产物目录（`target/`、`node_modules/`、`build/` 等）、编译产物与临时文件（`*.class`、`*.jar`、`*.tmp`、`*.bak` 等）、命令输出与覆盖率报告（`*-out.txt`、`jacoco.*`）。
- 无豁免：命中即 `git rm --cached` 移除，并把该形态补进 `.gitignore`；命令输出改写到仓库外或已忽略目录。

## 3. 运行方式

```
node .agent/tools/common/check-docs.mjs
node .agent/tools/common/check-encoding.mjs
node .agent/tools/common/check-modules.mjs
node .agent/tools/common/check-agents.mjs
node .agent/tools/common/check-artifacts.mjs
```

在推送门禁中的顺序与触发条件见 `06-协作流程.md` §2 与 `../java/08-静态检查.md`。门禁脚本本体是 `.agent/tools/common/pre-push-gate.sh`；提交前的 Markdown 表格格式化器是 `.agent/tools/common/format-md.ps1`。
