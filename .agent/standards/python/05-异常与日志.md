# 05 · 异常与日志

> 本文件写异常层级、错误码与日志口径；与具体类名无关。安全口径见 `../common/05-安全.md`。

## 1. 异常层级

（PY-ERR-001）自定义异常继承合适的内置基类，类名以 `Error` 结尾；公共出口按异常族分类处理。

依据：Google 指南「Exceptions」——异常名不重复后缀（`foo.FooError` 是坏名）。

（PY-ERR-002）断言不得承载业务逻辑与参数校验：`assert` 可能被 `-O` 移除。校验用显式 `if` + 异常。

依据：Google 指南「Exceptions」——断言不保证执行，业务逻辑依赖它是隐患。

（PY-ERR-003）禁止裸 `except` 与吞异常：要么重抛，要么记录后作为隔离点处理。

依据：Google 指南「Exceptions」——裸 `except` 会吞掉拼写错误、退出信号等本不该捕获的东西。

## 2. 错误码

（PY-ERR-004）错误码集中登记：单一模块定义全部码值，接口码与内部码分列，AI 域单独分段；新增先登记后使用；业务代码禁止硬编码码值。判定：形态检查（后续接入）+ 评审。

（PY-ERR-005）未登记异常经统一出口转通用错误码并记日志；不得向调用方泄露堆栈与内部信息。

依据：`../common/05-安全.md` 的输出约束——堆栈信息是攻击者的侦察材料。

## 3. 日志

（PY-LOG-001）日志级别口径：关键路径与参数进 info，失败进 error，调试细节进 debug；循环体内不记 info。

依据：与 java 域日志口径一致——循环内 info 是日志洪水的直接来源。

（PY-LOG-002）敏感字段脱敏：密钥、令牌、完整用户内容不落日志；模型 prompt 与输出按数据分级处理。

依据：`../common/05-安全.md`——密钥与个人内容进日志即泄露面。

（PY-LOG-003）结构化日志必带 `requestId`、用户标识、耗时；模型调用另带模型名与 token 用量。
