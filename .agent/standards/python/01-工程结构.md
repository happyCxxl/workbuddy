# 01 · 工程结构

> 本文件写分层、函数与类的分配、命名、类型注解与注释；与具体模块名无关。
> 风格基底是 Google Python Style Guide，本文件只写基底之外的判定与例外；导入排序、行长等机械口径由 ruff 配置执行，不在此复述。

## 1. 分层与依赖

（PY-LAYER-001）依赖单向向下：接口层（路由与请求装配）→ 用例层（模块函数编排）→ 数据访问层（repository 类）；外部能力一律经端口（`Protocol`）调用，实现在适配层。

- 禁止跨层调用与反向依赖：数据访问层不得感知接口层；用例层不得直接操作连接池与框架对象。
- 端口只放抽象，适配只放对接：端口文件不含具体供应商逻辑。

（PY-LAYER-002）模块按内聚组织，一个模块一个主题；公开接口经包的 `__init__` 显式导出；禁止相对导入。

（PY-LAYER-003）禁止循环导入；导入分组与排序由 ruff 判定，不手写。

## 2. 函数与类的分配

（PY-LAYER-004）**数据用类承载**：请求/响应与 LLM 结构化输出用 Pydantic 模型；表实体用 ORM 类；跨层纯数据用 `dataclass` 或 `TypedDict`。裸 `dict` 只在与外部系统对接的边界出现，且就地转成上述类型。

（PY-LAYER-005）**无状态逻辑用模块函数**；类只在「有状态或多方法」时出现：持配置与客户端的执行器、封装会话的 repository、领域对象。不得仅为分组一次调用的参数建类。

依据：微软编码标准「不得为分组参数建类」；Google 指南主张模块级函数优先。

（PY-LAYER-006）属性直接公开；需要计算、约束或兼容旧行为时才用 `@property`。禁止为读写字段写 getter/setter 样板。

依据：Google 指南「Getters and Setters」一节——无计算的 getter/setter 是噪声。

（PY-LAYER-007）禁止 `staticmethod`；`classmethod` 只用于命名构造器。依据：Google 指南「Function and Method Decorators」。

（PY-LAYER-008）避免可变全局状态：模块级只放常量与纯工具；确需全局状态时用 `_` 前缀并注明理由。依据：Google 指南「Mutable Global State」。

## 3. 命名与文件

（PY-NAME-001）模块、函数、变量 snake_case；类 PascalCase；常量 UPPER_CASE；私有成员一律 `_` 前缀。禁止用双下划线名字改写作为封装手段。

（PY-NAME-002）布尔判定用 `is_`/`has_` 前缀；无返回值函数用动词命名。

（PY-NAME-003）禁止遮蔽内置名与标准库模块名（`list`、`id`、`sum` 等不得作变量名）。判定：ruff。

（PY-NAME-004）文件命名 snake_case 且与主题一致；文件内的主类/主函数与文件名呼应。

## 4. 类型注解

（PY-LAYER-009）所有函数签名完整注解每个参数与返回值；公共 API 的注解必须稳定。判定：Pyright strict。

（PY-LAYER-010）禁止无理由 `Any`：确需使用必须注释理由，并优先用 `Protocol`、`TypeVar`、`TypeAlias` 收窄。判定：Pyright + 评审。

（PY-LAYER-011）只读集合参数用最窄抽象：不改动用 `Mapping`/`Sequence`/`Collection`，不强制要求可变具体类型。依据：微软编码标准「Collection Inputs」。

（PY-LAYER-012）类型报错按序解决：改进设计 → 窄范围的规则级抑制（注明理由）→ `cast()` → 运行时校验。禁止无理由的文件级抑制。依据：微软编码标准「Suppressions and Casts」。

## 5. 注释与文档

（PY-DOC-001）docstring 只写契约：做什么、约束、副作用、`Raises`；不写沿革、阶段、人员。依据：本项目决策（与 java 域同口径）。

（PY-DOC-002）模块与公共函数必有 docstring，格式随基底（`Args`/`Returns`/`Raises` 分节）；私有函数按需。

（PY-DOC-003）实现注释只补类型与名字表达不了的信息；`TODO` 注明理由与范围。依据：Google 指南「Comments and Docstrings」「TODO Comments」。
