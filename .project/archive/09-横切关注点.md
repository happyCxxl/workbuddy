# 09 · 横切关注点

> 本文件回答：贯穿所有模块的通用机制是怎么做的——这些机制不在单一模块里，散布在代码各处，最容易被忽略、也最容易重复造轮子。

## 安全与鉴权

> 认证方式、权限模型、敏感操作的保护。

- JWT 无状态认证：`JwtAuthFilter` 解析令牌、`JwtTokenSupport` 签发与校验、`SecurityConfig` 配置放行规则、`RestAuthenticationEntryPoint` 统一 401 响应。
- 登录防护：`LoginAttemptGuard` 限制失败次数，参数由 `LoginGuardProperties` 绑定。
- 管理接口：`@AdminOnly` 注解（规则见 `COMMON-SEC-21`）。
- 敏感配置：JWT 密钥等只出现在配置与本地环境，不入库、不入 prompt。

## 配置管理

> 配置文件、环境变量的组织方式与优先级。

- 配置面：主文件 `workbuddy-biz/src/main/resources/application.yml` 用 `spring.config.import` 逐行列出环节配置（无通配符）：平台级 `config/workbuddy-<域>.yml`、知识库环节 `config/knowledge/knowledge-<域>.yml`；本机覆盖 `application-local.yml` 以 `optional:` 载入（被 gitignore，缺失即跳过）。
- 配置类是纯载体：13 个 `@ConfigurationProperties` 只声明字段与按环节语义的方法，字段没有初始值；取值全部来自配置面，缺失时运行期取 0 或 null。新增环节的落点是「建一份环节 yml + 清单加一行 + 覆盖用例登记前缀」。
- 三类防线：`PropertiesConfigCoverageTest` 逐字段核对配置键存在（CI 期）；`ParserWhitelistChecker` 在白名单整段缺失时拒绝启动；`TaskTimeoutCheck` 在环节超时整段缺失时记告警放行，`timeoutOf` 对未配置环节回退全局默认。
- 单测取值：`PropertiesFixtures`（worker）与 `ConfigFixtures`（biz）用 YAML 加载器 + Binder 读配置面，不启 Spring 容器；改配置会影响单测断言，这是「测试验证发布基线」的预期代价。
- 值域校验（比例区间、正数下限）尚未用 JSR-303 注解，当前只有存在性与个别启动期守卫；补注解需先把基本类型字段换成包装类型。
- 敏感配置：JWT 密钥等只出现在配置与本地环境，不入库、不入 prompt。

## 日志与错误处理

> 日志口径、错误处理模式。

- 统一异常：`GlobalExceptionHandler` 捕获后转为统一响应结构。
- 抛出入口：条件守卫一律走 `ThrowUtil.throwIf`——业务拒绝用 `ErrorCode` 重载（`WorkbuddyException`，warn 级）；内部缺陷用异常工厂重载，保留 JDK 异常类型（`IllegalStateException` 等，error 级）。detail 为空白时回退错误码默认文案；消息里要解引用被检查对象时用工厂重载（三参数重载会提前求值）。
- catch 包装：**不用工具类**（catch 里没有"条件"，套守卫语义会把工具类变成通用异常工厂）。做法是先把原始异常记一条 `warn`，再抛业务异常——异常对象必须放最后一个参数，SLF4J 才会打栈；业务消息保持干净，原始原因只进日志、不返回前端。
- 响应口径：对外 HTTP 恒 200，错误语义由业务错误码携带（规则见 `JAVA-DTO-007`、`JAVA-ERR-005`）。
- 日志口径：注释与日志只写契约，不写沿革与人员（`AGENTS.md` §2 Never#2）。

## 事务边界

> 事务只包 DB 写；对象存储、Milvus、Redis 与任务入队都在事务外（`JAVA-TX-002`）。

- `KnowledgeBaseFileServiceImpl.submit`：文件校验与元数据读取在事务外；来源文件 / 文件结果 / 提交日志三写由 `TransactionTemplate` 短事务包住；`uk_request_id` 冲突回滚后回放。
- `StorageSourceServiceImpl.switchCurrent`：注册与探活（外部）在事务外；清旧、置新、探活结论与审计在一个短事务内；`StorageRouter.markCurrent` 在提交后执行，DB 是持久事实源。
- `IndexSetServiceImpl.recycle`：Milvus `drop` 在事务外先执行；审计与删版本行在短事务内。
- `IndexSetServiceImpl.rollback`：指针切回与补偿任务行仍在同一事务；`TaskQueueSupport` 在事务内只登记 `afterCommit`，Redis 入队延迟到提交后。
- 提交后入队失败只记日志，任务保持 `QUEUED`，由 `TaskStartupCompensator` 启动补偿与低频扫描补投；事务回滚则不推送。

## 对象映射与统计口径

> 实体/产物 → 出参对象怎么转（`JAVA-DTO-013`）。

- 数据载体之间的转换集中在共享模块的 `convert` 包：编译期注解处理器（MapStruct）生成实现，运行期无反射；调用方注入转换接口，生成类不进版本库。
- 输出算法对象的命令组装不进转换层（例如索引构建命令由调用方工厂生成），保证共享模块不反向依赖算法模块。
- 映射只搬字段：需要计数、过滤、取产物的部分放在 `support/stats/`（统计口径）与 `support/{index,lineage,stagecontent}`（各自领域装配），转换器用默认方法补齐口径差异（空值返回空列表、按 chunkId 关联产物字段）。
- 统计支撑类直接产出 `*StatsVO`（切片/预处理/组装/向量化），不再经 `Map` 中转；执行树节点与详情页共用同一份统计口径。
