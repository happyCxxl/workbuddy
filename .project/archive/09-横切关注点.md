# 09 · 横切关注点

> 本文件回答：贯穿所有模块的通用机制是怎么做的——这些机制不在单一模块里，散布在代码各处，最容易被忽略、也最容易重复造轮子。

## 安全与鉴权

> 认证方式、权限模型、敏感操作的保护。

- JWT 无状态认证：`JwtAuthFilter` 解析令牌、`JwtTokenSupport` 签发与校验、`SecurityConfig` 配置放行规则、`RestAuthenticationEntryPoint` 统一 401 响应。
- 登录防护：`LoginAttemptGuard` 限制失败次数，参数由 `LoginGuardProperties` 绑定。
- 管理接口：`@AdminOnly` 注解（规则见 `COMMON-SEC-21`）。
- 敏感配置：JWT 密钥等只出现在配置与本地环境，不入库、不入 prompt。

## 配置管理

> 配置文件、环境变量的组织方式与优先级。

- 配置文件：`workbuddy-biz/src/main/resources/application.yml`（通用）+ `application-local.yml`（本地覆盖）。
- 配置类：`JwtProperties`、`LoginGuardProperties`、`MilvusProperties`、`ModelVendorProperties` 按前缀绑定。

## 日志与错误处理

> 日志口径、错误处理模式。

- 统一异常：`GlobalExceptionHandler` 捕获后转为统一响应结构。
- 响应口径：对外 HTTP 恒 200，错误语义由业务错误码携带（规则见 `JAVA-DTO-007`、`JAVA-ERR-005`）。
- 日志口径：注释与日志只写契约，不写沿革与人员（`AGENTS.md` §2 Never#2）。

## 事务边界

> 事务只包 DB 写；对象存储、Milvus、Redis 与任务入队都在事务外（`JAVA-TX-002`）。

- `KnowledgeBaseServiceImpl.submit`：文件校验与元数据读取在事务外；来源文件 / 文件结果 / 提交日志三写由 `TransactionTemplate` 短事务包住；`uk_request_id` 冲突回滚后回放。
- `StorageSourceServiceImpl.switchCurrent`：注册与探活（外部）在事务外；清旧、置新、探活结论与审计在一个短事务内；`StorageRouter.markCurrent` 在提交后执行，DB 是持久事实源。
- `IndexSetServiceImpl.recycle`：Milvus `drop` 在事务外先执行；审计与删版本行在短事务内。
- `IndexSetServiceImpl.rollback`：指针切回与补偿任务行仍在同一事务；`TaskQueueSupport` 在事务内只登记 `afterCommit`，Redis 入队延迟到提交后。
- 提交后入队失败只记日志，任务保持 `QUEUED`，由 `TaskStartupCompensator` 启动补偿与低频扫描补投；事务回滚则不推送。

## 对象映射与统计口径

> 实体/产物 → 出参对象怎么转（`JAVA-DTO-013`）。

- 映射类集中在 `biz/service/support/assemble/`：编译期注解处理器（MapStruct）生成实现，运行期无反射；服务注入映射接口，生成类不进版本库。
- 映射只搬字段：需要计数、过滤、取产物的部分放在 `support/stats/`（统计口径）与 `support/{index,lineage,stagecontent}`（各自领域装配），映射类用默认方法补齐口径差异（空值返回空列表、按 chunkId 关联产物字段）。
- 统计支撑类直接产出 `*StatsVO`（切片/预处理/组装/向量化），不再经 `Map` 中转；执行树节点与详情页共用同一份统计口径。
