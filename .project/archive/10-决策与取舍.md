# 10 · 决策与取舍

> 本文件回答：关键决策是什么、否掉了什么。
> 记录被否掉的方案——后来者才不会重新走上同一条死路。

| 决策                                                 | 备选方案                       | 取舍理由                                  | 依据位置                                 |
|------------------------------------------------------|--------------------------------|-------------------------------------------|------------------------------------------|
| 单体多模块，不做微服务                               | 按功能拆微服务                 | 单人维护、部署简单；模块边界由 Maven 强制 | `AGENTS.md` §1                           |
| 模块按职责分五层（契约 / 基础 / 适配 / 算法 / 应用） | 按技术名词分层                 | 依赖方向单一，可用检查器判定              | `.agent/standards/java/01-分层与依赖.md` |
| 对外 HTTP 恒 200 + 业务错误码                        | 直接用 HTTP 状态码表达业务失败 | 前端统一处理分支；错误码集中登记          | `docs/README.md`「全局约定」             |
| 单实现的 Service 仍保留接口                          | 直接用类                       | 便于 mock 与替换；命名规约要求            | `JAVA-LAYER-006`                         |
| 限流走 Redis 令牌桶                                  | 单机内存限流                   | 多实例部署下限流与锁仍有效                | `workbuddy-infra` 的 ratelimit 包        |
| JaCoCo 门禁：全库 70%、核心模块 90%                  | 只报告不阻断                   | 防止不写测试的提交                        | 根 `pom.xml`、`COMMON-TEST-07`           |
| 规范（规则）与档案（事实）分离                       | 混在一处                       | 规则不随现状腐化；事实可重新采集刷新      | `.agent/` 与 `.project/` 的分工          |
| 档案新鲜度用独立状态文件承载                         | 在每份档案里写日期             | 单文件可总览、门禁可按基线判定            | `.project/archive/status.json`           |
| 检查器按语言分目录（`common/`、`java/`、`vue/`）     | 平铺一个目录                   | 与规范目录一一对应，好定位                | `.agent/tools/`                          |
| `vector` 模块并入 `infra`                            | 保持独立模块                   | 纯适配器、无业务表，属于基础层            | 结构目标（代码待迁）                     |
