# 02 · 背景与目标

> 本文件回答：项目存在于什么环境、解决什么问题、给谁用、做到哪为止。
> 这一节是全档案的**意图层**：后面的结构、数据、接口都是这些意图的技术投影。

## 背景与环境

> 只写客观事实：技术环境、业务环境、既有系统。不写需求与期望——那些属于「目标」。

- 单人开发、跨多台机器；无人工评审，门禁兜底。
- 后端 Java 21 + Spring Boot 3.2.5，Maven 多模块（8 个 `workbuddy-*` 模块，包根 `com.workbuddy`）。
- 前端 Vue 3 + TypeScript + Vite + Element Plus，位于 `web/`。
- 中间件 MySQL / Redis / MinIO / Milvus 由 `docker/docker-compose.yml` 编排；本地单机运行，`biz` 为唯一可启动模块。

## 解决什么问题

> 从使用者视角写一段话：现在的痛、用完之后发生什么变化。

- 个人文档散落在本地，查找靠文件名与记忆；把文档收进统一知识库、走完流水线后，可按语义检索定位。【待确认】

- 单人自用。【待确认】

## 目标

> 本期要做到的事，短句列表，一条一个目标。

- 知识库流水线可用：文档输入 → 解析 → 组装 → 预处理 → 切片 → 向量化 → 索引 → 检索评测。【待确认】
- 后续功能域可陆续接入（工作台定位）。
- 跨机器、跨会话的开发产出保持一致（规范与门禁兜底）。

## 非目标

> 本可以合理成为目标、但明确选择不做的事——**不是**「不该崩溃」这类反义表述。

- 【待确认】AI 拟候选：不做多租户与商业化；不做移动端；不做多人实时协作；不做公开 SaaS 部署。

## 术语表

> 项目专有名词与业务概念，AI 读代码时高频引用。

| 术语             | 含义                                                     |
|------------------|----------------------------------------------------------|
| 工作台           | 承载多个功能域的上层应用形态（本项目定位）               |
| 功能域           | 工作台内一个完整业务能力（当前仅知识库）                 |
| 契约层           | 跨模块共享的请求 / 响应 / 实体 / 错误码（`common` 模块） |
| 切片（chunk）    | 文档经解析与预处理后的最小检索单元                       |
| 向量化（embed）  | 把切片转成向量的环节，产物为向量集                       |
| 索引（index）    | 向量入库与检索结构，按版本管理                           |
| 检索评测         | 对检索质量做量化评估的运行记录                           |
| 血缘（lineage）  | 记录流水线产物之间的来源关系                             |
| 策略（strategy） | 解析 / 切片 / 向量化等环节的可选配置，按版本管理         |
