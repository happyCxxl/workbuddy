# 11 质量与风险

> 本文件回答：质量要求是什么、现状差多少、有什么风险。

## 质量要求

- 静态门禁：`mvn verify` 必须通过 Checkstyle、PMD、CPD（重复代码阈值 45 tokens）、SpotBugs（Low/Max），任一失败阻断构建（JAVA-META-003）。
- 覆盖率：全库指令覆盖 ≥70%；核心链路模块（biz、worker）≥90%（COMMON-TEST-07、JAVA-TEST-009）。
- 变异检查：核心链路模块按需跑 PIT，存活变异逐条说明；当前不设 CI 增量门禁（JAVA-TEST-011）。
- 用例质量：测试方法须写明守护规则/错误码（COMMON-TEST-11）；禁止恒真断言、无断言、只验交互；`@Mock` 超过 5 个视为被测类职责过载信号。
- 推送门禁：`.agent/tools/common/pre-push-gate.sh` 按改动范围跑检查器与 `mvn -o -q verify`，失败不得绕过。

## 测试规模

- 349 个测试源码文件（320 个含用例）；biz 模块 821 个用例（2 个跳过）；全库 1783 个用例、0 失败（按本次 `mvn -o verify` 的 Surefire JUnit XML 汇总，剔除已删测试类的遗留报告）。
- 最近一次全量 `mvn -B verify`（2026-10-23）：BUILD SUCCESS；`mvn -o test` / `mvn -o verify` 均可离线复跑。
- PIT（biz）：2218 个变异、击杀 97%、存活 44、未覆盖 19，残留逐条有处置记录。
- 验证耗时基线（本机 Windows / Maven 3.9.9 / JDK 21）：检查器档约 3 秒；定向用例档 15–35 秒；模块档（biz 及其依赖链全部用例）124 秒；`mvn -pl workbuddy-biz -am verify`（含静态检查与覆盖率）236 秒。其中 biz 自身用例约 71 秒，其余为未改动模块陪跑。
- Surefire `forkCount=2` 实测 155 秒，慢于默认 124 秒：模块与用例规模摊不平 JVM 启动开销，不作为提速手段。
