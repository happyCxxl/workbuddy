# 05 · 结构

> 本文件回答：代码怎么组织的。这是 AI 读仓库的地图——先有这张图，再下钻任何文件。

## 目录地图

> 顶层目录一览，每项一句话职责。

| 目录                        | 职责                                                                                      |
|-----------------------------|-------------------------------------------------------------------------------------------|
| `workbuddy-server`          | Java 多模块工程根：构建入口 `pom.xml` 与七个分层模块，唯一可启动模块在其中                |
| `workbuddy-web`             | 前端 Vue 3 SPA                                                                            |
| `workbuddy-lingxi`          | AI 服务（灵犀）：会话、记忆、人格与工具执行，Python 独立服务                              |
| `docker`                    | 中间件编排（MySQL / Redis / MinIO / Milvus / etcd）                                       |
| `.agent`                    | 规范与检查器（`standards/` 规则、`tools/` 检查器）                                        |
| `.project`                  | 本档案                                                                                    |
| `.github`、`.husky`、`.mvn` | CI 配置、Git 钩子、Maven JVM 参数与构建根定位（`.mvn` 留在仓库根，Maven 自 cwd 向上查找） |

## 模块 / 构建块清单

| 构建块   | 职责一句话                                                  |
|----------|-------------------------------------------------------------|
| `common` | 契约层，零业务逻辑                                          |
| `infra`  | 数据库访问基类、Redis 工具、限流组件、Milvus 与对象存储适配 |
| `file`   | 文件档案、内容寻址与存储源路由                              |
| `model`  | 模型供应商配置、模型目录                                    |
| `worker` | 流水线算法实现                                              |
| `auth`   | JWT 认证与登录防护                                          |
| `biz`    | 控制器、用例编排、启动类                                    |

七个模块都位于 `workbuddy-server/`，目录名与 artifactId 同为 `workbuddy-<能力>`；构建入口是该目录下的 `pom.xml`。

## 依赖边

> 构建块之间允许的依赖方向。

```
auth   → common, infra
biz    → auth, common, file, infra, model, worker
file   → common, infra
infra  → common
model  → common, infra
worker → common, file, infra, model
```

结构检查通过：7 个子模块、无环。

`workbuddy-lingxi` 为独立 Python 服务：不参与 Maven 依赖图，与业务后端只共享身份契约与基础设施。

## 可复用能力入口

> 横切能力的入口清单；动手写新工具类、新 Assembler 或新的"通用"方法之前先查这里（格式与维护要求见 `../../.agent/standards/common/09-可复用能力索引.md`）。只收入口，不写用法全文。

| 能力               | 入口                                                                                                                | 何时先想到它                     |
|--------------------|---------------------------------------------------------------------------------------------------------------------|----------------------------------|
| 判空与默认值       | `com.workbuddy.common.utils.NullUtil`                                                                               | 判断 null、取值兜底时            |
| 统一响应体         | `com.workbuddy.common.web.R`                                                                                        | 控制器要返回结果时               |
| 错误码与抛出       | `com.workbuddy.common.error.ErrorCode`、`com.workbuddy.common.exception.ThrowUtil`                                  | 要报业务失败时                   |
| 分页与查询对象     | `com.workbuddy.common.dto.request.page.PageQueryDTO`                                                                | 列表接口收 current / size 时     |
| 对象映射           | `com.workbuddy.common.convert`（映射接口包）                                                                        | 实体 / 入参 / 出参互转时         |
| 实体基类与公共字段 | `com.workbuddy.common.domain.base.BaseInfo`、`com.workbuddy.infra.persistence.mybatis.CommonFieldMetaObjectHandler` | 新建表实体时                     |
| 外部存储适配       | `com.workbuddy.infra.storage.StorageProvider`                                                                       | 读写文件产物时                   |
| 限流               | `com.workbuddy.common.annotation.RateLimit`                                                                         | 接口有成本或可被滥用时           |
| 管理权限           | `com.workbuddy.common.annotation.AdminOnly`                                                                         | 管理类接口要限管理员时           |
| 操作审计           | `com.workbuddy.common.annotation.Audit`、`com.workbuddy.infra.audit.AuditAspect`                                    | 要留"谁对哪个对象做了什么"时     |
| 启动期校验         | `com.workbuddy.common.startup.StartupCheck`                                                                         | 启动要校验配置或依赖可用性时     |
| 大整数序列化       | `com.workbuddy.biz.config.LongIdJsonConfig`                                                                         | 返回 Long ID 或改序列化口径时    |
| 任务触发与执行键   | `com.workbuddy.biz.task.support.TaskTriggerSupport`                                                                 | 触发流水线任务、改幂等或执行键时 |

未列出的分类：配置绑定——无（走 Spring Boot 配置绑定，用其自带能力）。
