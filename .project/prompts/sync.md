# 档案 SOP（唯一提示词）

> 模型处理 `.project` 的唯一流程：先跑入口，按待办逐项处理，再复核。
> 生成物统一放在 `.project/archive/`（档案 01–11 与 `config.json`）。

## 一、入口

```
node .project/tools/sync.mjs            # 状态报告与待办
node .project/tools/sync.mjs --suggest  # 配置候选（只读）
node .project/tools/sync.mjs --gate     # 提交门禁（pre-commit 自动调用）
```

处理前先跑无参数模式；处理完再跑一次，直到「待办：无」。

## 二、接入项目（生成配置 → 填档案 → 注册）

1. 跑 `--suggest` 取得候选。
2. 逐条核对：
   - `watch` 是否覆盖「改了就影响这份档案」的路径；
   - `checks` 的 `target` 小节名是否与档案标题一致；
   - 提取器是否真的适用（没有构建文件就不要 `modules`）。
3. 整理成表格请用户确认：**用哪条、理由、哪条不适用**；确认后写入 `.project/archive/config.json`。
4. 按 `.project/_template/` 填写 11 份档案，写入 `.project/archive/`；0→1 项目的事实类字段填「尚未成型（补齐触发点）」。
5. 按第五节把 `.project` 注册进 `AGENTS.md`（档案未生成前不要注册，避免指针悬空）。
6. 跑 `sync.mjs` 复核，直到待办为空。

## 三、更新档案（提交被拦截，或体检发现漂移）

1. 读 `--gate` 或验证器输出，确认哪些档案需要更新。
2. 运行采集命令取证据（git、检查器、扫描脚本）。
3. 判断是否真的需要改内容：
   - **需要**：只改对应档案，保留结构与其它内容；
   - **不需要**（改的是实现细节，事实未变）：不改正文，只更新状态。
4. 更新 `.project/archive/status.json`：把该档案改为 `已复核`，写 `reviewed`（当天）与 `baseline`（当前 `git rev-parse --short HEAD`）。
5. 跑验证器 `node .project/tools/check-project-docs.mjs`，ERROR 清零。
6. 与代码同提交（状态文件必须在本次提交里）。

## 四、状态文件

`.project/archive/status.json` 是**新鲜度的唯一事实源**，按档案编号记录：

| 字段       | 含义                                               |
|------------|----------------------------------------------------|
| `status`   | `已复核` / `待复核` / `尚未成型`                   |
| `reviewed` | 最近复核日期（`尚未成型` 可为 null）               |
| `baseline` | 复核时的 HEAD 短哈希；提交门禁据此判断“是否复核过” |
| `note`     | 备注；`尚未成型` 必须写明补齐触发点                |

档案文档内不再记录日期——所有时间信息只在此文件。

## 五、注册到 AGENTS.md

1. 先读根 `AGENTS.md`，看它现有结构（路由表、验证阶梯）。
2. 在路由表最合适的位置追加一行：

   ```
   | 项目现状（是什么、欠什么债） | `.project/archive/01-身份.md` + `.project/archive/11-质量与风险.md`（事实档案；先于规范读） |
   ```

3. 有验证阶梯表就再追加一行，没有不新建：

   ```
   | 项目档案（`.project/archive/`） | `node .project/tools/sync.mjs --gate` |
   ```

4. 护栏：**只追加，不改写、不删除、不重排既有内容**；验证不通过就回退这一行，不调整其它内容迁就。
5. 改完运行项目的入口体检（如 `node .agent/tools/common/check-agents.mjs`）。

## 六、所有动作共用的规则

- **来源分级**：L1 代码 / 构建 / 编排 > L2 git 与检查器输出 > L3 项目文档（只用于意图）；冲突以 L1 为准，过时文档记入 `11-质量与风险`。
- **数字必须有命令证据**；写不出证据标【待核对】，不猜不编。
- **同一事实只写一次**；其余文件引用路径不复述（归属表见 `_template/README.md`）。
- **新鲜度只在 `status.json`**：复核超 90 天视为过期；档案文档内不写日期。
- **提交时缺配置不放行**：`archive/config.json` 缺失时门禁拒绝提交，须运行 `--suggest` 生成后写入；0→1 项目写入空配置 `{"docs": {}}` 表示暂不检查。
- **判定原则**：
  - 0→1 项目配置留空，等构建文件与入口层出现后再生成；
  - 引擎不支持的栈只保留 `watch` 触发，不硬造 `checks`；
  - 档案没有声明的事实不配检查；候选与现状冲突以仓库为准。
