# .project — 项目事实档案

> 记录「这个项目是什么、现在怎样」。规则（必须怎么写）在 `.agent/standards/`；两边互不越界：档案只写事实，规范只写规定。
> **生成物统一在 `archive/`**：11 份档案与 `config.json`；本目录其余文件是通用能力（入口、提示词、模板），可整体复制到任意项目。
> 导入新项目：复制本目录 → 跑 `node .project/tools/sync.mjs` 看待办 → 按 `prompts/sync.md` 执行。

## 目录结构

| 路径                           | 性质       | 内容                                                                         |
|--------------------------------|------------|------------------------------------------------------------------------------|
| `tools/sync.mjs`               | 通用       | **唯一入口**：无参 = 状态与待办；`--suggest` = 配置候选；`--gate` = 提交门禁 |
| `tools/check-project-docs.mjs` | 通用       | 结构化验证（被入口调用，也可单独运行）                                       |
| `prompts/sync.md`              | 通用       | 唯一 SOP：接入、更新、注册与共用规则                                         |
| `_template/`                   | 通用       | 11 份空白档案、`config.example.json`                                         |
| `archive/`                     | **生成物** | 11 份档案、`config.json`、`status.json`（随项目不同）                        |

## 通用骨架约定

1. 每份文件开头一句话说明「本文件回答什么问题」。
2. 每个字段标注填法：**AI 采**（客观事实，自动采集）或 **AI 拟**（给出候选与理由，由用户确认或修改；用户也可提出新要求，由 AI 重填）。
3. 不适用的字段填「无」，不删字段。
4. 「尚未成型」是 0→1 项目的合法值：必须写明补齐触发点；与「无」的区别是「将来会有」。

## 来源与保鲜

- **来源分级**：L1 代码与构建文件 > L2 git 与检查器输出 > L3 项目文档（只用于意图）。L3 与 L1 冲突以 L1 为准，过时文档记入 `11-质量与风险`。
- **状态文件**：`archive/status.json` 是唯一的新鲜度来源（`status` / `reviewed` / `baseline` / `note`）；超过 90 天未复核视为过期；档案文档内不写日期。
- **提交前触发**：`.husky/pre-commit` 运行 `node .project/tools/sync.mjs --gate`——缺配置时拒绝提交（要求先补 `archive/config.json`，空配置表示 0→1 暂不检查）；命中管辖路径时要求 `archive/status.json` 在同提交更新（对应条目 `baseline` 等于当前 HEAD）；只改文档或测试不触发。配对表在 `archive/config.json`。
- **更新流程**：按 `.project/prompts/sync.md` 执行。
- **结构化验证**：`node .project/tools/check-project-docs.mjs`——按 `archive/config.json` 的声明执行，防写错数字；随档案更新在提交时自动执行。引擎与项目技术栈无关，配置才是项目数据。
- **配置生成**：`node .project/tools/sync.mjs --suggest` 扫描仓库给出候选，按 `prompts/sync.md` 与用户确认后写入 `archive/config.json`。
- **字段归属**：每个事实只归一个文件，其余引用路径不复述；归属表见 `_template/README.md`。

## 运行流程（SOP）

| 场景         | 入口                                    | 步骤                                                                                                            |
|--------------|-----------------------------------------|-----------------------------------------------------------------------------------------------------------------|
| **接入项目** | `sync.mjs`（无参 → `--suggest`）        | 按待办：确认配置写 `archive/config.json` → 按 `_template/` 填 11 份档案 → 按 `prompts/sync.md` 注册 `AGENTS.md` |
| **提交代码** | `.husky/pre-commit` → `sync.mjs --gate` | 命中管辖路径则要求同提交更新档案；更新后自动跑结构化验证（`--prefixes` 限定范围）                               |
| **定期体检** | `sync.mjs` 或 `check-project-docs.mjs`  | 核对不一致、遗漏、多余与状态过期；按 `prompts/sync.md` 修正                                                     |

三条流程共用一个入口：**触发看路径配对，验证看配置声明，更新看提示词规则**。

## 红线

1. 只写事实，不写规则；规则一律在 `.agent/standards/`。
2. 密钥、凭据、连接串永不入内（`COMMON-SEC-01`）。
3. 每个数字只在此处维护；别处引用不复述。

## AI 进入项目的读取顺序

`AGENTS.md` → `archive/01-身份`（这是什么）→ `archive/11-质量与风险`（欠什么债）→ `.agent/standards/`（怎么写）。
