# 切片环节：现状、问题与优化方案

> 本文件是 `.project/analysis/` 专题分册之一，聚焦 CHUNK（切片）。
> 结论基于源码静态审查，未启动服务、未运行测试；未运行时验证的判断标 `[推断]`。

## 1. 环节职责与边界

- 输入：PREPROCESS 视图 `PreprocessView` + STRUCTURE 文档 `UnifiedDocument` + 切片策略快照；
- 输出：`ChunkSet` JSON + `wb_chunk_set` / `wb_chunk`；
- 职责：章节划分、元素路由（BODY/TABLE/IMAGE）、窗口切分、后置处理（overlap/minMerge/标题前缀）、父子层级；
- 不负责：文本清洗、向量化、索引；但切片长度/内容直接决定向量化窗口与检索粒度。

## 2. 真实执行流程

1. `ChunkTaskRunner` 读 PREPROCESS 产物 + STRUCTURE 文档 + 策略快照；
2. `ChunkPipeline` 按标题栈/章节把元素分组；
3. `ChunkElementRouter` 按元素类型路由：
   - BODY：正文聚合/窗口切分；
   - TABLE：行切片 + Markdown 序列化；
   - IMAGE：图注占位/邻接合并；
4. 后置处理：overlap、`minMergeLen` 合并、标题前缀、父子层级；
5. `ChunkSectionAssembler` 生成父片（SECTION）；
6. 落 `ChunkSet` 产物 + `wb_chunk_set` / `wb_chunk`。

### 2.1 默认策略（种子 `chunk-hybrid v1`）

| 项           | 默认值                               |
|--------------|--------------------------------------|
| 正文算法     | `paragraph-aggregate`，800/1000 字符 |
| 表格算法     | `row-slice`，30 行/3 行重叠          |
| 图片算法     | `caption-placeholder`                |
| 兜底算法     | `recursive-length`，500/50           |
| 父子层级     | `parentChild=ON`                     |
| 标题入正文   | `titleInContent=ON`                  |
| 表格入正文流 | `tableInBodyFlow=OFF`                |
| 最小合并长度 | `minMergeLen=300`                    |
| 结构重叠     | `structureOverlap=0`                 |

### 2.2 token 与窗口

- `tokenCount = ceil(charCount / 1.5)`；全链路没有真实 tokenizer；
- `ChunkWindowEstimator` 聚合算法上界取 `softMaxLen`，实际片长可达 `targetMaxLen + softMaxLen`，再叠加标题前缀/表格 Markdown/`minMergeLen`；
- `WindowSlicer.slice`：`step = max(1, len - overlap)`；正文 fixed-window 未校验 `overlap < len`。

## 3. 问题清单

| #    | 问题                         | 代码证据                                                                                                                             | 影响                                                 | 层级       |
|------|------------------------------|--------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------|------------|
| C-01 | 不是真实 tokenizer           | `tokenCount = ceil(charCount / 1.5)`；切分长度全是 `String.length()`                                                                 | 中英混排/表格/数字的 token 比被抹平；可能超模型窗口  | 契约缺失   |
| C-02 | 窗口估算偏低                 | `ChunkWindowEstimator` 聚合算法上界取 `softMaxLen`，实际可达 `targetMaxLen + softMaxLen`，再叠加标题前缀/表格 Markdown/`minMergeLen` | 前置校验放行超窗片，供应商侧静默截断                 | 算法缺陷   |
| C-03 | overlap ≥ len 时片数爆炸     | `WindowSlicer.step = max(1, len - overlap)`；正文 fixed-window 未校验 `overlap < len`                                                | 单文档产生海量近似重复片                             | 参数校验   |
| C-04 | 表格长行无上限               | `TableMarkdownSupport.rowSlice()` 长行直接单片；表格路没有 maxLen 参数                                                               | 表格片超窗，语义被截断                               | 算法缺陷   |
| C-05 | 表格结构失真                 | `markdownRow` 忽略 `rowSpan/colSpan`；`prepareRows` 丢弃全部 `isHeader` 单元格                                                       | 合并单元格、纵向表头错位；无表头表整表静默消失       | 契约缺失   |
| C-06 | 每张图片产出同文本极小片     | `NormalizerImpl` 把 caption 置空；`ImageCaptionSliceStrategy` 用常量占位文本；`MinMergeProcessor` 不合并 IMAGE                       | 每图一条 ~35 字噪声片，检索命中也没有信息            | 算法缺陷   |
| C-07 | 父片无长度上限且默认不入索引 | `ChunkSectionAssembler.buildParentChunk()` 拼接全部子片；`EmbedPipeline` 默认 `includeParent=OFF`                                    | 父片浪费存储；检索 `PARENT_EXPAND` 静默失效          | 跨阶段契约 |
| C-08 | 非默认正文算法会打乱片序     | `ChunkElementRouter` 仅在 `bodyAlgorithm.flushOnContentBoundary()` 为真时先结算；`title-boundary`/`structure-hybrid` 为 false        | chunk 顺序与原文不一致，上下文错位                   | 算法缺陷   |
| C-09 | Excel sheet 层级不被识别     | 结构阶段把 sheet 生成为 `SECTION(level=0)`；切片只把 `TITLE` 当章节边界                                                              | sheet 名变成正文片，全文档无 titlePath/无父片        | 跨阶段契约 |
| C-10 | 落库字段无长度保护           | `wb_chunk.title_path=512`、`page_range=1024`、`strategy_version=32`；`formatPageRange` 明确不截断                                    | 长标题/多段页码/长版本名导致批次插入失败，任务半成品 | 数据模型   |
| C-11 | chunkId 是序号               | `chunk-0001` 等按顺序编号                                                                                                            | 重切后序号复用/漂移，索引无法按 ID 精确收敛          | 标识模型   |
| C-12 | 步骤日志与最终产物不一致     | `stats.incr` 在路由期累加，后置 overlap/minMerge/titleInContent 会改片数/片长                                                        | 子步骤数字对不上最终 chunkCount，排障误导            | 可观测性   |
| C-13 | 切片元数据不足               | `Chunk` 无 bbox/provenance/charRange；DB 无 `sourceElementIds`/`fallbackReason`，只在产物 JSON                                       | 无法做单元格级高亮/溯源；检索结果无法定位原文        | 契约缺失   |
| C-14 | 标题前缀重复计入             | `titleInContent=ON` 时标题前缀进入片文本，但 `tokenCount` 未按最终文本重算                                                           | 片长/窗口校验与实际内容不一致                        | 算法缺陷   |
| C-15 | 表格入正文流会丢溯源         | `tableInBodyFlow=ON` 时表格 Markdown 并入正文片，`tableRef`/cell 溯源丢失                                                            | 检索命中表格片无法回表/高亮                          | 跨阶段契约 |

## 4. 根因

1. 切片先于向量化，且一套 `ChunkSet` 可服务多个模型：没有模型端口，只能用字符数近似 token。
2. 窗口估算模型与后置处理脱节：估算在切分前，标题前缀/表格 Markdown/合并会改变最终片长，没有“按最终片长回算”的闭环。
3. 表格/图片的语义在切片层被压扁：Markdown 表达力有限，cell 模型只有 row/col，图片没有 OCR/图注。
4. 章节边界只认 `TITLE`，不认 `SECTION`；与结构阶段的层级模型不一致。
5. 父子层级与向量化开关各自默认，没有组合校验；父片无长度上限。
6. 切片元数据只保留“可检索文本”，不保留“原文定位”；DB 列宽也没有保护。

## 5. 可复用骨架

| 能力          | 现状                                      | 可复用性                     |
|---------------|-------------------------------------------|------------------------------|
| 切片管线      | `ChunkPipeline` 固定步骤，路由/后置可插拔 | 高                           |
| 元素路由      | `ChunkElementRouter` 按类型分流           | 高                           |
| 窗口切分      | `WindowSlicer` 支持 fixed/recursive       | 中；需要参数校验和 tokenizer |
| 表格 Markdown | `TableMarkdownSupport` 已有行列/转义      | 中；需要合并单元格/长行      |
| 图片切片      | `ImageCaptionSliceStrategy` 已有占位      | 低；需要 OCR/图注后重做      |
| 父子层级      | `ChunkSectionAssembler` 已有父片          | 中；需要长度上限/摘要        |
| 策略          | `ChunkAlgorithmSpec` 已有算法/参数/开关   | 高；可继续扩展               |

## 6. 优化方向

1. **tokenizer 与模型绑定**：切片策略声明 tokenizer/模型窗口；`tokenCount` 用真实 tokenizer；窗口校验按最终片长回算。
2. **修正窗口估算**：上界 = `targetMaxLen + softMaxLen + 标题前缀 + 表格 Markdown + minMerge`；`overlap < len` 校验；overlap 对短片禁用。
3. **表格切片**：支持 `rowSpan/colSpan`、保留表头、长行按字符/token 拆分；无 cells 时至少保留原文本，不静默丢表。
4. **图片切片**：有 OCR/图注时用真实文本；无文本时不产占位片，或并入邻片；`MinMergeProcessor` 合并相邻 IMAGE。
5. **父片**：长度上限/摘要；父片默认入索引或父片展开改读切片产物；`parentChild`/`includeParent` 组合校验。
6. **章节边界**：`TITLE` + `SECTION` 都作为章节锚点；Excel sheet 生成 titlePath/父片。
7. **片序**：所有正文算法遇到 TABLE/IMAGE 先结算正文缓冲，保证片序与原文一致。
8. **元数据**：`Chunk` 增加 `sourceElementIds`/`charRange`/`bbox`/`fallbackReason`；DB 列宽改 TEXT 或截断策略。
9. **chunkId 稳定**：用内容哈希/章节路径 + 序号，重切可收敛。
10. **统计口径**：路由期统计改为最终产物统计，或分“路由片数/最终片数”。

## 7. 讨论清单

| 顺序 | 讨论项         | 需要确认的取舍                                              |
|------|----------------|-------------------------------------------------------------|
| 1    | tokenizer 选型 | 绑定模型还是通用 tokenizer；是否需要新增依赖                |
| 2    | 窗口估算公式   | 是否按最终片长回算；超窗是截断还是重切                      |
| 3    | 表格合并单元格 | Markdown 如何表达 rowSpan/colSpan；是否改用 HTML/结构化文本 |
| 4    | 图片占位片     | 无 OCR 时是否产片；并入邻片的边界                           |
| 5    | 父片策略       | 入索引还是展开读产物；父片长度上限/摘要                     |
| 6    | 章节边界       | SECTION 是否一律当章节；Excel sheet 的 titlePath            |
| 7    | chunkId        | 内容哈希 vs 序号；重切收敛策略                              |
| 8    | 元数据落库     | 哪些字段进 DB；列宽/JSON                                    |
| 9    | 统计口径       | 路由期/最终期如何对齐                                       |
