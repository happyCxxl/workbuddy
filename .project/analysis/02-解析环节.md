# 解析环节：现状、问题与优化方案

> 本文件是 `.project/analysis/` 专题分册之一，聚焦解析环节（PARSE）。
> 结论基于源码静态审查，未启动服务、未运行测试；未运行时验证的判断标 `[推断]`。

## 1. 环节职责与边界

解析环节负责把“已建档的源文件”变成“结构化解析结果”：

- 输入：`WbFileResult`（文件结果）+ `WbSourceFile`（来源文件）+ `FileStorage` 打开的输入流 + `ParseProperties`；
- 输出：`ParseOutcome`，其中 `parseResult` 落对象存储为单 JSON，`stepLogs` 落 `wb_knowledge_pipeline_step_log`；
- 不负责：合并多路结果、标题层级推定、页眉页脚处置、切片、向量化；这些分别归组装/预处理/切片/向量化；
- 不直接碰 DB 与产物存储：落库由 `ParseTaskRunner` 完成。

设计意图是“解析只产事实，裁决归下游”。这个边界本身合理，问题在于“事实”不够、质量门禁又不消费能力结果。

## 2. 真实执行流程

`ParsePipeline.run()` 固定六步：

1. 文件级路由：先把 Tika MIME 归一，再按 `mimeType` 精确 `equals` 找 `DocumentParserPort`；
2. 原生解析：调用解析器，产出 native 路（元素 + 页指标 + 解析事实）；
3. 信号判定 + 内置降级：`SignalDetector` 把页级指标和 `ParseFact` 转成 `Signal`，`SignalFallbackHandler` 按子类型写告警/计失败单元；
4. 结果封装：native 路 + OCR 占位路 + `CapabilitySnapshot`；
5. 成功率门槛：`evaluate()` 按内容单元成功率给 SUCCESS / PARTIAL_SUCCESS / FAILED；
6. 质量汇总：坏页比例达门槛时追加 `QUALITY_BAD_PAGE_RATIO` 告警。

### 2.1 PDF 路径

- 文件小于 `large-file-min-bytes`（默认 8MB）整档入内存；大于则落临时文件；
- 第一遍全档逐页提取：字符坐标、字号、字体、线段、图片框、乱码率、文字占比、矢量覆盖率；
- 第二遍按 `page-window-size`（默认 50 页）从页产物存储读取并装配元素；PDF 只提取一遍，页产物按窗口走内存或临时磁盘；
- 版面：1pt 分箱做字符投影，按 `column-gutter-min-width` / `column-gutter-max-coverage` 找竖直栏沟，最多 `column-max-count` 栏；跨栏行切上下带后按栏序重排；
- 表格：有边框走 `RuleSegments → RuleGrid → RuledTableBuilder`；无边框走 `TextTableBuilder`；假表门限包括列填充率、非空单元格占比、表头数字占比；失败则整块降级为段落并写 `degraded/degradeReason`；
- 页眉页脚：页顶/页底 `header-area-ratio`/`footer-area-ratio`（默认 8%）带内，跨页重复文本 + 页码模式；
- 图片：只按 CTM 占位矩形面积 ≥ `image-min-area-ratio`（默认 5%）产 `IMAGE` 元素；D1-1 起用 `PDFRenderer` 按 `page-image-dpi` 渲染页图，扫描页写 `PAGE_IMAGE`、图片框裁剪写 `IMAGE_CROP`，`assetRef` 指向资产清单中的真实 `assetId`；
- OCR：只对“整页 `charCount==0` 且含图”的页调用 provider；provider 恒 `null`；`OcrRegion.imageRef` 已可指向 `PAGE_IMAGE` 资产，但 provider 契约仍缺 MIME/DPI/语言。

### 2.2 Office 路径

- DOCX：段落 + `styleID` + 字体事实 + 表格（`gridSpan`/`vMerge`）+ 段落内图片原始字节写资产 + 页眉页脚部件 + 文本框正则提取；表格内图片、SmartArt/drawing 子树不遍历；
- DOC：段落 + 样式名 + 首 run 字体 + 域代码剥离 + 表格仅行列文本（无合并信息）+ 图片原始字节写资产（位置仍丢失）+ 仅首页页眉页脚；
- XLS/XLSX：每个 sheet 一个 `TABLE`；合并区域 origin 记 span、被覆盖格文本并入 origin；公式优先取缓存值；工作表图片原始字节写资产；
- PPT/PPTX：按文件名后缀选 HSLF/XSLF，只处理顶层 `TextShape`/`TableShape`/`PictureShape`；图片原始字节写资产；GroupShape/备注/母版丢失；
- Office 统一用 `office-page-chars`（默认 3000）折算“虚拟页”，质量门槛按虚拟页判定，与物理页脱节。

### 2.3 质量门槛

| 条件                                                                                                            | 结果                                      |
|-----------------------------------------------------------------------------------------------------------------|-------------------------------------------|
| 0 内容单元                                                                                                      | `PARSE_CORRUPTED`                         |
| 全为空白页                                                                                                      | `PARSE_CORRUPTED`                         |
| 内容单元全为扫描页                                                                                              | `SCANNED_UNSUPPORTED`                     |
| 内容单元 ≤ `short-document-max-units`（默认 3）且坏页 ≤ `short-document-max-failed-units`（默认 1）且有可读单元 | 放行（SUCCESS/PARTIAL）                   |
| 成功率 < `success-unit-ratio`（默认 0.9）                                                                       | `RATIO_BELOW_THRESHOLD`                   |
| 部分单元失败                                                                                                    | `PARTIAL_SUCCESS`，失败页元素仍留在产物里 |

## 3. 现有骨架与可复用点

| 能力       | 现状                                                                                                                                          | 可复用性                         |
|------------|-----------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------|
| 解析器策略 | `DocumentParserPort` 按 MIME 路由，PDF/Office 各有实现                                                                                        | 高；路由只需加 MIME 归一化       |
| 管线模板   | `ParsePipeline.run` 固定“路由→原生→信号→降级→封装→门槛”                                                                                       | 高；扩展点已经留出               |
| 信号/降级  | `SignalDetector` + `SignalFallbackHandler` 按子类型处置                                                                                       | 中；需要把“事实”和“失败信号”分开 |
| 多路结果   | `ParseSource` 已支持 native/ocr/layout/table，`ParseResult.sources` 按来源分组                                                                | 高；OCR 接入不需要改结果骨架     |
| 元素契约   | `ParseElement` 已有 `bbox`/`displayBBox`/`font`/`confidence`/`needsOcr`/`degraded`/`provenance`/`cells`，`assetRef` 指向 `ParseResult.assets` | 高；缺角色候选                   |
| 质量契约   | `QualityInfo` 已有 warnings/scannedPages/blankPages/failedPages                                                                               | 中；缺“可读页/OCR 页/降级页”     |
| 能力快照   | `CapabilitySnapshot` 已有 parser/ocr/layout/table 引用                                                                                        | 高；缺阈值快照/配置哈希          |
| 能力注册   | `CapabilityRegistry` 三能力口，按 Spring Bean + 开关注册                                                                                      | 高；实现类被整体移除，接口仍在   |

结论：解析环节的骨架方向正确，缺的是“资产 + provider + 质量门禁消费 + 错误分类 + 配置校验”，不是推倒重来。

## 5. 根因

1. 能力层被整体移除后，契约仍按“有模型”设计；D1-1 已补 `ParseAssetSink` 与 `ParseResult.assets`，`OcrRegion.imageRef` 可指向真实页图资产，PDF 页图/裁剪图与 Office 原始图片字节均落对象存储。
2. 质量门禁与能力结果原先解耦：`ScannedFallbackHandler` 直接把扫描页计失败，`evaluate()` 只看 native 的 `scannedPages`；D0-2 已改为 handler 只登记扫描页，门禁按 OCR 覆盖重算失败单元。
3. 解析器把“结构缺口”写成事实，信号层原先又把事实当失败：D0-5 已给 `ParseFact` 加 `level`，正常去重/剪枝/补强为 `INFO`，只有 `WARN` 事实进入信号判定。
4. 错误分类原先只有 `PARSE_CORRUPTED` / `PARSE_FAILED`：没有加密、超时、超大、格式不支持等分支；D0-1 已拆为 `PARSE_UNSUPPORTED_FORMAT` / `PARSE_ENCRYPTED` / `PARSE_TOO_LARGE` / `PARSE_INPUT_UNREADABLE` / `PARSE_TIMEOUT`。
5. 配置原先无默认值/无校验：缺键即 0，启动不报错；D0-3 已加 `@PostConstruct` 启动期校验，并对齐注释。
6. Office 实现按“文本树”而非“版式”处理：虚拟页、图片按序追加、GroupShape 不递归，导致位置/层级信息在解析层就丢失。

| D1-3 | OCR 触发与合并     | `ocrSource()` 遍历 `nativeSource.elements` 的 `needsOcr=true` 图片/页，按 bbox 调 OCR；结果产 `ocr` 路；组装环节按 bbox/页码去重                                                                                                                                                                                                                                        | 图文混排 Word 图片文字被识别；不重复正文                  |
| D1-4 | 语义角色候选       | `ParseElement` 增 `roleCandidate`（TITLE/LIST/CAPTION）或角色事实；PDF 用字号/加粗/行首编号/居中，DOCX 用 style/numPr/outlineLvl，PPT 用 title placeholder；层级仍归组装                                                                                                                                                                                                | 样本集抽检标题候选召回/准确；列表/图注候选可追溯          |
| D1-5 | Office 结构补全    | DOCX 表格内图片、文本框、SmartArt 记录 `UNSUPPORTED` 事实；PPT GroupShape 递归；DOC 图片按锚点插入；Excel 合并单元格/隐藏 sheet                                                                                                                                                                                                                                         | 样本文件元素覆盖率提升；至少“未支持”可查                  |

D1 的前置：对象存储写入能力（`FileStorage` 已有）、灵犀 OCR 接口、资产清理策略。D1 不做多模态向量，只做“可读文本 + 可展示图片”。

### D2：结构化能力（需模型/数据，暂不排期）

- 版面模型：阅读顺序、栏/区域、图文绕排；
- 表格结构模型：无框线、合并单元格、跨页表格；
- 文档图：标题/列表/图注/公式/脚注/参考文献；
- 多模态检索：图片语义向量、图表理解。

这些能力需要标注数据、模型选型和评测集，不能靠规则堆叠保证。
