# 解析环节统一重构：需求（单元级解析 + 文档级组装）

> 本文件回答：解析环节**要做什么**——解析与组装的职责边界、解析产出的契约、每个文件格式的单元口径。
> 范围：`workbuddy-server/workbuddy-worker/src/main/java/com/workbuddy/worker/parser/` 下全部解析器，以及与解析衔接的组装（STRUCTURE）阶段。
> 本文是需求基线；是否实现、怎么实现见 `11-解析环节统一重构-设计.md`。
> 结论：解析只回答「这一单元有什么、在哪里、质量如何」；组装回答「这些单元合起来是什么文档」。

**阅读指引**：要确认「做什么」读第 3、4 节；要核对验收读第 6 节；要讨论未决项读第 7 节。

---

## 1. 背景与目标

### 1.1 现状（已核实）

1. **PDF 有显式流水线，但文档级动作仍留在解析里。**
   - `PdfDocumentPipeline` 已拆出 `PageExtractionStep`、`PageAssemblyStep` 等页级步骤；
   - 但 `HeaderFooterStep`（跨页识别页眉页脚键）、`TableContinuationStep`（跨页续表标记）仍在解析阶段做文档级检测/标记。
2. **Office 解析器是「一个 `parseNative` 从头做到尾」。**
   - `DocxDocumentParser` / `DocDocumentParser` 在 `parseNative` 里直接产出段落、表格、图片、页眉页脚，再算虚拟页指标；
   - `ExcelDocumentParser` 每个 sheet 一个 `TABLE`；
   - `PptDocumentParser` 每个 slide 一组元素；
   - 解析、文档级组装、质量在同一个方法里混着做。
3. **结果模型是扁平的文档级对象。**
   - `ParseSource.elements` 是整份文档的元素平铺列表；元素只带 `page` 字段，没有按单元（页/sheet/slide）分组；
   - `ParseSource.unitCount` 已经是「单元数」口径（PDF 页数 / Excel sheet 数 / Word 虚拟页数），但结果没有按单元组织。
4. **跨页/文档级语义目前一半在解析、一半在组装。**
   - 解析：`HeaderFooterStep`、`TableContinuationStep` 做检测/标记；
   - 组装：`TableContinuationResolverImpl` 做跨页表合并、`StructureAssemblerImpl` 做章节树、`ReadingOrderResolverImpl` 做全档阅读顺序。

### 1.2 目标

把解析环节收敛为**单元级解析**：

- **解析只做**：每个单元的内容抽取 + 位置/几何 + 单元质量；
- **解析不做**：任何需要看多个单元或全档才能判断的事；
- **组装做**：页眉页脚、跨页表合并、标题层级、章节树、元素关系、跨页阅读顺序、文档级质量。

一句话：

> **解析回答「这一单元有什么、在哪里、质量如何」；组装回答「这些单元合起来是什么文档」。**

## 2. 术语

| 术语                        | 含义                                                                                                               |
|-----------------------------|--------------------------------------------------------------------------------------------------------------------|
| 单元（unit）                | 解析的最小组织单位。按格式不同：PDF 物理页、XLSX 工作表、PPTX 幻灯片、DOCX 段落/表格流（或虚拟页，仅用于质量口径） |
| 单元结果（unit result）     | 一个单元解析出的元素 + 几何 + 质量，是解析产出的最小可独立消费对象                                                 |
| 文档结果（document result） | 组装后的整份文档：结构、关系、文档质量                                                                             |
| 单元质量                    | 属于单个单元的质量指标（字符数、乱码率、空单元、图片占比、置信度等）                                               |
| 文档质量                    | 属于整份文档的质量（单元覆盖、扫描单元占比、缺单元、整档是否可用）                                                 |

## 3. 核心职责边界（需求正文）

| 职责                       | 解析                         | 组装    |
|----------------------------|------------------------------|---------|
| 抽取每单元内容             | ✅ 必须                      | —       |
| 输出每单元位置/几何        | ✅ 必须                      | —       |
| 每单元质量指标             | ✅ 必须                      | —       |
| 页内段落切分、页内表格结构 | ✅ 可做                      | —       |
| 页眉页脚识别/分类          | ❌ 不做（文本原样输出）      | ✅ 必须 |
| 跨页表格识别/合并          | ❌ 不做（每页表格独立输出）  | ✅ 必须 |
| 标题层级、章节树           | ❌ 不做（只给样式/字体事实） | ✅ 必须 |
| 元素关系、跨页阅读顺序     | ❌ 不做                      | ✅ 必须 |
| 文档级质量汇总/门禁        | ❌ 不做                      | ✅ 必须 |

约束：解析产出必须**自包含**——不携带 `PDDocument`、POI `Workbook`/`XWPFDocument` 等解析器句柄，可序列化、可缓存、可独立重试。

## 4. 功能需求

### FR-01 结果按单元组织
解析产出必须是**单元集合**，不是文档级平铺列表。每个单元有稳定的序号与类型。

### FR-02 解析只做单元内
每个单元的结果只依赖本单元内容；解析不得为判断某个元素去读其他单元或全档。

### FR-03 不做跨单元/文档级判断
解析不得产出下列结论：页眉/页脚标签、跨页表格合并、标题层级、章节结构、跨页阅读顺序、文档结构。

### FR-04 页眉页脚文本原样输出
页眉页脚的文字与位置作为普通单元内容产出；是否归类为页眉页脚由组装决定。

### FR-05 跨页表格只做单页片段
每个单元内的表格结构（单元格、行/列、合并跨度）由解析产出；跨页表格的识别与合并归组装。

### FR-06 单元抽象覆盖各格式
「单元」必须覆盖：PDF 物理页、XLSX/XLS 工作表、PPTX/PPT 幻灯片、DOCX/DOC 段落/表格流、图片页。不得要求所有格式都按物理页切分。

### FR-07 每个解析器产出同一单元契约
换解析器（PDFBox → POI → 未来的其他实现）不改变组装消费的契约；组装只依赖单元结果，不依赖解析器类型。

### FR-08 位置与几何信息完整
单元结果必须携带下游能据以做跨页/跨单元判断的几何信息：bbox、字号、字体、置信度、表格行列与合并跨度、图片框、页面尺寸/旋转（PDF），sheet 行列（Excel），slide 形状（PPT）。

### FR-09 单元质量在解析，文档质量在组装
解析产出每单元质量指标；文档级质量（覆盖、扫描占比、缺单元、整档可用性）在组装/质量环节产出，不在解析里下结论。

### FR-10 单元结果可序列化、可缓存、可重试
单元结果不得泄漏解析器句柄；单个单元失败可隔离、可单独重跑，不影响其他单元。

### FR-11 取消/超时单元级退出
解析循环按单元检查取消令牌；取消后尽快退出，不写半成品单元。

### FR-12 兼容迁移
现有 `ParseSource` / `ParseResult` 是下游契约；新单元结果模型必须给出迁移路径，改造后组装、预处理、切片、向量化不因解析产物变化而中断。

## 5. 非功能需求

| 编号   | 需求                                                                   |
|--------|------------------------------------------------------------------------|
| NFR-01 | 行为等价：改造前后元素、指标、质量结论有黄金对拍兜底；差异必须显式登记 |
| NFR-02 | 可测试：每个单元可独立构造 fixture 测试，不启动 Spring、不解析整份文档 |
| NFR-03 | 可观测：单元质量、失败单元、文档质量均可查；失败能定位到具体单元       |
| NFR-04 | 性能：不重复解析同一单元；页级解析可并行，组装串行                     |
| NFR-05 | 单一事实源：单元口径、质量口径集中在一处定义，不散落在各解析器         |

## 6. 验收标准（按格式）

| 格式     | 验收点                                                                                  |
|----------|-----------------------------------------------------------------------------------------|
| PDF      | 每页独立产出单元结果；不产 HEADER/FOOTER 标签、不产续表标记；跨页表、页眉页脚由组装产出 |
| DOCX     | 产出段落/表格/图片 + 页眉页脚部件原始内容；不按物理页切分；不产标题层级                 |
| DOC      | 同 DOCX；页眉页脚部件原始输出                                                           |
| XLSX/XLS | 每 sheet 一个单元；sheet 内合并单元格/公式保留；不产跨 sheet 表合并                     |
| PPTX/PPT | 每 slide 一个单元；slide 内文本/表格/图片产出；deck 结构归组装                          |
| 组装     | 消费单元集合，产出文档结果（结构、关系、文档质量）                                      |
| 回归     | `mvn -o -pl workbuddy-worker -am test` + biz 定向通过；黄金对拍通过                     |

## 7. 讨论清单

| 顺序 | 讨论项             | 需要确认的取舍                                                                        |
|------|--------------------|---------------------------------------------------------------------------------------|
| 1    | DOCX/DOC 单元粒度  | 段落/表格流 vs 虚拟页（虚拟页只做质量口径）；是否保留 `office-page-chars` 虚拟页      |
| 2    | 单元结果命名与字段 | 已定：`ParseSource` 上挂 `units`，`ParseUnitResult` 复用 `PageMetric`/`PageDimension` |
| 3    | 页眉页脚部件承载   | Office 的页眉页脚是「普通元素」还是「原始部件元数据」                                 |
| 4    | 组装器形态         | 每格式一个组装器（Pdf/Docx/Workbook/Deck），还是统一组装器 + 格式钩子                 |
| 5    | 文档级质量门禁去留 | 解析任务的 SUCCESS/PARTIAL/FAILED 门禁是留在解析任务收尾，还是移到组装/独立质量环节   |
| 6    | 迁移顺序           | 先统一契约再改处理器，还是先 PDF 后 Office                                            |
| 7    | `ParseSource` 去留 | 已定：保留为唯一解析产物（含单元集合），不另设包装类                                  |
