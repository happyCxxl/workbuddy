# 08 · 数据与评测平台实现设计

> 状态：设计文档（待实现）。对应需求见 `.project/analysis/07-数据与评测平台需求.md`；本文件只写实现方案，不重复需求背景与"为什么"。

## 1. 模块归属与依赖

- 新建模块 `workbuddy-eval`，承载领域无关骨架（数据集 / 标注 / 运行 / 指标 / 对比 / 门禁）。
- 功能域在各自模块实现三个扩展点；解析域在 `worker` 模块的 `parser.eval` 包。
- 依赖边（新增两条，无环）：
  - `eval → common, infra, file`
  - `worker → eval`（解析适配器直接复用 `ParseContext`、`PdfBoxDocumentParser` 等解析机器）
  - `biz → eval`（控制器与装配）

结构性影响（一次性登记，无行为风险）：根 `pom.xml` 模块清单、`.project/archive/05-结构.md` 依赖图；`check-modules` 自动定位模块，脚本无需改。

## 2. 技术栈

| 层            | 选型                             | 备注                                                                |
|---------------|----------------------------------|---------------------------------------------------------------------|
| 骨架框架      | Java 21 / Spring Boot 3.2.5      | 复用                                                                |
| 持久化        | MyBatis-Plus                     | 复用 `BaseInfo` 分档、逻辑删除、自动填充                            |
| 数据库迁移    | Flyway（唯一新增依赖）           | 现 `init.sql` 为删库重建式；首版收成 `V1__baseline`，评测表走 `V2+` |
| 样本/产物存储 | MinIO via `StorageProvider`      | 库只存 `object_key`                                                 |
| 运行触发      | `TaskTriggerSupport`             | 串行后台执行，不经线上链路                                          |
| 前端          | Vue 3 + TS + Vite + Element Plus | 新增 `/eval` 路由组                                                 |

不引入新的 ORM / 调度 / 计算框架；指标计算是纯 Java 函数，跑批是串行循环。

## 3. 数据模型（`wb_` 前缀 + DTO-010 三档）

| 表                          | 作用                                                         | 档位                           |
|-----------------------------|--------------------------------------------------------------|--------------------------------|
| `wb_eval_dataset`           | 数据集登记（name / domain / desc）                           | 完整档（有删除/更新/人为操作） |
| `wb_eval_dataset_version`   | 数据集版本（不可变，draft/frozen）                           | 只追加                         |
| `wb_eval_item`              | 样本 item（object_key / source / split / meta / defect_tag） | 只追加                         |
| `wb_eval_annotation_schema` | 标注 schema 注册（domain × 版本 × 金标结构 JSON）            | 只追加                         |
| `wb_eval_annotation`        | 金标（item × schema × payload × annotator × status）         | 只追加                         |
| `wb_eval_metric`            | 指标注册（domain / name / direction / granularity）          | 只追加                         |
| `wb_eval_run`               | 运行（dataset_version × domain × pipeline_version 哈希）     | 只追加                         |
| `wb_eval_run_item`          | 逐样本运行项（产物键 / 耗时 / 成本 / 错误码 / 降级码）       | 只追加                         |
| `wb_eval_metric_value`      | 指标值（run × metric × item）                                | 只追加                         |
| `wb_eval_comparison`        | 对比（baseline × candidate × verdict）                       | 只追加                         |
| `wb_eval_regression_case`   | 回归用例（已修缺陷 → 期望指标）                              | 只追加                         |

对齐约定：主键 `BIGINT` 雪花显式传 id；`del_flag VARCHAR(1)` 只给"有删除"的表；`create_by/create_time/update_by/update_time` 按档位启用；码值（split / source / status / verdict）全走枚举。代表一例：

```sql
CREATE TABLE wb_eval_run
(
    id                 BIGINT        NOT NULL COMMENT '主键（雪花，应用显式传 id）',
    dataset_version_id BIGINT        NOT NULL COMMENT '数据集版本',
    domain             VARCHAR(32)   NOT NULL COMMENT '功能域码（EvalDomain 枚举）',
    pipeline_version   VARCHAR(1024) NOT NULL COMMENT '管线版本快照（代码/配置/模型哈希，JSON）',
    status             VARCHAR(32)   NOT NULL COMMENT '状态（EvalRunStatus 枚举）',
    create_time        DATETIME(3)   NOT NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '创建时间',
    finish_time        DATETIME(3)            DEFAULT NULL COMMENT '完成时间',
    PRIMARY KEY (id),
    KEY idx_version (dataset_version_id)
) COMMENT ='评测运行：一次「数据集版本 × 功能域 × 管线版本」的执行（append-only）';
```

## 4. 领域无关骨架：三个 SPI + 注册表

骨架只存不透明 JSON，永不解析金标/产物内容；域特有逻辑收进三个扩展点，靠 Spring 收集注册：

```java
// 1. 标注 schema：域定义「金标长什么样」
interface AnnotationSchema {
    EvalDomain domain();
    String version();
    String specJsonSchema();              // 金标结构定义（JSON Schema）
    void validate(String payload);        // 写路径校验
}

// 2. 指标族：域定义「怎么打分」
interface MetricFamily {
    EvalDomain domain();
    List<MetricDef> metrics();            // 每个指标：name/direction/granularity
    double evaluate(MetricDef def, List<RunItemResult> results, List<Annotation> golds);
}

// 3. 运行适配器：域定义「怎么跑一遍」
interface EvalRunAdapter {
    EvalDomain domain();
    RunItemResult run(EvalItem item);     // 输入样本 → 产物 + 错误/降级
}
```

骨架编排类（`EvalRunService`、`EvalCompareService`、`EvalGateService`）只依赖这三个接口，通过 `EvalDomain` 从注册表取实现。**插一个新功能域 = 在对应模块加 3 个 `@Component` 实现类，零骨架改动。**

## 5. 运行编排

- `POST /eval/runs` 触发 → `TaskTriggerSupport` 入队 → 串行遍历 item → 每个 item 调 `EvalRunAdapter.run()` → 产物写 MinIO、`wb_eval_run_item` 记耗时/错误/降级。
- 失败隔离：单样本异常记 error 继续，最后报告把「运行失败」与「质量差」分开。

## 6. 指标与门禁

- 跑完 → 对每个 `MetricFamily.metrics()` 逐个 `evaluate(runItems, golds)` → 落 `wb_eval_metric_value`。幂等：按 `(run_id, metric_id, item_id)` 覆盖写。
- 解析域四类指标（文本保真 / 块检测 IoU / 阅读顺序 / 表格 TEDS）是 `worker` 里的纯函数，可单测。
- 门禁：`EvalCompareService` 拉基线 vs 候选指标值 → `EvalGateService` 判定「至少一项 ↑ 且无 ↓」→ verdict（pass / fail / manual）。holdout 样本标记 split，参与最终判定但不参与调参；公开/内部按 source 分表报分。

## 7. API 与前端

- 控制器放 `biz`，前缀 `/eval`，HTTP 恒 200 + `R` 外壳，雪花 ID 字符串化，提交类接口带 `requestId` 幂等键，错误码集中进 `ErrorCode`（新增「评测平台」分域，任务码分列）。
- 前端 4 页：数据集管理 / 标注 / 运行与报告（逐项 diff + 指标 diff）/ 门禁。
